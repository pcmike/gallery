# Upgrading and backups

What changes at each version, and what to back up.

← [Guide index](README.md) · [Project README](../../README.md)

## Upgrading and backups

**Updating** means replacing `index.php`, by hand or with **Update now** in the Health check when a newer version is out ([how it works](admin.md#new-versions-and-update-now)). Settings (`.gallery-config.php`), captions and everything else live beside it and are untouched; the Health check then shows what it was upgraded from.

**Upgrading to 2.6.8** from 2.6.7: replace `index.php`. The photo **info panel** now has a **main switch**, *Info panel* in Settings → Metadata, which is off to start with: **the panel disappears everywhere until you switch it on**, even in folders that had it on, and the folded list of what it shows (*Media information*) now holds all fourteen switches, greyed out until the main switch is on. The settings group is called *Metadata* (it was *Location data* and, for a short while, *Locations and media information*), and a folder's switch is *Show media info*, first in the folder's Metadata section. Health now shows the first characters of the running file's checksum next to the version (*Running 2.6.8 · build 3f9a1c2e*), so two builds of one version can be told apart. **A folder's settings have one new choice, *Who can see this folder*** (Public, Unlisted, Private, Only me), in place of the *Private folder* and *Not listed* switches; **"Not listed" is now called "Only me"** everywhere you read it. Nothing stored changes for it: an Only me folder is still private plus the `unlisted` flag in its own `.gallery-items.php`, so everything you set keeps working. **Unlisted** is new: a public folder with `quiet: true` in its own `.gallery-items.php` (and, by itself, **Gallery of its own** on unless the folder has `ownGallery: false`); an older version ignores both marks and shows the folder as an ordinary public one, so going back to 2.6.7 or older **lists every Unlisted folder again** (the marks stay in the files, and this version picks them up when you return).

**Upgrading to 2.6.7** from 2.6.6: replace `index.php` (or press **Update now**). One thing can change on screen: a folder's *Show photo locations* switch is now taken from the folder above when the folder has made no choice (before, a folder you had never touched was simply off). So a folder inside one that has locations on **now shows its locations too**, unless you switch it off. After updating, look through the subfolders of any folder that has locations on, and switch off any that should stay private (a folder you switched off yourself stays off). The new **photo info** panel is off in every folder until you switch it on; its field switches are in Settings (since 2.6.8 under *Metadata*, behind a main *Info panel* switch).

**Upgrading to 2.6.4** from 2.6.3: replace `index.php` (or press **Update now**). Nothing stored changes. The only difference: the thumbnail clean-up now leaves a folder from elsewhere on the server (`EXTRA_FOLDERS`, `EXTRA_ROOTS`) alone, so another gallery showing the same folder keeps its thumbnails; a gallery no longer tidies its own old thumbnails in such a folder, and a few can build up there (safe to delete by hand).

**Upgrading to 2.6.6** from 2.6.4 (or 2.6.3, 2.6.2): replace `index.php` (or press **Update now**). Things to know:
- **Scrub location data is on to start with.** If visitors may download originals (or you show locations), the location is now taken out of every original a visitor is sent, shown or hidden on the page. You and people with the private-view password still get the files as they are. Switch it off in Settings (*Scrub location data*, under *Location data*) if you want the old rule (only a location the gallery hides is taken out).
- **Share links and wrong addresses.** New random link addresses are 8 letters and digits (old links keep their 16 and keep working; if you added the tidy server rule for 16-character links, the current rule from Settings → Server setup covers both). A wrong address, an unknown `?photo=` and a stray word after `?` now answer 404 (an unknown `?photo=` used to show the front page), and the pause for wrong share-link addresses is after ten tries, not five.
- **A folder's settings are in a new order** (the switches together under the description, then the order of the photos, Collections and Locations). Nothing is stored differently.
- **New lines in the settings file**: `EXTRA_FOLDER_NAMES` (the names a place from elsewhere has had, so renaming it keeps its view counts) and `HEALTH_SET_ASIDE` (Health check rows you set aside), both kept by the admin, never typed. An older version doesn't know them: it ignores them and its Health check says they aren't settings (a typo?); delete the lines if you go back and that bothers you.
- **Visitor downloads are now each folder's own switch** (see the changelog), and fail closed: a gallery set to Everything, or on the old on/off line, has downloads off after this version until you switch folders on. Nothing is deleted: the old lines stay in `.gallery-config.php`, and going back to an older version finds them. A new line `PUBLIC_DOWNLOAD_ROOT` holds the main page's switch.
- **A folder can have `keepLocation`** in its own `.gallery-items.php` (the switch *Keep the location in files visitors get*); an older version ignores it and scrubs as the gallery-wide setting says. The map pin grouping row is gone from Settings (each folder's own stays).
- **An Only me folder can have `addressFile`** in its own `.gallery-items.php` (the switch *Links send the bare file*); an older version ignores it and shows the viewer page.
- **A folder that holds only folders shows the cover of its first card**, not simply the first photo by name; a cover you chose on the folder (**Cover photo** in its settings) is kept as it was chosen.
- **Going back to 2.6.4 or older** (the *Go back* button, or an older `index.php`) shows every **Only me** folder to anyone holding an *Everything* share link, because those versions treat it as an ordinary private folder. The mark stays in the folder's file, so upgrading again hides them again; *Go back* asks first when any folder is Only me.
- **Every thumbnail, tile and cover is made again.** The pictures the gallery makes got a new name (it now keeps the photo's colour profile), so each one is made again the first time it is looked at after the upgrade. On a big gallery on small hosting, the first visitors wait for it; *Prepare media* in Settings does it ahead of time.
- **Dates taken are read again, and may sort differently.** A photo's or video's taken time is now the clock time its camera wrote, for every photo alike (a phone's time was converted to UTC, a camera's was not, so a folder holding both sorted by the zone's offset too). In a folder that holds both phone and camera photos the *Date* order can change, to the right one; the suggested Dates change the same way. Every file is read again the first time it is looked at, or ahead of time with *Prepare media*. A GPS block of zeros no longer offers a pin at 0 N 0 E.
- **Visitor CSVs gain a last column,** `utc_offset`, after `time_zone`. A spreadsheet or script that reads the columns by position and expects `time_zone` last needs the one extra column.
- **View counts start again from zero, once.** They are now kept under a key of each folder's own (`.gallery-stats-key.php`, guarded, beside `.gallery-stats.sqlite`) instead of a plain hash of the photo's path, which anyone who could fetch the database could test a guessed path against. The first visit after the upgrade drops the old table and compacts the file (the page-view total stays), and counting starts again. From then on a folder copied with its dot files keeps its counts wherever it is shown, and renaming it loses nothing. Going back to an earlier version shows no counts for these folders.
- **The sign-in box is called `lens`** (it was `access_code`), and the page shows the gallery's own icon. A script that posts `access_code` or `login_password` still works. A wrong entry says "Out of focus."
- **A file whose name starts with a dot is no longer a photo** (macOS `._IMG_1.jpg` copies, and a `.hidden.jpg`). Health says how many are left out.
- **A password longer than 72 bytes is refused** when it is set (bcrypt reads only the first 72); existing passwords keep working as before.
- **A settings file that can't be used now stops the gallery instead of opening it.** A `.gallery-config.php` that isn't valid JSON, isn't an object, is **empty** (zero bytes, only the guard line, only blanks or comments), starts with a byte-order mark or can't be read by the web server used to mean "run on the defaults", so a gallery closed with *Close the public gallery* opened to everyone. Now every address answers **503** with a short page that names the file and what is wrong, until you fix it, put `{}` in it (that still means "no settings") or delete it to start the first-time setup again.
- **Linked files are not followed.** A `.gallery-cache` folder or a data file (`.gallery-items.php` and the others) that is a link is no longer read or written through. A folder whose data file is a link counts as unreadable and is hidden from visitors, and Health names each linked `.gallery-cache`. If you pointed one at another disk on purpose, make it a real folder or file there.
- **A place from elsewhere named like one of your folders no longer takes its place.** If a place in *Folders from elsewhere* has the same name as a folder in the gallery, the gallery's own folder wins everywhere, the place isn't shown and Health names it. Rename the place if you want both.
- **A visitor's country is no longer taken from CloudFront's or Vercel's header** (any visitor could add one behind most proxies). It comes only from Cloudflare's own header (with the Cloudflare setting) or from the country file; with neither it is unknown. If you relied on those headers, turn on *Look up the country of each address*.
- **Files with a picture's name that aren't pictures are left out.** An empty `.jpg`, or a text or web-page file saved as `.jpg`, no longer shows as a broken tile; Health names them and nothing on disk is touched.
- **The capture dates kept for sorting are now in a guarded file.** They were in `.gallery-cache/taken3.json`, a plain file that holds the names of the folder's files and could be read by its address on a server without the `.gallery-` rules; they are now in `taken4.php`, which answers 404 like `meta1.php`. The old plain file is removed the first time a folder of the gallery is looked at with the date order, or by the thumbnail clean-up; any left (the cache off with the order by name, or a place from elsewhere) are named in Health under *Left behind*, with a button that removes them. The dates are read again once. With **ENABLE_THUMBNAIL_CACHE** off nothing is written there any more: the date order reads the files on every look.
- **A new note's name can't have a dot in it** except the one before `.md` (a dot becomes `_`), so a web server that hands any name with `.php` in it to PHP never gets a note. Notes that already have dots in their names keep them.
- **Nothing else behaves differently** until you use something new: **Collections** (a new file, `.gallery-collections.php`, beside `index.php`; an older version ignores it), **Only me**, **Gallery of its own** (`unlisted`, `ownGallery` and `allowOriginals` in a folder's own `.gallery-items.php`, `addr` on a photo whose address was replaced, `ownGalleries` in the gallery's own) and the new Prepare media line (**Tidy leftover thumbnails**). **Going back to an earlier version** is safe for what is private (an Only me folder is just Private there, so the private-view password opens it); a *Gallery of its own* mark is ignored, collections are not shown, and photo links stop working. See [Only me](private-and-sharing.md#not-listed-a-folder-only-you-can-open) and [Collections](notes-and-folders.md#collections).

**Upgrading to 2.5.0** from 2.4.2: replace `index.php`. **Subfolders are now on by default**: a gallery that never set `AUTO_GROUP_BY_FOLDER` will start showing its subfolders as cover cards (the scan skips dot and system folders). If you want the old behaviour, switch *Show subfolders* off in Settings. A gallery that had it set keeps its choice. *Folder style* is now Cover cards or Flat; an older `inline` still works and means Flat with *Show folder names* on. New files: none.

**Upgrading to 2.4.2** from 2.4.1: replace `index.php`. Nothing stored changes, and nothing in how it works. Only the license changed: from 2.4.2 it is MIT with the Commons Clause (see [LICENSE](../../LICENSE)); versions up to 2.4.1 stay plain MIT.

**Upgrading to 2.4.1** from 2.4.0: replace `index.php`. Nothing stored changes. The signed-in browsers table now shows **Addresses** and **Device changes** counted from each browser's history file, so existing browsers show the right numbers at once. A browser that was flagged *a different device of the same kind* only because of an iPhone's own networking stays flagged until you press *Looks fine* (new ones are not flagged). The About icon now opens a new tab, and the new-link form's "easy to guess" note only appears when the link really opens something private.

**Upgrading to 2.4.0** from 2.3.2: replace `index.php` and open the admin. Things to know:
- **Private-view guests type the password once** (and so does anyone else who relied on the old fixed cookie): sign-ins are now a token per browser, which you can see and end in *Settings → Signing in and passwords → Browsers signed in*. You stay signed in as the owner (the old stay-signed-in token is swapped for a new one the first time). Both lengths start at **3 days**.
- **New links start at 2 browsers**, not unlimited (`DEFAULT_LINK_USES`; 0 is unlimited). Links you already have are untouched. A link set to *Off* for downloads now gives none, even of public photos.
- **First-run setup asks for a code** in `gallery-setup-code.php` beside `index.php`, instead of using a timer. A gallery that already has a password is not affected.
- **No lock icon on the page.** The admin is at `?admin` (or `…/admin`); on a computer it opens the shell. The gallery-wide map switch (`ENABLE_MAP`) is gone: a map is available wherever photo locations are allowed.
- **New files**, all guarded and all in `.gitignore`: `.gallery-browsers.php`, `.gallery-browsers-log.php`, `.gallery-signin-<id>.php` (one per signed-in browser), `gallery-setup-code.php`, `.gallery-ffmpeg.php` and the lock files `.gallery-ffmpeg.lock`, `.gallery-archive-1.lock` and `.gallery-archive-2.lock` (the note of where ffmpeg is and the locks that older versions kept in the server's shared temp folder; the old ones there are no longer used and can be deleted: `gallery-ffmpeg-*` and `gallery-archive-*`), and, only if you switch the country lookup on, `.gallery-geo.php` and `.gallery-geo-state.php`. Add the names to your backups' ignore list if you keep one. *Files this gallery has made* in Settings lists them all.
- **The country lookup is optional and off.** Turning it on downloads one 4 MB file from DB-IP to your server. The only other request the server makes itself is the daily look at GitHub for a newer version (on by default; `CHECK_FOR_UPDATES` switches it off).
- **For people who edit the code:** `index.php` is now built from the parts in `src/` by `php build.php`; edit `src/`, never `index.php` (see CONTRIBUTING).

**Upgrading to 2.6.6** moves the visitor logs into [one SQLite file](private-and-sharing.md#the-visitors-tab-the-log) (`.gallery-visits-<random>.sqlite`) and adds the **Visitors** tab, which needs **pdo_sqlite**. The older logs (`.gallery-linklog-*.php` and the public address's stand-in record in `.gallery-links.php`) are **not** carried over and nothing reads them; the Health check lists them under *Left behind* with a **Remove them** button for when you have seen the new log work. The caps on a log (5,000 timeline lines, 2,000 visitors…) are gone, the public log's *keep for* setting became **Keep visitor records for (days)** and covers every link too (0, keep until trimmed, to start with: a line `LOG_PUBLIC_DAYS` in `.gallery-config.php` is ignored), and a new **Warn when visitor records pass (MB)** setting watches the size. Going back to an earlier version loses nothing of the new log, but that version doesn't read it.

**2.6.6 also adds the backup and the Health dashboard.** The first visit after the upgrade makes a backup (`.gallery-backup-<random>.zip`, with its note `.gallery-backup.php`; the Health check's looked-through results are kept in `.gallery-health-cache.php`), then one a week. See [the backup](admin.md#the-database-and-the-backup). Going back to an earlier version leaves those files where they are, unread (an older version that finds a visitor log made by a newer one writes nothing into it). The backup is a ZIP with a fresh secret name each time; keep your server rule for files starting with `.gallery-` in place. Share links, settings and captions are not changed by any of it.

**Upgrading to 2.3.2** adds [an old address that keeps working](private-and-sharing.md#an-address-of-your-own) when a link's address changes (working, paused or killed, 10 ways in per link), a **came in on** line on the Visitors tab, and links in the admin that jump to one setting. Nothing stored changes; a link made before it simply has no old addresses. A new share link now starts on **Just the public gallery**.

**Upgrading to 2.3.1** adds [your own address for a link](private-and-sharing.md#an-address-of-your-own), [closing the public gallery](private-and-sharing.md#closing-the-public-gallery) and `…/admin` for the sign-in. If you use the tidy share address on nginx or Apache, **replace its rule with the newer one** in [The address, and the server rule](private-and-sharing.md#the-address-and-the-server-rule) (the old one keeps working for random addresses only, and the admin's check says it needs updating). It also adds three things to [share links](private-and-sharing.md#share-links): the **Show a preview photo** choice (links made before it have no picture until you switch it on in *Edit*), the **Just the public gallery** scope, and the opt-in [log of the public address](private-and-sharing.md#logging-the-public-address) (`LOG_PUBLIC_VISITS`, off). Nothing stored changes; the public log, once on, writes `.gallery-linklog-ffffffffff.php` and `-items.php` beside `index.php`, which the `.gallery-` server rules and `.gitignore` entries already cover.

**Upgrading to 2.3.0 or later** adds [share links](private-and-sharing.md#share-links), off until you switch on *Allow share links*. Nothing stored changes. Once links are used the gallery writes `.gallery-links.php` (the links) and a `.gallery-linklog-*.php` for each (its log) beside `index.php`, and stamps a hidden id into the `.gallery-items.php` of a folder a link covers; add the two new names to `.gitignore` and your backups (below). On a private photo or a private folder's card, the link button now asks you what you mean, and is gone for everyone else.

**Upgrading to 2.0.8 or later** changes one default: a gallery that has never had its photo order set now runs by date taken, oldest first, so videos sit among the photos they were shot with (before, by file name). A gallery that groups photos by filename keeps name order, and an order you chose yourself is never touched; to keep the old order, pick **Name** in Settings (or `"PHOTO_SORT_ORDER": "filename"`).

**Upgrading to 2.0.9 or later** moves the lock from beside the title into the icon strip (joined to the archive icon), and signing in with it, as the owner too, returns you to the page you were on instead of the admin page; the gallery title still leads to the admin.

**Upgrading to 2.2.0 or later** changes nothing stored: private folders, photos' own privacy and every folder setting are read exactly as before. What is new is how they are shown and changed (the three looks of the lock, *Going through a private folder first*, and folder settings that save by themselves, with no Save button).

**Upgrading to 2.1.0 or later** removes the *Photos* (*Media*) tab from the admin: its job moves to the gallery itself, as a pencil on every tile and in the viewer (caption, link, place, Private, Location, Cover) and the *Select* button, which takes over from *Arrange* (placing photos by drag and drop is part of it). Folder settings is now the admin's first tab, and the Private tab's links open that photo's editor. Nothing stored changes.

**Upgrading to 2.0.11 or later** changes a few things you will notice: the visit total moves from the icon strip into the line under the title; the strip now stays at the top of the screen while you scroll; opening a folder no longer jumps to its cover photo; and you get an **Arrange** button for placing photos by hand (nothing is stored until you use it). A Home Screen app you already added keeps its old icon until you remove it and add it again, and on an iPhone a family member may need to sign in once inside the app (the lock) because the Home Screen app keeps its own cookies.

**Upgrading to 2.0 from 1.x** leaves the gallery looking the same, with three notes: `?download` now redirects to this repository instead of serving the script (serving it would hand `ADMIN_PASSWORD` to any visitor); view counts carry over (1.x's `.gallery-stats.json` is imported on the first request with `TRACK_VIEWS` on, then removed); and you may see a new setup notice counting photos in subfolders when `AUTO_GROUP_BY_FOLDER` is off. See [CHANGELOG.md](../../CHANGELOG.md).

**Keeping runtime data out of git.** If your deployed gallery is in git, add these two lines to `.gitignore` (what the gallery writes holds GPS, password hashes, the install secret, share-link addresses and visitor IP addresses, the weekly backup ZIP among it):

```
.gallery-*
gallery-setup-code.php
```

Every name the gallery writes starts with `.gallery-` (the settings, the data files, the logs, the backup, the thumbnail folder `.gallery-cache/`), except the one-time setup code file. *Files this gallery has made* in Settings lists them all.

`.gallery-items.php`, `.gallery-config.php`, `.gallery-collections.php`, `.gallery-links.php`, the visitor log (`.gallery-visits-*.sqlite`), the view counts (`.gallery-stats.sqlite` with its `.gallery-stats-key.php`) and your `.md` files can't be regenerated. The gallery makes a weekly backup of its own files (see [the database and the backup](admin.md#the-database-and-the-backup)); for the rest, use the admin's JSON export for captions and your host's backups.
