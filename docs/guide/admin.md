# The admin

First run and signing in, the shell, the Health check, passwords, and the files the gallery makes.

← [Guide index](README.md) · [Project README](../../README.md)

## The admin

### First run and signing in
A new gallery has no admin password, so there is no admin yet: `?admin` is only a one-time "Set up your gallery" page. So that whoever reaches it first can't simply take the gallery, the first request makes a small text file, **`gallery-setup-code.php`**, beside `index.php` (a guard line, then `Setup code: K7QP-X2MV`), and the page asks for the code in it: open the file with your host's file manager or an FTP program, type the code, then choose a password (8+ characters with a letter and a number) and you're signed in. The code can be typed in lower case, with or without the dash. There is no time limit to race; a wrong code is throttled like a wrong password (a few tries, then a short wait), and the file is deleted once a password exists. Nothing else changes while there is no password: the page is the only thing behind `?admin`, the public gallery is untouched, and it needs HTTPS (or `localhost`). If the folder can't be written to by the web server, no code can be made, but nothing could be saved either: the page then shows the exact settings-file text to create by hand. To skip all this, put `ADMIN_PASSWORD` in the settings file. (Older versions opened the page for five minutes after an upload, or for fifteen after `touch .gallery-setup`; that file is now ignored.)

After that, visit `?admin` (or `/admin`, or `?reveal` / `/reveal`) and type the password: there is no lock icon in the gallery, so the sign-in is an address you type (add it to your bookmarks). It is one form: either password brings you to where you were going, signed in (the private-view password shows private items; the admin password makes you the owner). Signed in as the owner, the gallery's title opens the admin on wherever you are (on a folder's page, that folder's settings), and the Log out icon in the admin (on a phone, in the Menu) signs you out.

The sign-in box is deliberately **not a password field**, so browsers and password managers don't offer to fill or save it: a text box drawn as dots, named `access_code`, read-only until tapped, on a bare page with a large lock drawing (which goes back) and no heading, button or word "password". Return sends it. The admin refuses plain HTTP (except on `localhost`), uses a fresh session on login (Log out also clears private view; how long you stay signed in is [below](#staying-signed-in-and-which-browsers-are-signed-in)), protects every save with a CSRF token and throttles guesses (5 wrong from one address in 15 minutes means a 60-second delay). Scripts may send an `Authorization: Basic` header instead.

#### Staying signed in, and which browsers are signed in
A sign-in used to last until the browser forgot it: a browser closing, or a phone closing a Home Screen app, ended it, and four hours without a visit did too. Now each browser that signs in (you, or anyone given the private-view password) gets its own **token**: a random code in a cookie (`HttpOnly`, `SameSite=Lax`, `Secure` on HTTPS, kept to the gallery's own folder). The server keeps only a hash of it in `.gallery-browsers.php`, with who it is for (owner or private view), when it was made and last used, when it ends, a short label for the device ("iPhone · Safari", never the raw user-agent) and a mark of the password it was made under. When the owner's browser has lost its session but still has the token, the admin opens without asking for the password. Every visit pushes the end out again, so regular use never signs you out.

- **How long:** `ADMIN_STAY_SIGNED_IN_DAYS` for you and `PRIVATE_VIEW_SIGNED_IN_DAYS` for private view, **3 days** each to start with (*Settings → Signing in and passwords*), counted from the last visit. **0**: until the browser closes (and, on the server, a day), and a lost session is not resumed.
- **The list.** At the end of that group, *Browsers signed in* shows every browser that is signed in: you or private view, the device, when it signed in, when it was last here and when it stays until, with this browser marked. **Sign out** ends one (it is asked for the password the next time it comes: a lost phone, a shared computer), **Sign out all other browsers** keeps only the one you are using. Neither needs a new password for anyone else. Each browser also has [an address history and alarms](#address-history-and-alarms), under **History**, and *Recently signed out* lists the ones that have gone.
- **Log out** ends that browser's token on the server, so a copy of the cookie stops working too; other browsers stay signed in.
- **Changing a password** ends every token made under the old one (the owner's for the admin password, guests' for the private-view password); the browser you changed it from gets a new one.
- **A script** that sends the password with every request (a `curl` with `-u`) makes a token each time; those last an hour, are kept to the last ten, and never push a person's browser out of the list.
- Tokens made by 2.3.2 (the *stay-signed-in* cookie) work once more and are swapped for the new kind. Everyone who was in private view types the password once after the update.

The token only gets you in: a change still needs the page's own security token. A Home Screen app keeps its own cookies, so it needs one first sign-in of its own.

#### Address history and alarms
Every browser in the list remembers where it has been used from. Each sign-in, each new address and each change in what the browser says it is, is added to a file of its own, **`.gallery-signin-<id>.php`** (a guard line, then one line each: when, why the line was written, the **full** IP address, the country if known, and what the browser said it was). The table counts two things from it: **Addresses** (how many different IP addresses the browser has come from) and **Device changes** (how many times the identity it sends changed). An iPhone's own background networking (*NetworkingExtension*, *CFNetwork*) sends a different identity from Safari on the same phone: it is logged and counted, but never flagged, and the table says how many of the changes were that. **History** (or either number) opens the stored lines as they are, newest first, under the counts, in a box that scrolls; *Download all N lines (CSV)* gives the whole file (opens safely in a spreadsheet). *Most networks in 24 hours* counts *networks*: an IPv4 `/24` or an IPv6 `/64`. Nothing is capped: lines older than `BROWSER_HISTORY_DAYS` (**90**) are trimmed, and the Health check shows how big all of it has grown (*Address history*) so you can watch it.

A browser is **flagged** when it looks different from when it signed in; the flag is amber or red on the list and counts in Settings' number and the Health check:
- *A different device of the same kind* (amber): the same family of device (a phone), another model or browser version.
- *A different kind of device* (red): made on an iPhone, now used as a Windows computer.
- *A new country* (red): needs [the country file](#the-country-file). Used from the US before, now from DE.
- *Many networks in 24 hours* (red): more than `BROWSER_NETWORKS_ALARM` (**20**) networks in a day (a phone moving between Wi-Fi and mobile data uses a few; a shared cookie uses many).

**Looks fine** on a flag says you have seen it (it comes back only for a *new* reason). Each flag can instead **sign the browser out by itself**: `BROWSER_END_ON_DEVICE`, `BROWSER_END_ON_FAMILY`, `BROWSER_END_ON_COUNTRY`, `BROWSER_END_ON_NETWORKS` (Settings → Signing in and passwords), **all off** to start with. A browser that is signed out, expires or loses its password moves to **Recently signed out** (kept `BROWSER_ENDED_DAYS`, **30**), with the reason, and its history stays until it ages out. A script's one-hour token keeps no history and raises no flags.

#### The country file
Off until you turn it on (Settings → Signing in and passwords → *Look up the country of each address*, a two-step *Turn on…* that says what it does first). It downloads **one** file, [DB-IP's "IP to Country Lite"](https://db-ip.com/db/download/ip-to-country-lite) (about 4 MB, 9 MB unpacked; CC BY 4.0, so the credit is on that row), once, and then roughly monthly: the page load that finds the file seven days old fetches the new one in the background (after the visitor has their page where the server allows, else when you next open the admin). It is looked up on **your server**: no visitor's address is ever sent anywhere. **This is the only time the gallery makes a request of its own to another site** (maps, which load from visitors' browsers, are separate), and only if you switch it on. *Turn off* can keep or delete the file. Behind Cloudflare, CloudFront or Vercel (with `TRUSTED_PROXY` set) their own country header is used first, even with the file off. `COUNTRY_DB_URL` (a config-file-only setting) names another source: an `https` address, or `http` only to `127.0.0.1`; `{ym}` stands for the year and month.

### What the admin has
The sidebar's top group, **The whole gallery**, holds *Features*, *Edited*, *Shares*, *Collections* (once you have made one) and *Settings*; under it is the folder list (always with **Root**, and with hidden subfolders greyed and tagged *hidden*; while the gallery is shown *Flat*, a lock beside each folder makes it private or visible with one press, and the phone Menu's folder list has the same). Picking a folder shows that folder's own heading with its tabs (*Folder settings*, *Notes*); on the whole-gallery pages those tabs are not shown. **Features** says what the gallery can do and where each thing stands: *Features you can switch on* (state, real numbers, a button to the setting; no switches here) and *Things you do on the gallery itself* (the lock, pencil, star, Select, notes, the backup; the first four each with a **Show me** that opens a page with photos on it, a folder when the front page has none, and points at that button with a small tail on its note, which follows the button if the page moves). *Act on many photos at once* mentions sharing only when share links are on. A gallery with nothing configured yet opens on it. On a phone the three whole-gallery buttons are one row.

- **A Select button** in the icon strip to act on several photos at once (make them private or public) and to place photos next to each other by drag and drop (see [photo order](notes-and-folders.md#photo-order)).
- **A lock and a star on every tile**, and the same two buttons in the viewer, for you only (never visitors or private-view viewers). The lock (top left) is solid red and labelled *Private* when the photo is private, and a faint open lock when it's public; press it and the photo flips between the two. In a private folder it has three looks, because a photo can be private on its own, public, or just follow its folder: a dashed lock labelled *Folder* (private only because its folder is), a solid red *Private* (kept private on its own) and an open lock (public, though its folder is private). Each press goes to the next: Folder, then Private, then Public, then Folder again. The star (top right) is gold on the photo that is its folder's cover (the gallery's own, at the top level) and faint on the others; press one and that photo becomes the cover, and the gold star moves to it. On a desktop the faint ones appear on hover. Each gives a short message and doesn't open the viewer. In the viewer they are the two buttons just left of zoom (star, then lock), lit gold or red when they apply to the photo shown, and they keep the tiles behind them in step. If the admin session has ended it says so. They use the same saves as the admin's, so nothing else is touched.
- **A pencil on every tile** (lower left; on a desktop it appears on hover, like the lock and the star) and in the viewer's toolbar, for you only. It opens the viewer on that photo with its editor: *Caption*, *Information link*, the *Private*, *Location* and *Cover* switches on one row, and the place (latitude, longitude, label) below them. In a private folder the *Private* switch has the same three looks as the lock (*Folder*, *Private*, *Public*), and a line under it says what the next press does. On a phone the editor is a sheet under the photo, so the photo stays in view, with a *Hide keyboard* button; on a wide screen it is a panel beside the photo. Nothing needs a Save button: the switches save as you press them, and the text saves when you leave a field, a second after you stop typing, and when you press *Prev* or *Next* (to go through a folder's photos one by one, typing as you go) or *Done*. A link that doesn't start with `http://` or `https://`, or a place that isn't a latitude and longitude, is marked and not saved. A place read from a photo's GPS but not yet kept is offered with *Keep the location from the photo*: typing a caption never keeps it by accident. The tile's badges and the viewer follow each save. Two tabs can't clobber each other (a record that changed elsewhere is refused, with an explanation). `?photo=NAME&edit=1` opens a photo with its editor up; the Private tab's links use it.
- **No photo list in the admin any more.** Captions, links, places, privacy, covers and making many photos private or public are all done on the gallery itself, with the pencil, the lock, the star and *Select*.
- **Folder settings** (the Root is a folder too, so its tab is called the same): the title or display name, dates, position, description, the order of the photos (including its own *Put first* list), how the folders under it appear (*Cards* or *Flat*, and in Flat whether to show their names and notes: two buttons each, the one Settings says outlined and the folder's own choice solid) and a *Privacy* section with three switches that look alike: *Private folder*, *Show photo locations publicly* and, indented under it (the map shows only photos whose location is public, so it is dimmed, with a note, while locations are off), the map. The gallery's top has the same form (without the folder switch), so a notes file isn't needed just to name it. **Nothing here has a Save button:** a text field saves when you leave it or a second after you stop typing, the order choices and every switch as soon as you change them, and each says *Saving…* or *Saved* beside its own label. A value that isn't valid (a position that isn't a whole number) is marked and not saved. Each save is checked against the record's fingerprint, so a change made in another tab is never overwritten, and a save sends only the field you changed, so nothing else is touched. (A browser without JavaScript still gets a Save button.)
- **Notes**: every `.md` in the folder, edited as raw text and saved byte-for-byte; *Save*, *Save As* and *Delete* are separate (the latter two ask first) and locked to `.md` names. A file missing `{gallery}` is shown as not active with a one-click fix.
- **A readable JSON copy** of what you typed (captions, locations, links, names, covers, private flags; no passwords or visitor records), for this folder or the whole gallery: under *Settings → Files this gallery has made*, below the backup ZIP (which is the real backup).
- **Visitors** (a sidebar tab after Settings, while there is something to show): [who looked at what](private-and-sharing.md#the-visitors-tab-the-log), for the public address (if you log it) and every share link, narrowed by country, source or a search, in four views, with CSV export and trimming. It needs SQLite and is hidden without it.
- **Shares** (a sidebar tab, while [share links](private-and-sharing.md#share-links) are on): your links and what each has been used for, with a **See visitors** button, and the buttons to pause, extend, replace the address, revoke or delete, **Preview as this link**, and **Copy**, **Share…** and a **QR code** for each. A **Share** button also sits in the icon strip of a private folder's page, **Share…** on the Edited tab's private-folder rows and in Select mode, and the viewer's link button on a private photo asks whether you mean a share link. **Several links at once:** the *Select* button beside *New link* turns the state pill of each link into a tick; a bar at the bottom then counts them and offers *Select all*, *Clear*, *Done*, *Pause*, *Resume*, *Extend…*, *Revoke…* and *Delete…* for the picked links (each done the way its button on a row does it; Revoke and Delete name the links, and Delete asks for a tick first, since the logs go too).
- **Collections** (a sidebar tab, once there is a collection): every [collection](notes-and-folders.md#collections) with where it lives, its address, what it holds, problems and the share links that include it. They stand among the folders in the list below, in italics; a collection's own settings are a folder's.
- **Edited** (while anything is private or set by hand): only what you set yourself, in one place: private and public flags, captions, information links, places you typed or removed on purpose, a photo's own location switch, and each folder's own settings (hidden, Not listed, name, description, dates, position, Gallery of its own, downloading originals from a photo's link, Cards or Flat and its names and notes, location and map switches, photo order, groups, stacks, cover), and a photo's new address. What the gallery read from the files is never listed. A summary line and chips (*All, Private, Captions, Links, Locations, New links, Folder settings*, each with a count), then one **closed card per folder** that has anything, its header saying what is inside (as filtered): press it to open it. An open card shows the folder's **cover as a picture** (press it to open the folder scrolled to that photo, ringed for a moment, to choose another), *Open folder*, *Folder settings* and the settings as pills; for a **private folder** also what opening it would do ("3 photos stay private · 39 photos become public when opened"), **Make public…** (asks first, with the counts) and **Share…**; each photo with a caption, link or place as a row with an **Edit** button (it opens the editor in that photo's own folder, so closing it leaves you on the folder's grid); pressing any photo's thumbnail, here or in the Health check's file lists, **shows it in its folder** (the grid scrolled to it and ringed in periwinkle for a moment); and the photos whose only edit is their privacy as thumbnails with a **lock that works** (press it to make the photo public, with an *Undo* for a few seconds; an open lock, a photo public inside a private folder, is made private again by the next press), as many as fill two rows, the rest behind **+N**. *Expand all* and *Collapse all*. The "Private isn't locked" warning, with the rules written for your server, shows at the top only while private is not locked (when it is, the Health check says so).
- Two tabs can't clobber each other: a save whose record changed elsewhere is refused with an explanation. The admin works at phone width.

### The shell

An **Admin** pill (top left of your own gallery page, on a computer) opens the **shell** on that folder: the admin's header and sidebar stay where they are, and the main area is one frame that shows either the gallery page or an admin page, so you stop jumping between them and losing your place. The header is `Gallery title / this folder` (each name goes to that folder's photos; the folder's parents are in the tree; a long name makes the line a little smaller, never bigger, then is cut short) over the sidebar's width, with its divider on the sidebar's edge; then two joined icon buttons for the folder you are in (*Folder settings* and *Notes*, starting exactly where the gallery's own icon strip starts below; the lit one closes again), and on the right an icon that opens the gallery on its own and a *Log out* icon, all drawn like the gallery's own icon buttons. The sidebar is *Features* (how many of the eight switchable features are on, or in amber how many need setting up), *Edited*, *Shares* (links in use, and *N new* when some have news since you last looked), *Settings* (a red number only when the Health check has something to fix) and the folder tree; the numbers are asked for again a moment after anything is changed in the frame. Pressing a folder in the tree opens that folder's settings; pressing the one you are already in shows its gallery instead. The folder tree keeps its names readable in a deep gallery (smaller steps, levels past the fifth stop indenting, the full name on hover, the folder you are in always in view). The pages in the frame are the ordinary gallery and admin pages: nothing in them changes, and `?admin` itself still works on its own address. On a wide window the shell stops growing where the gallery does (1400 px, centred), and an admin page in the frame keeps the classic admin's column width. The shell's address (`?admin&shell=1&folder=…&tab=…`) always says where you are. Only a signed-in request can be framed, and only by your own site; every other admin page still refuses to be framed. On a phone there is no frame: the ordinary pages carry one bar at the bottom (*Gallery*, *Folder*, *Notes*, *Menu*) that keeps the folder; *Menu* opens a sheet with the whole-gallery pages, the folders and *Log out*.

### The page keeps up when you come back to it
The admin is often left open in a tab while things happen: a visitor comes, a lockout happens, you do something in another window. When you come back to the tab (or bring the window to the front), the numbers in the sidebar (and in the phone's Menu) are asked for again, and an open **Visitors** tab refreshes its list and its pills by itself, keeping what you had chosen, an open **Shares** tab draws its list again (a link another browser paused, or that has run out, shows its new state), keeping the rows you had open, and in Settings **Browsers signed in** and **Prepare media**'s numbers do the same. It does this at most every 15 seconds, and never while something is open under your hands: a menu or dialog, the new-link form, a selection of links or a field you are typing in is left alone and the refresh catches up when you are done. Places where you edit are never swapped under your hands. Instead, when you come back to the window and something was changed somewhere else (another browser saved a setting, or the settings file was edited by hand; a folder's names, captions or marks were changed; photos were added, removed or renamed in the folder or below it, for instance by a sync, in which case it says where and what, such as *1 item added to random*, with the folder's name a link that opens it with what arrived marked and scrolled to), a quiet bar at the top says so, with **Refresh** (and **Dismiss**). A save you made on this page is not "somewhere else", so it never raises the bar. On your own gallery page a small pill at the bottom says when photos in the folder changed. The Health check does not re-run by itself (its checks take real time and network): its refresh icon does.

### New versions and Update now
Once a day (when you open Settings; the page asks after it has loaded, so a slow GitHub never slows it down) the Health check asks the project's releases page on GitHub which version is the newest. **Only when that is newer than yours**, a *Version X is out* notice appears at the top of the Health check with **Update now** and **View release**. Nothing is sent but an ordinary request (GitHub sees your server's address; nothing about your gallery, photos or visitors). *New versions → Check now* looks at once. The switch is `CHECK_FOR_UPDATES` (Settings → Server setup; off stops the daily look, Check now still works); `UPDATE_FEED_URL` is only for a mirror of your own or a test.

**Update now** replaces `index.php` and nothing else. It downloads the release's `index.php` and its `.sha256` from the project's own release address, and refuses (changing nothing) a download whose checksum differs, that is cut short, or whose own version isn't the release's. The file it replaces is kept as `.gallery-previous.php` (guarded, so a visitor asking for it gets a 404), the new one goes in with a single rename and is read back, and the page reloads. For a day afterwards a notice offers **Go back to X**, which puts the kept file back exactly as it was. Your photos, settings, captions and every other file are never touched. It needs the web server to be able to write `index.php` (and the folder it is in); where it can't, the notice offers only *View release*, with the reason, and you replace the file yourself as before. The check is only against the checksum published with the release, so it protects against a damaged download, not against a release published by someone else.

### Health check
**Settings** opens with a **Health check**: the running version and what it was upgraded from, PHP and its extensions, the settings file and passwords, folders from elsewhere, whether folders are writable, whether every folder's data file still reads (a damaged one is flagged before a save could overwrite it), ffmpeg, and, tested by your browser, the server rules ([below](server.md#locking-down-the-files)). It only looks. It counts only what needs fixing: *All good* when nothing does, otherwise *N things to fix* with just those rows (red = a problem, amber = worth a look; the one it can find that matters most, *private is not locked*, has a *Fix this →* link to the rules in Settings → Server setup, opened). Everything optional (tidy folder links, tidy share addresses, the nginx redirect, ffmpeg not found, passwords still stored as plain text, old "nothing found" marks) is a grey *optional* row behind the chevron button (*N optional*, or *Details*), together with everything that passed. Open it after an upgrade, a move or replacing folders.

### Passwords
Both passwords are stored in `.gallery-config.php` as **bcrypt hashes**, so a copy of that file doesn't give them away (a hash typed into the sign-in does nothing). New passwords are hashed on saving; a plain-text one (older file, or edited by hand) works and is replaced by its hash at the next sign-in, which signs everyone out once. Sign-in cookies are keyed with a per-install secret in `.gallery-secret.php` (deleting it signs everyone out). Pick long passwords: a short one can still be guessed from its hash. A forgotten password can't be read back: delete the `ADMIN_PASSWORD` line, create `.gallery-setup`, and open `?admin`. To write a hash yourself: `php -r 'echo password_hash("the password", PASSWORD_DEFAULT), "\n";'`.

### What a folder keeps
Each folder holds its own data: `.gallery-items.php` (captions, saved locations, cover, name, dates, the **private flags** of the folder and its photos and, once a share link has covered it, the folder's hidden id), `.gallery-stats.*` (view counts) and `.gallery-cache` (thumbnails, the sort cache and `meta1.php`, the record of what each file says about itself, GPS included, so it is guarded like the data files and covered by the `.gallery-` server rules). Settings, passwords, extra-folder paths, the sign-in key and notes live beside `index.php`. So **wiping a folder and putting a new one in its place keeps every setting working, but the new folder starts blank, and a folder that was private is public again until you mark it**. Keep its `.gallery-items.php` (or the Export download) before replacing a folder. If the new folder is owned by another user the gallery can still show it, but nothing can be saved there and thumbnails aren't cached; the Health check lists such folders.

### Files this gallery has made
The gallery never touches your photos, videos or notes. What it writes is small and sits beside `index.php` (settings, share links and their logs, the install secret, sign-in records) or inside each folder it shows (`.gallery-items.php` for captions, locations, private marks and names; `.gallery-stats.php` for view counts; the `.gallery-cache` folder for thumbnails), a mapped folder included. **Settings → Files this gallery has made** is the one place that shows all of it:

- **Show list**: each kind of file, where it lives, how many and how big, what it is for and what happens if it is deleted. A file whose name only *looks* like the gallery's (`.gallery-items.php.bak`, one without the guard line, a link) is listed as left alone.
- **Download ZIP**: one ZIP laid out as the files are on disk, from the folder `index.php` is in (a mapped folder appears under its name in the gallery), with a `README.txt` that says what each file is, where each mapped folder comes from, and how to put them back (unzip over the folder). It asks for the admin password again, is sent so that nothing keeps a copy, and does not hold thumbnails unless you tick them. There is no size limit: each data file is copied from disk to a temporary file in the server's temporary folder (so a file being written to cannot change while it is sent) and sent from there, never held in memory, and the copies are removed when the download ends; the page checks there is room first. It holds password hashes, the install secret, link addresses and visitor IP addresses: keep it private.
- **Delete…** removes everything the gallery made, in three steps: take a copy (or say you don't want one); the admin password and the word `DELETE`; a last button that says how many files go, above a *Show the files* list. It works from the same list as the ZIP, one file at a time, and only for files with an exact name the gallery makes and (for its data files) its own guard line; it refuses to delete anything at all if one entry does not check out or if the list changed since you looked, never follows a link, never removes a folder except an emptied `.gallery-cache`, and never touches a photo, video, `.md` file or `index.php`. **Nothing stays private afterwards**: the private marks are among the files deleted, so what you had marked private can be seen by anyone who reaches the gallery, and a closed gallery opens (the last step says so in red; move private photos out of the folder first if that matters). Folders you had added from elsewhere on the server disappear from the gallery (the folders are not touched). The gallery has no admin and shows plain; to start again add an empty file named `.gallery-setup` beside `index.php`, then open `?admin` within fifteen minutes and choose a password (the delete does not make that file itself, because that would leave the admin open to whoever arrived first). Every share link stops working. The settings file goes last, so a failure partway leaves a working gallery and says what is left.
- `tests/tools/skeleton/make-skeleton.sh` (read-only) writes a tarball of the gallery's own files and the names, sizes and dates of everything else (no photo contents), so the delete can be tried on a stand-in for a real gallery.

### Data files are guarded
Generated files (`.gallery-items.php`, `.gallery-stats.php`, `.gallery-login-attempts.php`, `.gallery-stay.php`, `.gallery-secret.php`, `.gallery-health.php`, `.gallery-update.php`, `.gallery-previous.php`, `.gallery-links.php` and each share link's `.gallery-linklog-*.php` before 2.6.5) hold captions, GPS and the exact names of hidden items. They are stored as PHP files starting with a guard line, so a direct request runs it, answers **404** and stops, with no server setting needed. The gallery reads them as plain text and skips the guard line; text is written with `<` and `>` escaped. Two are not PHP files and have no guard line: the optional `.gallery-stats.sqlite` (only counts keyed by a hash of each photo's path) and the visitor log, `.gallery-visits-<24 random letters and digits>.sqlite` (IP addresses, browsers, what each visitor looked at). The random name keeps the log's address from being guessed, the [server rules](server.md#locking-down-the-files) refuse both, and the Health check asks your browser whether the log can be fetched.
