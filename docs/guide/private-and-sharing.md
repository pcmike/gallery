# Private items, share links and sharing

Hiding photos, temporary share links, downloads, and how links preview when shared.

← [Guide index](README.md) · [Project README](../../README.md)

## Private items

For photos, videos or folders that shouldn't be on the public link but that trusted people may see in the same gallery. There are two ways in: a **[share link](#share-links)**, a temporary address for a person that you can limit, watch and switch off, and a **viewer password** for people who should always have access. Both are described below; share links come first in practice.

1. Make an **item** private, or a whole **folder** (covering everything beneath it, with its **Private folder** switch, or the lock beside it in the admin's folder list while the gallery is shown Flat). An item can be switched back to *public* inside a private folder, or *private* inside a public one, or set to simply follow its folder.
2. Set `PRIVATE_VIEW_PASSWORD`. Give people the address `?reveal` (or `/reveal`): a one-field form accepting either password; the private-view one signs that browser in (for 3 days from its last visit, [setting](admin.md#staying-signed-in-and-which-browsers-are-signed-in)) and returns you to the plain link. There is no lock icon in the gallery to press, and nothing on the page tells a visitor that a sign-in exists. Visiting `?reveal` signed in again, or clearing the browser's cookies, locks private items again in that browser. It is a **password, not a secret link**: links pasted into chats get crawled and can't be revoked.

A private item is removed outright for anyone without the password: absent from the grid, notes, viewer, counts, badges, map and link previews, and `?img=`, `?photo=`, `?folder=` and the video endpoint all answer "not found". A group whose members are all private disappears. The same HTTPS requirement and throttle as the admin apply. The cookie is specific to each copy of the gallery, so several galleries on one site never interfere.

### Going through a private folder first

A folder you have made private hides everything in it, and nothing is stored on the photos for that: they just follow the folder. That is the way to prepare a folder before anyone sees it.

1. Switch **Private folder** on in the folder's settings (or leave it on from the start).
2. Go through the photos on the gallery. Each tile shows what it is: a dashed **Folder** lock (private only because the folder is), a solid red **Private** (kept private on its own: it stays private when the folder opens) or an open lock (public). Press the lock, or use **Select** and its *Private*, *Public* and *Folder* buttons, to set the ones that must stay private. A banner at the top of the folder's page counts what opening it would do ("3 photos will stay private · 39 photos become public when you open it") and follows every change you make.
3. Switch **Private folder** off in the folder's settings, or just press the red banner on the folder's page. Either first asks, with the same counts ("3 photos stay private, 39 photos become public"), and only then opens the folder: the photos that followed it become public, those you marked stay private.

A photo that sits inside another private folder stays private too, and is counted with the ones that stay. The counts include everything beneath the folder.

**The main page shows you which folders are private** (you only; a visitor sees none of it, nor the folders). A folder you made private has a red **Private** pill on its card (**Not listed** on a [Not listed](#not-listed-a-folder-only-you-can-open) folder) (press it to be asked whether to make the folder public, with the counts), a folder hidden only because one above it is private has the dashed **Folder** pill, and in the row of folder buttons at the top of a folder's page each private folder has a small lock. Where a folder holds photos that are private on their own, its count line says so at the end: "253 photos · 7 videos (2 private ›)", or "36 photos · 6 videos (3 stay private ›)" on a private folder (the same number as its banner). **Press that bracket** and the folder opens with those photos first, in the order it already had; the sort button's *Private items first* shows as on, and the choice lasts for that visit only. In **Private items first**, "private" means photos marked private on their own (in a private folder everything is hidden, which would set none of them apart).

### Not listed: a folder only you can open

A folder can be **Not listed**: for the folder you keep for yourself and share from one photo at a time, the way you might once have left a folder with a blank `index.html` in it so the server wouldn't list it. Switch **Not listed** on in the folder's settings (it sits under *Private folder*, last of the three switches; it makes the folder private too).

- **You** see all of it, with a **Not listed** pill on its card and a banner on its page.
- **Nobody else does, however they come in.** A stranger, and a person with the private-view password, get the same "not found" as for a folder that isn't there, and the folder is left out of every list (cards, folder buttons, counts, ZIPs, previews). A photo you marked public inside it makes no difference. For that reason the lock on a photo in a Not listed folder doesn't mean Public or Private: it is an open lock when the photo's own link works and a solid red one when **Link off** (it doesn't; the tooltip says which). Press it to switch between the two; the folder's page says only that the folder is Not listed, with nothing to press.
- **A share link** opens it only if the link names it (*Only some folders*; the form asks first, because everyone with that link then sees all of it). An **Everything** link leaves it out, and so does a link that names a folder above it, so a link meant for "all my photos" never hands over the folder you meant to keep.
- **It is stored as private plus a flag**, so an older copy of the gallery still keeps the folder private (but there the private-view password would open it).

Like a private folder, it is only as closed as the server rule that makes a bare photo address answer 403 (the Health check says whether it is in place).

### A Not listed photo's own link

Each photo in a Not listed folder has a link that opens **that one photo** for anyone who has it, and it is short: eight letters and digits, `https://example.com/photos/Ab3x9Qz2`. Where the server's one-word rule is not set up (see *Share links*), the same link is `https://example.com/photos/?Ab3x9Qz2`; **Copy link** checks which one works and copies that. The page is that photo alone: no grid, no other photos, no way into the folder, kept out of search engines, and the link is not passed on to other sites. Its pictures and its message preview carry the same code; a wrong code is answered exactly like a link that does not exist.

- **Getting it:** there is nothing to make. Every photo in a folder has its link the moment you switch **Not listed** on. On the photo's tile, beside the pencil, press **Copy link** (the link); in the viewer, the link button copies it. **New link** (the link crossed out) asks first, then gives that photo a different code and copies it: the old link stops at once, for everyone who had it.
- **How it works:** the eight characters are worked out from the folder's hidden id, the file name and a secret of your install, so nothing is stored until you press **New link** (then a random string is kept on that photo alone). When someone opens a link, the gallery works out the code of each photo in your Not listed folders (about a microsecond each) and opens the one that matches. Renaming or moving the folder keeps every link; renaming the photo, or moving it to another folder, ends its link. A photo marked private on its own has none. A copy of the whole folder has the same hidden id, so its photos' links open nothing until the copy is removed.
- **Guessing:** eight letters and digits is about 218 trillion possibilities. A wrong link is counted like a wrong share link (see *Wrong addresses and the pause*, below).
- **Opening in the gallery, or sending the bare file:** the folder's switch **Links send the bare file** (under Not listed; off to start with) decides what the link does. Off, it opens the photo in the gallery's viewer. On, it answers with the picture itself (or the video, played inline and seekable) and nothing else, which is what you want for embedding in a forum or sending in a chat app. The bare picture is exactly what the viewer shows at full size: a JPEG, PNG, WebP or GIF is the file itself with its location removed for anyone but you (when **Scrub location data** applies), an iPhone HEIC photo is its converted JPEG (at most 2,400 pixels on the long side). It is not indexed, sends no referrer, and counts as a view and as a Not listed photo opened by its link in the public log. It does not depend on **Allow downloading originals**: the viewer's download button still gives the true original (HEIC stays HEIC), as before. To override the folder's choice for one link, add `?file` (the bare file) or `?view` (the viewer) to it by hand: `https://example.com/photos/Ab3x9Qz2?file`; nothing the gallery copies has it. Some forums and apps decide whether to embed from a file extension, and these links have none.
- **Downloads:** the folder's own switch, **Allow downloading originals** (off to start with, whatever the gallery's download setting says). There is no ZIP for a Not listed folder. The location is taken out of the file for anyone but you, people with the private-view password and share links set to show all locations, while **Scrub location data** (Settings) is on: to give someone the location, make a share link set to show all locations.
- **It is not a secret.** Anyone who has the address can pass it on; the code only stops someone with one address from counting up to the others. For an address you can limit, date, watch and switch off, make a [share link](#share-links).

### A gallery of its own

In a folder's settings, **Gallery of its own** (limits navigation) shows one album on its own. Someone who **arrives inside that folder** (an address typed or pasted, a link from a chat or another site, a bookmark) is offered no way up past it and no folders beside it, and the page is built without them, so their names are not in it. A folder inside it shows as usual; its own way back leads up to the marked folder and stops there. Someone who **comes in through the main gallery** keeps their way back: a short cookie (set only when some folder is marked) remembers where they came in, and a click inside the gallery is told from a typed address by the browser. Typing the main gallery's address always works. The owner and people on a share link are not affected, and with no folder marked nothing changes and no cookie is set. This is tidiness, not a lock: it does not hide public pages from someone who types their address.

## Share links

A share link lets someone see private things for a while, without a password and without being able to see anything else. It is an address (or a QR code) for one person or group: it can open a limited number of times, start and stop on dates you choose, and cover everything, only some folders or only some photos. Every link keeps a log of who looked at what. Turn on **Allow share links** in Settings (`ENABLE_SHARE_LINKS`, off by default); a link you made is then listed in the **Share links** tab.

### Making a link
Wherever you are looking at something private, you can share it:
- **A private folder:** the **Share** button in the icon strip of its page, the link icon on its card on the main page, or **Share…** on its row of the *Private folders* list on the Edited tab.
- **A photo:** the viewer's link button on a private photo asks *Share just this photo…* or *Copy link* (a plain link only opens for people who already have access).
- **Several photos:** **Select**, pick them, **Share…**.
- **Anything, with every option:** **+ New link** in the Shares tab.

The first four open a short form: **Who is it for?** (a name only you see), **Use the name as the address** (see below) and **Show only these photos** (or **Show only this folder**), ticked to start with. There are no browsers or Stops working rows: a link made here lets in as many browsers as the setting *New links can be opened by (browsers)* says (**2** to start with, 0 is unlimited) and never stops, and the window says so in words (*Up to 2 browsers can open it (their phone and their computer, say)…*) with a note on where to raise it for a group; change it in the full form, or with *Extend…* later. It then shows the address with **Copy**, **Share…** (the phone's own share sheet) and **QR code**. *More options…* carries what you typed into the full form. The address starts as the name for a folder, but **random for one private photo or a group that are all private** (a one-off share); unticking the box gives a random address right there and never opens the full form, and **Type my own instead…** is the way to the full form with the address box open.

**The full form** (*+ New link* on the Shares tab, or *More options…*) starts with the **name** and the **address** (see *An address of your own*), then one sentence that says what the link will do with the settings it has now: what is the default is plain grey, what is not is darker and bolder. Under it are four folded rows, each with its value on one line: **What they can see**, **How long and how often**, **Downloads and locations**, and **The opening page** (title, preview photo with *Choose…*, note and heads-up). A row that differs from the defaults has a *Changed* tag and *Back to the default*, and *Reset all* clears them. The defaults are: just the public gallery, unlimited opens, never ending, starting immediately, downloads and ZIP off, locations shown only where set, the gallery's title with an automatic preview photo and no note. **Edit…** on an opened link (it ends the paragraph that tells the link's settings in the same plain words) opens the same form filled in.

### What a link can see
A new link starts on **Just the public gallery** (nothing private); pick another choice in the form if the person should see more.

- **Everything**: the whole gallery, public and private, including what you add later. It leaves out a [Not listed](#not-listed-a-folder-only-you-can-open) folder: to share one, pick it by name under *Only some folders*.
- **Only some folders**, each with everything inside it, or **only its public items**. The picker is a tree: ticking a folder ticks everything inside it, and you can untick any you don't want (a folder with something left out shows a dash). The link keeps the folders at the top of what is ticked, and the ones left out (*Eurotrip, without Rome*): a folder added under Eurotrip later is still included, and one inside a left-out folder can be ticked again on its own. A [Not listed](#not-listed-a-folder-only-you-can-open) folder inside a ticked one is not ticked for you: tick it yourself. Downloads and ZIPs, which are chosen from the folders the link covers, take in everything inside a folder as they always did. (A [collection](notes-and-folders.md#collections) can be picked too, in italics, among the folders: the link follows it as you change it, and a link shows only the collections it names): every folder you pick has a small switch, *Everything* or *Public items only*. With the switch on, the private photos and videos in that folder (and in the folders inside it) are left out, and the rest of it is shown. So one gallery can hold `sunrises` and `sunsets`, a few items marked private, and a link to `sunrises` shows only the public sunrises while a link to `sunsets` shows the whole folder. A private item is shown through a *Public items only* folder only if you name it as a photo (*Some folders and some photos*, below). A folder that is private as a whole can't be set to public items only (nothing in it is public); the form says so. A link made before this keeps *Everything*. The link's paragraph on the Shares tab counts it folder by folder, for example *Sunrises (public items only: 31 of 38; 7 private left out)* or *Sunsets (everything inside: 52, 9 private)*.
- **Only some photos**, wherever they are (**+ Add photos** in the full form, or from Select).
- **Some folders and some photos**, in one link: pick folders (each with everything inside it, or only its public items) and single photos from anywhere. A person may see an item if it is inside a picked folder (a public one, for a *Public items only* folder) or is a picked photo, and nothing else private. "Show only what they can see here" starts ticked, so the link shows just what you picked. There is no way yet to leave a photo out of a picked folder. The link's front page shows the picked photos as plain tiles and a picked folder as a folder card; a link to photos only is just a grid of those photos.
- **Just the public gallery**: nothing private at all. The person sees exactly what any visitor sees, and the link's log shows who looked at what. Use it to find out who opens an address you post or send. It grants nothing, so there are no download choices and no *show only* box, and it starts with unlimited opens, no end date and no heads-up line (you can still set any of them). It can open in a public folder but not a private one.

**Public things are visible too**, as to anyone: a link to one private photo in a public folder opens that folder with the photo in the viewer, the public thumbnails are underneath, and closing the viewer lets the person scroll the public photos. If you would rather they see only what you picked, tick **Show only these photos** (on to start with for a link made from one photo, from Select or from a folder, and in the full form for every choice that limits what they see, folders included; it shows under *What they can see* and you can change it, later too with *Edit*. The quick Share on a folder has the same box, ticked). The pages they see then list nothing else, not even the public photos, and the folder grid shows only your picks. **It is a tidy view, not a lock:** a public photo can still be opened by anyone who knows its address. A person using a link is told nothing about other private folders: no counts, no locks, no hints.

A link remembers a folder by a **hidden id** kept in the folder's own `.gallery-items.php`, not by its name. Renaming or moving the folder keeps the link working; a new folder with the same name is not covered; a copied folder (the same id twice) is ambiguous and shows nothing; and a folder the web server can't write to can't be used for a link (the form says so). If a folder is deleted the link shows **Folder missing**, with *Take it out of this link*. Anything that can't be matched shows nothing: it fails closed.

### Options
- **Download originals** and **ZIP of a folder**, each: *Off*, *Everything* (every photo and video the link shows, public or private), *Everything but private* (the public ones only) or *Only some folders*. The link's own answer decides for the people using it; the gallery-wide *Let visitors download originals* is for people who came in without a link, and is hidden while the gallery is closed. For a link to just the public gallery *Everything but private* is the same as *Everything*, so it isn't offered.
- **Opens in:** the page a person lands on: the front page, or a folder the link covers. It is a menu with the folders as a tree, like the Media tab's.
- **Photo locations:** *Shown only* (the default: the places you have set to show, with a folder's *Show photo locations to visitors* switch and a photo's own Show or Hide) or *All* saved locations. A location that is hidden is removed from every download and ZIP the link hands out ([how](#downloads)).
- **Starts**, **Opens** and **Stops working**, in your browser's time zone. Opens are counted per browser, not per page: once someone is in they can keep looking until the link stops.
- **Heads-up:** a thin line at the top of the gallery, "The link being used to access this media expires on …", amber in the last day and dismissable. `SHARE_HEADS_UP` sets the default; each link can turn it on or off; a link with no end date never shows it.
- **Opening page title and note:** the gallery's title, a plain neutral title (one of a few such as "A shared gallery" or "Some photos for you", the same one every time for the link), or your own text; an optional note. Never a folder name.
- **Preview photo:** the **Show a preview photo** box puts a picture in the link's message preview (what Messages, Discord or Reddit show when the address is pasted) and above the title on the opening page (the whole photo at its own proportions, never cropped, up to 60% of the screen's height; a chat app cuts the *message preview* to its own card shape). It is on to begin with when the title is the gallery's own and off with a neutral title or your own text, and you can change it on any link. The form shows the picture the link will use as soon as the box is ticked, and you can accept it or press **Choose…** to pick another: a folder, then one of its **public** photos (a private photo can't be picked, and a link limited to some folders and/or photos lists only the ones it covers; and the choice is checked again every time the picture is used, so a photo that has since gone private or been deleted is quietly replaced by the automatic one); **Automatic** goes back. The automatic picture of a link limited to some folders and/or photos comes only from the **public photos that link covers** (never from elsewhere in the gallery, because the opening page and a chat's preview show it to anyone before the link is opened); if what it covers holds no public photo it shows the gallery's icon instead. The automatic picture is the front page's own cover photo if it has one and it is public, else the cover of one of the **public** folders (a public photo from the front page if there are no folders), the same one every time for a given link. It is chosen as a signed-out visitor would see the gallery, so a private photo is never used; if nothing is public there is no picture and the icon stays. The link's **Settings** shows the picture it will use (*Preview photo*). Anyone who sees the pasted message sees the picture, so leave it off for a link whose gallery shouldn't be recognisable.

### What the person sees
The address opens a page with one button, **Open the gallery**. **Pressing the button is what uses the link**, so a message app's link preview can't use it up. The same address opening again within 15 minutes (an app's own browser, then Safari) is not a second use. Every link that doesn't work (expired, used up, paused, revoked, mistyped, switched off) shows the same page, *This link isn't valid*, with nothing to press and no reason given. The page is not indexed, not stored and sends no referrer.

Once in, they see the gallery as the link allows: no owner tools, no lock for signing in, and no link button on private things (a plain link would be useless to them). What they look at is counted in the gallery's [view counts](settings.md) like anyone's, and they see those counts only if *Show view counts to visitors* is on.

### The address, and the server rule
A link looks like `https://example.com/trip/k7QpR2mX`: the gallery's own address and 8 letters and digits (links made before 2.6.5 have 16, and keep working), or **a name of your own** (see *An address of your own*, below). For that tidy form the server must hand the path to the script. **Settings → Server setup → Web server rules** has the rule for your gallery's address (it is one of the optional parts of the nginx and Apache blocks, written out in [The server](server.md#locking-down-the-files)) and a chip that says whether it works (the Health check says too; it is optional). Until it is in, the long form works as it is: `https://example.com/trip/?k7QpR2mX` (`?link=k7QpR2mX` works too).

The rule matches one word of 4 to 40 letters, digits and hyphens, with no dot and no closing slash. A photo (it has a dot) and a folder's own address (it ends in a slash) are never touched. It **replaces** the older rule that matched exactly 16 letters and digits (a link made before still works): remove the old one. The rule also has no "is it a real folder?" check, on purpose: a link and a folder can then share a name (`/trip/carol` is the link, `/trip/carol/` the folder), and a folder typed without its closing slash is sent on to the folder (by the gallery itself on nginx; on Apache it first takes Apache's own slash redirect, one extra step with the same result, and a link of that name still wins).

### Wrong addresses and the pause

An address that does not exist (a share link's, a Not listed photo's, an unknown `?photo=`, a bare word after `?`) is answered with the same "This link is not valid" page, status 404, whatever was wrong. A wrong address that is shaped like one (4 to 40 letters, digits and hyphens) is **counted**; **ten** in 15 minutes from one visitor pause that visitor for a minute, and during the minute even a right address gets a "Please wait a moment" page (status 429) that counts the seconds down and tries again by itself when the time is up. That is what stops anyone from guessing: at ten a minute, finding one of your addresses would take a very large network many years. What is **not** counted: a right address, a wrong `?folder=` or `?photo=`, a stray word that is not shaped like an address (under four characters, over forty, or with other characters), tracking parameters like `?fbclid=` that chat apps add (they are ignored), you, and anyone with the private-view password. The pause is for addresses only: it never stops anyone browsing the gallery or signing in (the password has its own count, five). A visitor is the connection: a household or office shares one, so set `TRUSTED_PROXY` if you are behind a proxy.

### An address of your own
The link form has **Use the name as the address**, ticked to start with: the link's name ("John Doe") becomes `…/johndoe` (letters and digits, no hyphen) and a number goes on the end (`johndoe2`) if that is taken or is a word the gallery uses. A link that opens private photos still starts on the name, with a yellow note that a name is easy to guess and that unticking the box gives a random one. Unticking the box for a public link opens the address field with the cursor in it; for a link that opens private photos it gives a random address (**Type my own instead** opens the field). **Random** gives a code that can't be guessed. Or type any name of 4 to 40 letters, digits and hyphens (shown in lower case; it opens in any case). It is checked when you save: it can't be the name of a folder or file in the gallery's top level, a word the gallery uses itself (`admin`, `index`, `reveal`, ...), or an address another link has or had. A short or ordinary name can be guessed by someone who tries (the same short lockout that holds back wrong tokens applies), so keep the random one for anything sensitive. Changing the address signs out anyone signed in through the old one, and the old address either keeps working (see below, and the default) or is paused. Emptying the field gives the link a new random address.

**Keep the old address working.** When you change an address that already exists (a random one to a name of your own, say), the form offers **Keep the old address working too**, ticked to start with (untick it to pause the old address instead). Ticked, the old address is not paused: anyone who opens it is sent on (a temporary redirect) to the link's present address, so the address bar shows the new one if they copy it, and the link's limits, dates and log are the same. A link has up to ten addresses that work at once (its own and nine kept old ones); each is listed under the link's *Settings* as **Also works at**, with how many visits it sent and when the last was, and **Pause** and **Kill** buttons. *Replace address…* is the "it leaked" button and pauses the kept addresses too. A kept or paused address counts as taken: no other link can use it.

An old address has three states. **Working** (under *Also works at*) sends people on to the present address. **Paused** (under **Paused addresses**, listed by first and last four characters) shows the "not valid" page, stays reserved to the link and keeps its visit totals; **Resume** puts it back to work (up to nine can work at once), and the list says how many times it was tried while paused and from how many IP addresses. **Killed** is for good: **Kill** (asks first) forgets the address, drops its totals and frees the name, so another link, or a folder, can use it; a one-line summary stays under **Killed addresses** (when, visits, IP addresses, tries; never the address itself) until you press **Clear**. A custom name that is killed can be taken by another of your links, and anyone still holding the old address would land on whatever uses the name next. A link remembers every paused address, however many. **Address**, the first line of a link's Settings, shows the address (a name whole; a random code by its last four characters).

When a link has more than one address, the Visitors tab says which one each visitor **came in on** (`via: carol-and-sam`, or `via: k7Q2…Tb4e` for a random code) in a line under the link's name in *Came in at*; people who came before the second address existed have no such line. The CSV export has the same `came_in_on` column, and each kept address in Settings says how many different IP addresses used it.

A folder added later (over FTP) with the same name does not take the address: with the rule above the link keeps `/trip/name` and the folder keeps `/trip/name/`. The Shares tab says when a folder shares a link's name. This needs the newer rule above; with the older one only random addresses work, and the admin's check ("tidy share addresses") says so.

### Closing the public gallery
**Settings → Share links → Close the public gallery** (`CLOSE_PUBLIC_GALLERY`, off) shuts the plain address. Then only these get in: you (signed in), anyone with the private-view password, and anyone who came in through a share link. Everyone else, for every address of the gallery, gets the page of a link that is not valid ("This link is not valid. Please contact the person who gave it to you."): the same page and status as a mistyped link, so nothing says there is a gallery. These stay open to everyone: a share link's own address and its opening page, the sign-in, and the preview photo of a live link (a chat app asks for it without a cookie).
- **Signing in:** `https://example.com/trip/admin` (or `…/reveal`) goes to the one sign-in (the admin password or the private-view password), as does `…/admin/` and `…/?reveal`. It needs the rule above in place; `…/?admin` always works.
- **Needs a way in:** it is refused while share links are off or no admin password is set, and share links can't be switched off while it is on (open the gallery first). If it is on in the settings file but one of those is missing, it does nothing and the setup notice says so.
- **The public address log** has nothing to log while the gallery is closed; its earlier records stay in the Visitors tab.
- **Not a lock on the files:** the gallery's pages are closed, but the web server can still hand out a photo file to anyone who knows its exact address unless the rule that makes a bare photo address answer 403 is in place (see the Health check). A folder typed without its slash is not sent on for a stranger, so a closed gallery doesn't say which folders exist.

### Sending a link
**Copy** puts the address on the clipboard. **Share…** opens the phone's share sheet. **QR code** opens the code large at once (white, with the gallery's icon in the middle) to hold up to a camera, with **Copy** (the picture, to paste into a message), **Save** (the picture) and **Done**.

### Statuses and changes
**How many browsers can open it.** A link counts *browsers*, not page views: each new browser that presses *Open the gallery* is one (the same address within 15 minutes counts once, so an app's own browser followed by Safari is one). Once the limit is reached the link shows **Used up**: the next new browser is turned away (the Shares list shows it as an amber *blocked try*), and everyone already in keeps looking until the link ends. That makes the limit the way to keep a link for one person from being passed around: a new link starts at **2** (a phone and a computer; *Just one* is stricter), and a link for a group is made *Unlimited*. When someone you meant gets a new phone, *Extend…* lets one more browser in. Setting a limit on a link that has already been opened by more browsers stops *new* ones; those already in stay in, so to cut them off give the link a new address (*Edit…*).

Each link is **Active**, **Paused**, **Used up**, **Expired** or **Revoked**. *Pause* and *Resume*, *Extend…* (a used-up link is asked how many more times it can be opened, with *Unlimited* taking the limit off; an expired one is asked when it should stop working; one that is both is asked both; the same button is on the row for either), , *Replace address…* (a new address; the old one stops at once and anyone who is in is signed out; name, settings and log stay. Its dialog has **Cancel**, **Random**, which gives a random code, and **Custom…**, which opens Edit on the Address so you can choose a name of your own), *Revoke* (final: it stays listed with its log) and *Delete…* (which also deletes its log). The sign-in a link gives is checked against the link on every request, so pausing, revoking, replacing or letting it expire cuts off people who are already in.

### Preview as this link
**Preview as this link** opens a new tab showing the gallery exactly as the link does, so you can check a folder-limited link before you send it. A strip at the top says whose view it is, lists what the link includes and what it doesn't (**What's included**) and has **Exit preview**. **Nothing you do in a preview is counted or logged.** A browser has one set of cookies for all its tabs, so while a preview is on, *every gallery page in that browser* shows the link's view (each carries the strip, so you can't mistake it for your own); the admin pages stay yours and the Shares tab says a preview is open, with **End preview**. A preview ends by itself after four hours.

### The Visitors tab (the log)
Everyone who opens the gallery without being you is in one log: the people who used each share link, the people who came in with the private-view password (shown as **Private view**) and, if you switch it on (below), the people who opened the plain public address. **Visitors** is a sidebar tab after Settings; it appears while share links are on, or the public address is logged, or something was logged before.

**The log needs SQLite.** It is kept in one SQLite file beside `index.php` (`.gallery-visits-` and 24 random letters and digits, then `.sqlite`: the random part is there so its address can't be guessed even where the server rule that refuses `.gallery-` files is missing, and the Health check also asks, from your browser, whether the file can be fetched). That needs PHP's **pdo_sqlite** and a folder the web server may write to. Without them nothing is logged and the Visitors tab is hidden: the logging switch in Settings is greyed with the reason, Health says "Visitor log: needs SQLite", and share links themselves keep working. View counts don't need it (they fall back to a JSON file). A damaged log is caught by the Health check, which offers to restore it from the weekly [backup](admin.md#the-database-and-the-backup) or to set it aside and start a new one (nothing is deleted).

A visitor is an address with a browser, named plainly ("Safari on iPhone"), under each source it used: someone who used the public address and a link is in the list once for each. For each the log records what they **saw** (on their screen, even as a thumbnail, and how many times: once for each time a page was opened with it on screen, counted from 2.6.5 on), **opened** (large, in the viewer, or played, for a video), **downloaded** (an original or a ZIP), and which folders they opened. Tries that were turned away are logged with the reason (paused, replaced…). A link's records stay when it is revoked, paused or ends; deleting the link deletes them.

**Narrowing it.** The top line of the tab is a row of pills and a search: **All** (a list of the countries seen, by their two-letter codes with how many visitors each; tick any number, or *All countries*) and **Sources** (a list: *Public* is the public address, *Private view* is the people who came in with the private-view password (it is listed once there are any), *Lockouts* is below, *Blocked* is the people turned away from links (see below), and then each of your share links; tick any number). The lists stay open while you tick and close with *Done*, *Esc*, a press outside or the pill again; on a phone they are sheets at the bottom of the screen. The **search** finds an address, a browser, a country code or a country's name (every word has to match). A country in a row, or a link's name in *Came in at* (the name is one pill with a small arrow inside it: the name picks just that link in the pills above, the arrow goes to the link's row on the Shares tab), picks just that one, and pressing an IP address puts it in the search. An address takes the room of a whole IPv4 address (255.255.255.255); a long IPv6 address is shown as its first two groups and its last (`2600:1700:…:b21e`), with the whole address as its tooltip, in the search once you press it, and in the CSVs. The columns keep their places whatever the choices leave. A pill that is narrowing the view has a small **×** inside it that clears just that pill (the Media view's two menus too); a line under the views says "Showing 5 of 14" with **Clear**, which clears them all. The choices apply to all four views and to the CSVs.

The four views are the same for everything: **Visitors** (one line per address and source, with where, browser, **Came in at** (for the public address the folder, the front page or a Not listed photo, each a link that opens it; for a link, the link's name), first and last seen, **Visits** (for a link the presses of *Open the gallery*; for the public address and the private view the visitor arriving or coming back after half an hour) and **Opened** (photos, videos and folders they opened; the button goes to **Media** for that address)), **Folders** (a line per folder: *Opens*, *Media seen*, *Opened* (shown large or played, each file once), *Downloaded*, and when; the last three numbers are buttons that take you to **Media** for that folder and that kind), **Media** (a grid of what was looked at, with two menus that answer as you tick: **All folders**, listed as a tree where ticking a folder includes the folders inside it, and one choice: *Most viewed*, *Most recent*, *Photos*, *Videos*, *Private*, *Opened* or *Downloaded*) and **Timeline** (what happened in order, with a small picture on each line; every picture opens the folder at that photo). Nothing is capped; a list shows the latest 300 and says how many there are in all.

The **export icon** beside the search opens a menu. **This view** is a CSV of exactly what the tab you are on shows, with every choice applied: the pills and the search, and on Media the folders and kind (Photos, Videos, Opened, Downloaded and so on); it holds all of those lines, not only the first screenful, and it is named for the tab and for what it was narrowed to (`visitors-media-downloaded.csv`, or `visitors-media-maureen-US-203.0.113.5.csv` with a link, a country and an address in the search). The Folders and Media CSVs start with **link**, **country** and **search** columns that say what they were narrowed to ("all links" and "all countries" when they were not), and Media's also with the folders and the kind, so a file still says what it is once it has been renamed or put beside others; Media's has a **seen** column (how many times it was on screen, blank for what was logged before that was counted) beside opened, played and downloaded. With *Blocked* ticked it is the blocked tries. Below it are the four fixed CSVs: visitors, what they looked at (one line per visitor and item), blocked tries and everything in order; each follows the pills and the search and holds IP addresses. The Folders view has its own CSV through *This view*. On a phone's Home Screen app a CSV goes to the share sheet (Save to Files, Numbers, AirDrop) instead of taking over the screen, which has no way back. The menu also has **Trim the log…**, which takes out what is older than 7, 30 or 90 days or a date, for one source or all, says what would go before it does anything, keeps the totals (opens, views and the number of visitors) and offers the CSV downloads first. **New activity** since you last looked still shows on a link in the Shares tab, which now holds only your links and a **See visitors** button on each.

**How long records are kept** is one setting for all of them: **Keep visitor records for (days)** (Settings → Visitors and logs, `LOG_KEEP_DAYS`; 0, the default, keeps everything until you trim it). With a number, records older than that are removed once a day. **Warn when visitor records pass (MB)** (`LOG_WARN_MB`, 100; 0 turns it off) makes the Health check say, with the size and the oldest record, when the log has grown past that.

The address is the connection's. **Behind Cloudflare** or another proxy every visitor would look the same, so set `TRUSTED_PROXY` (Settings → Share links): `cloudflare` reads Cloudflare's own header, but only when the request really comes from Cloudflare's ranges (built in), and `proxy` reads `X-Forwarded-For` only from the ranges you list in `TRUSTED_PROXY_RANGES`. This also corrects the sign-in throttle and the wrong-address pause below. The Shares tab says so when it sees a proxy that has not been set up.

**Blocked.** Someone who tries a link that has ended, been used up, paused or replaced is turned away and written down (the address, the browser, which link, why, how many times). Tick *Blocked* under Sources to see every link's blocked tries at once, in place of the visitors; tick a link or two beside it to narrow to those links (or a country, or the search). Each row says why and what would let them in ("extend it", "resume it"), and its link's name takes you to that link on the Shares tab. The other way: a link's row on the Shares tab, when it has blocked tries, has **→ Blocked tries** beside **→ Visitors**, and the arrow beside a link's name on the Visitors list goes to its row. The export menu has **Blocked tries** (one line per address: link, address, country, browser, first and last tried, tries, why), which follows the same choices; the other CSVs ignore *Blocked*, and the other views say it is listed on the Visitors view. Blocked tries are not counted in the red number in the sidebar.

**Lockouts.** Too many wrong access codes (five in 15 minutes), wrong setup codes or wrong share links and photo links (ten) pause a connection for a minute. Each time one starts it is written down. It is in the list like any other visitor (someone at the door is one), as one line per address and kind (*Locked out: sign-in*, *setup code*, *addresses*, with a count when it happened more than once) and a line in the timeline; tick **Lockouts** under *Sources* to see only them. The Visitors number in the sidebar is a **red circle** while a lockout has happened that you have not seen, and goes grey once you open the tab. The Health check says how many there were in the last seven days, with a **→ Visitors** link that opens the tab already showing them. Your own tries are in there too. Without the Visitors tab (no share links and no public log) only a small count per day and kind is kept (`.gallery-lockouts.php`, 30 days, no addresses), so the Health check can still tell you something happened.

### Logging the public address
A link to just the public gallery tells you who used *that* link. To log **everyone** who opens the gallery's plain address, switch on **Log visitors to the public address** (Settings → Visitors and logs, `LOG_PUBLIC_VISITS`, off by default; it does not need share links, but it does need SQLite). The Visitors tab then lists them as **Public**, beside the people who used your links.
- **Who is logged:** anyone who opens the gallery in a browser that runs scripts. Not you, not people signed in with the private-view password (they are logged as **Private view**, whether or not this is on), not people using a share link (their link's records are separate), and not link-preview bots. A visit is a visitor arriving, or back after half an hour. It records the address, browser and country and the public folders and photos looked at; a private one is never recorded.
- **Where they came in:** when a visit begins with an arrival (an address typed or pasted, a bookmark, a link from another site or an app: the browser says it was not a click inside the gallery) the Visitors view shows **Came in at** (the folder, the front page, or a Not listed photo opened by its link), the timeline says "Arrived at" and how, and the CSVs have a `came_in_at` column and "arrived" lines. Opens of a Not listed photo are logged and tagged **Not listed**.
- **How long:** see *How long records are kept* above.
- **Turning it off** stops the logging; what was logged stays in the tab until you **Trim** it.
- **It stores every visitor's IP address.** Check what your local privacy rules ask of you (a notice on the page, a retention limit) and keep it only as long as you need it. Behind Cloudflare or another proxy, set `TRUSTED_PROXY` first or every visitor will look the same.

### What a link is, and isn't
A link is a secret address: **anyone who has it can use it**, up to its limits, so keep each as narrow and short-lived as you can and revoke one that went further than you meant. An address is not a person: two people on one network, or one person on two phones, can look alike in the log. Wrong addresses are throttled like wrong passwords.

## Downloads

**Original.** The viewer's caption bar has a download button that saves the file exactly as it sits on the server (a HEIC stays HEIC). On a phone it opens the share sheet, so **Save Image** / **Save Video** puts it straight into Photos (anywhere that isn't possible it is a normal download).

| Visitor | Button | File |
|---|---|---|
| The owner | always | as it is on the server |
| Private-view password | always | as it is on the server |
| Someone using a [share link](#share-links) | as that link allows (off, everywhere it covers, or some folders) | location blanked unless the link shows all saved locations |
| Anyone else | only with `PUBLIC_DOWNLOAD_MODE` (off; everything or chosen folders) | location blanked (always, while *Scrub location data* is on, which it is to start with; with it off, only if the gallery hides it) |

A folder can opt out of the scrubbing for its own photos: its **Locations** section has **Keep the location in files visitors get**, under *Show photo locations to visitors for this folder* (it shows only while that is on). With it on, a visitor's copy of a photo from that folder keeps the location where the gallery shows it; a location the gallery hides is still taken out, the folders inside it are not covered, and nothing changes for you, the private-view password or a link that shows every location. It is off to start with, so a folder you forget still scrubs.

The same rule covers the full-size picture in the viewer, a video as it plays (including ranged requests) and a Not listed photo's own link: with **Scrub location data** on (Settings, under *Let visitors download originals*, on to start with) a visitor who isn't signed in never receives the coordinates of any photo or video, shown or hidden on the page. To give someone the location, make a [share link](#share-links) set to show all saved locations. A photo that carries a location is then sent by the gallery itself rather than handed to the web server (a photo with none still goes the fast way). Private items stay a 404.

**How the location is removed.** Nothing is re-encoded and the size doesn't change: the bytes holding the location are overwritten in the copy sent, and your file is never touched. Blanked: EXIF GPS (JPEG, HEIC, PNG, WebP), GPS and place names in XMP, city/sub-location/state/country in IPTC, and a video's location atom. Date, camera and caption stay. Thumbnails and share previews are re-encoded and never carry a location. **Not covered:** maker notes, GIF and BMP, and text you wrote yourself. A damaged file whose metadata can't be read safely isn't sent as an original at all (422; the viewer shows the re-encoded copy; a video isn't played). Only hidden-location files for signed-out visitors go through PHP, and those responses stay out of shared caches.

**Everything as one ZIP.** Signed in as the owner or with the private-view password, an **archive** button beside the gallery icon saves every original (or, on a folder's page, that folder and below) as one ZIP. It says how many files and how big and **always asks first**. It's a 404 for anyone else. Files are exactly as on the server, locations included.
- It is streamed as it's built (1 MB at a time), so nothing is stored and memory stays flat; files are stored, not compressed, so the size is known up front and a cut-off download shows as incomplete. Over 4 GB or 65,535 files it uses ZIP64.
- Each download holds a PHP worker for as long as it takes, so **only two run at once** (a third gets a 503), there is no resume, and more than 100,000 files is refused. Your host must allow a request that long (shared hosts, proxies and `request_terminate_timeout` may cut it off; with nginx the script sends `X-Accel-Buffering: no`).

## Sharing and previews

Every link you'd paste gets a correct Open Graph preview: `?photo=`, `?folder=` (display name, description or notes, and cover photo) and `?map`. The gallery's own link shows the front page's own cover photo if it has one, else the cover of one of its folders (the cover you chose for that folder, else its first photo; never a video or a private folder, and the same all day); a gallery without folders uses one of its photos. Private items are nonexistent to a crawler, so pasting one never previews it. A shared video previews as picture and title, not a playable embed.

`?folder=Europe/France/Paris` needs no server setup and is what the gallery itself shares. To also type `/kb/Europe/France/Paris/`, map it onto the script: it is one of the optional parts of the nginx and Apache blocks in **Settings → Server setup → Web server rules** (written out in [The server](server.md#locking-down-the-files)), and a chip there says whether it works. The rule matches only paths ending in `/` (so it can't catch `index.php` or a photo), captures the name inside the `rewrite` (which makes nginx escape spaces), and needs php-fpm to pass the original `REQUEST_URI` (the standard `fastcgi_param` does). On Apache it needs `mod_rewrite` and `AllowOverride FileInfo`, and the `B` flag stays: it escapes spaces, `&`, `+` and `#`.
