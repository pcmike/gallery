## Fixed (2026-10-20, second pass)
- [x] **The nginx rule the Share links tab (and the README) gave was refused by nginx: `unknown directive "16}$"` (owner).** nginx reads an unquoted `{` in a pattern as the start of a block, and the rule's `[A-Za-z0-9]{16}` had none quoted. Both patterns are now quoted. This was never run through a real nginx before (only its text was checked), so it was tested properly this time: the generated rule passes `nginx -t` on nginx 1.26 with php-fpm, the tidy address opens the link page, the tab's probe address answers with the "invalid" marker the tab looks for, and wrong codes and the gallery itself behave; the old rule fails with the owner's exact error. The generated Apache `.htaccess` rule was run through real Apache 2.4 the same way and works. The two server-rule checks in the suite now decode the generated rule and check that no `{` is left outside quotes (they used to assert the broken text). **To apply on your server:** replace the two lines in your `gallery.inc` with the quoted ones (the tab shows them), then `nginx -t` and reload.
- [x] **Copy gave "Couldn't copy: select it and copy by hand" on the first press (Safari, owner).** The share form's Copy used only the newer clipboard call and showed an error the moment a browser refused it; Safari refuses a first press. Now the older, synchronous way goes first (it always happens inside the click), the newer call is the second choice, and an error shows only when both are refused. Tests: the browser suite makes the browser refuse each way in turn and checks that copying still works, and that only "both refused" shows the error (it fails if the older way is removed).
- [x] **The Share links tab's Copy buttons, and the Copy buttons on the server-rule snippets, did nothing at all when the browser refused** (no error, no copy). They now use the same copy.
- [x] **Copy image could never work in Safari.** The picture was made after the click, and Safari only allows a clipboard write while the click is fresh. The picture is now made as soon as the code is drawn and handed over at once; Save image uses the ready picture so a phone's share sheet is asked inside the click.
- [x] **The heads-up line ("The link being used to access this media expires on …") is centered** across the top, with its close button at the right edge (owner).
- [x] Tested for the first time: a link for **one photo** opens straight into the viewer on that photo, and the folder then shows only that photo (it did; the test is new).
