# Changelog

All notable changes to this project are documented here. Versions correspond to the `GALLERY_VERSION` constant in `index.php`.

## [2.0.8] - 2026-10-14

### Added
- **A link that opens the page with the small overview map showing.** End a gallery or folder address with `#map`: the small map opens, scrolls into view and gets the highlight border a photo gets when a link snaps to it (not the full-screen map, so nothing to close on a phone, and it isn't remembered as that visitor's choice). A small link icon in the open map's top right corner copies the address; the full-screen map has the same icon in its bottom left corner (copying its `?map` link) instead of a text button.

### Changed
- **Photos and videos now run by date taken, oldest first, by default** (before, by file name). A gallery that has never had its photo order set changes order on upgrade; pick **Name** in Site settings (or `"PHOTO_SORT_ORDER": "filename"`) to keep the old order. A gallery that already chose one keeps it, and so does one that groups its photos by filename (the default is still name there, which keeps a group's files in sequence). A video sits among the photos it was shot with.

### Fixed
- **Date order put iPhone videos last.** A video's date was taken from its movie header, which holds when the file was last saved or exported, not when it was shot, so a batch of videos copied off a phone hours after the photos sorted after every one of them. Date order now uses the recording time the phone keeps in the video's metadata (with its time zone) and falls back to the header only for a video that has none. Dates already worked out are read again once (the cache file is now `taken3.json`).

## [2.0.7] - 2026-10-12

### Added
- **Sharper tiles.** Each photo's tile is now a square cut from its middle at two sizes (560 and 1080 pixels) and the browser picks by how wide the tile is and how dense the screen is, so a phone gets enough pixels for every one of its own (before, a 480 pixel thumbnail was stretched across a column about 1000 pixels wide, and a portrait photo had even fewer across). Progressive JPEGs. Only tiles near the screen load.
- **Prepare thumbnails** (Site settings): makes every photo's tile pictures ahead of time, a few seconds' worth at a time, with a count and a progress bar; stop and carry on whenever you like.
- **"Put first" is one list you order** (Site settings): *Private items*, *Videos* and *Located photos*, each with a switch and a drag handle. Drag a row (a finger works, and so do the arrow keys on a focused handle) to set the order the three stack in; what is switched on always sits above what is off, and a sentence under the list says the result ("Videos, then photos with a location, then the rest."). New setting `SORT_PRIORITY`; the default order is as before, so nothing re-sorts until you move a row.
- **A folder's "Put first" is the same list**, always shown under the same *Site's / This folder's own* pills the other sort rows have. It follows the site's until you change a switch or drag a row; then the pill moves to *This folder's own* (the section's heading says "custom" as you go, before you save) and *Site's* puts the site's list back. A list that would sort exactly as the site's does counts as the site's and isn't stored; every switch off while the site puts something first is the folder's own, and its sentence says what the site does. A folder with its own order always opens that section by itself. It is stored with the folder (`photoSort.priority`); the visitors' sort button keeps its switches and uses the folder's or the site's order.
- **A lock on every tile for the owner**: red "Private" on a private photo, a faint open lock on a public one; press it to flip the photo. Visitors never see it.
- **Add to Home Screen as an app** (owner only for now): the pages carry a manifest and an icon so the gallery can open full screen with no Safari bars.

### Changed
- **On a phone the viewer's counter and buttons are a row across the top**, with the close button last, and the photo takes everything below it (a tall photo is as tall as the screen allows) on a plain black backdrop. Nothing is left to tap near the bottom edge, where Safari answers a tap by bringing its toolbar back and costing a second tap, and nothing is laid over the photo. The viewer stays sized to what is visible, so Safari's bars never cover the photo.
- **Zoomed in on a desktop, the viewer's controls sit on a soft dark pill** (the counter and buttons at the bottom, and the close button and arrows), so they stay readable when the photo runs underneath them. The close button and the arrows are drawn icons (a circled cross, chevrons) in identical round boxes, centred exactly, instead of text characters that sat a little off. Each control lights its own box when the mouse is over it, so you can tell which one you are on; the map button's icon still shows blue when it is on and the link button still flashes green when copied.
- **The download button takes the photo from the browser's memory** (the viewer is already showing that exact file), so the share sheet opens at once.
- The download and gallery buttons above the photos use the same 8px gap as the map and sort controls.

### Fixed
- **In the admin, Site settings and the folder you were in are no longer both lit.** While Site settings (or Private) is showing, that folder is only softly tinted, so the one lit item is the one you are looking at.
- **On a phone the button row keeps its places.** The map and sort buttons stay at the left and the download and about buttons at the right, as on a desktop, on one line that never wraps (the buttons get a little narrower if there are many). 2.0.5 had pushed them all to the left.

## [2.0.6] - 2026-10-12

Never a video or a private folder; a gallery with no folders still uses one of its photos. A cover you set for the whole gallery still wins.

### Fixed

## [2.0.5] - 2026-10-12

### Changed
- **On a phone, the viewer's download button saves to Photos.** It hands the original to the share sheet ("Save Image" / "Save Video") instead of a download that lands in Files. If Safari insists on another tap the button lights up and says so; anywhere sharing a file isn't possible (or a file is over 150 MB) it is the plain download as before.
- **On a phone the map, sort, download and about buttons sit together in one row.**
- **Quick links to the folders beside the one you're in.** A swipeable row of pills under the breadcrumb on a folder's page, in the order the parent page shows them, the current folder lit (up to ten; with more, a window around it plus an "All" pill back to the parent). Private folders stay hidden from visitors.
- **The sort button is left out of a listing laid out by a notes file** (a for-sale page with no folders, where your notes set the order), and there is a *Sort button* switch in Site settings to hide it everywhere.
- **The gallery link's preview picture** (when you haven't chosen a cover) is a photo picked from anywhere in the gallery, never a video or anything private, and the same one all day, instead of whichever photo happened to come first.

### Fixed
- **Ordering by date didn't use the capture date for most files.** It read dates only from JPEGs, and only where PHP's EXIF extension was installed; HEIC photos and videos fell back to the file's modified date. It now reads the capture date from JPEG and HEIC photos and the creation time of videos, with no extension needed, and uses the camera's recorded time zone when there is one.

## [2.0.3] - 2026-10-12

### Added
- **Photo order.** A sort button above the photos: by name or date (taken, else the file's date), either way round, with videos, located photos and (for the owner) private items first; the "first" choices stack. Site settings sets the default, each folder can override it, and a visitor's choice is kept in a cookie (or a `?sort=` link). Photos placed with `{photos:}` or a group keep your order.
- **Video everywhere, and better.** A play mark on every video tile, a real thumbnail (ffmpeg, else the browser's first frame), a hover clip and scrubbing with a mouse or a finger (up to 640 px clips, 320 px frames), in the grid, group strips, covers and the admin; on a phone the tile in view plays by itself. A video's location is read from the file.
- **Health check** at the top of Site settings: version history, PHP and extensions, settings and passwords, writable folders, unreadable data files, ffmpeg. It folds to one green line when all is well and shows only what needs attention.
- **Server checks.** The admin's browser tests whether photo files are refused by address, whether tidy folder links work and whether the nginx redirect works; warnings and rules that no longer apply go away. If nginx has the `internal` location but the setting is empty, it says so and offers to set it.
- **Rules to copy** for nginx and Apache, on the Private tab and in Site settings.
- **Downloads.** An original-file download in the viewer (locations blanked for visitors where hidden), and the whole gallery or a folder as one streamed ZIP for the owner and private-view visitors.
- **A setup notice when a folder from elsewhere on the server is missing or unreadable**, instead of silently showing nothing.
- **Passwords stored as hashes** in `.gallery-config.php` (plain-text ones are upgraded at the next sign-in); sign-in cookies are keyed per install.
- **ffmpeg status in Site settings**, green when found and red when not.
- **The cover photo is highlighted** in the grid, and folder and gallery descriptions take Markdown and alignment.

### Changed
- **The sign-in box is not a password field**, so browsers stop offering to fill it: a bare page with a lock drawing and one box.
- **Setup notices are for the owner** once an admin password exists.
- **A hidden location is hidden from visitors who aren't signed in, not from you.**
- **Pin grouping defaults to 1 mile** (was 50).
- **Phones:** the viewer's map starts off (its pin button pulses until pressed once), and the viewer is sized to the visible screen so Safari's bars don't cover the caption.
- **Site settings are grouped and collapsible** (with a chevron), with shorter explanations, and "Site settings → Server setup" jumps straight there. The admin drops teal for its blue-violet accent.
- **Admin controls are tidier.** Choices are pills instead of drop-downs, typed numbers have no arrows and a small box, the Export tab has "This folder" and "Entire gallery" side by side, the notes buttons line up with their boxes, and an empty gallery says what to do.
- **Date suggestions read naturally:** "Oct 1-11th, 2026" inside a month, "10/03/2026 - 11/02/2026" across months.
- **The gallery title is the way back to the admin**; the footer is gone and the about icon sits with the map buttons.

### Fixed
- **With "nginx internal redirect" set, photos and videos from folders brought in from elsewhere on the server failed to load.** Only files under the gallery's own address go through nginx now.
- **The server checks no longer pass or fail for the wrong reason** when photos come from elsewhere on the server.
- **First-run password boxes demanded 12 characters** though the rule is 8.

## [2.0.2] - 2026-10-11

### Added
- **Select several photos and make them private (or public) in one go.** A **Select photos** button above the thumbnail grid turns on a selection mode: pick thumbnails (or *Select all*), then **Make private** or **Make public**. Choosing none, or a photo that isn't there, changes nothing and says why.
- **Map pin grouping can be turned off, and goes below one mile.** `0` means no grouping (every photo its own pin), and fractions such as `0.1` are accepted, both site-wide and per folder, for very dense cities where photos are taken metres apart. Pressing a numbered pin now zooms in as far as street level (it stopped at a zoom where close photos still overlapped).
- **A page of only a few folders shows larger cover cards on a wide screen.** One to four folders and nothing else: one to four big cards, centred, instead of small tiles in an empty page. Phones and narrow windows keep the normal grid, and a page with loose photos or more folders is unchanged. The map buttons above them share that width, so they always sit exactly over the first card's top left corner, and the big cards load a larger picture (offered alongside the small one, so a phone keeps the small one) instead of stretching a thumbnail.

### Added
- **Opening a folder takes you straight to its chosen cover photo.** If the owner picked a cover photo for a folder (and it sits right in that folder), pressing the folder's card opens the folder already scrolled to that photo, which flashes briefly, instead of at the top of a long page. A folder with no chosen cover opens at the top as before, and the card's copy-link icon still shares the plain folder address.
- **Zoom in the photo viewer.** A zoom button in the caption bar (or pressing the photo, or the `z` key) steps through three views: the whole photo fitted to the screen (as before); **fill the width** of the window (a portrait on a small laptop now uses the whole width and you scroll up and down, never sideways); and **actual size**, one photo pixel per screen pixel, scrolling both ways. It always uses the original file at its own proportions, never stretched and never blown up past its own size, keeps its level as you move between photos, and Escape steps back to fitting before it closes the viewer. On a phone, swiping down scrolls a zoomed photo instead of closing it. Videos aren't zoomed.

### Changed
- **Folder cover pictures are sharp squares cut from the original photo.** They used to be squares cropped out of a small 480-pixel thumbnail, so a card looked soft and over-cropped, especially the large ones. The cover card now has its own picture: the largest square that fits the original (640 px for ordinary cards, 1200 px offered for large cards and sharp screens, the browser picking by card width), cut across the middle of a landscape photo and from the upper-middle of a portrait one, so most of the scene survives. It is cached like the other sizes and goes through the same private-photo checks.
- **The sign-in's heading is just "Enter your password"** (nothing about there being two kinds), for the lock's sign-in and the admin's, and has a grey **← Go Back** button, before Continue on the same row, that takes you back to the page you were on (the browser's own back, so the scroll position and open photo come back too).
- **One lock beside the gallery title is the only sign-in, replacing both the "Private view" footer link and the title-as-admin-link.** A small line-drawing of a closed lock appears to the right of the title when there is an admin password, or a private-view password and something private. It leads to one password box that tells the two passwords apart: the private-view password shows the private items, the admin password signs in to the admin (on the folder you pressed it in). The box is shared by both throttles (wrong guesses lock that address out of both). The title is plain text now, and a signed-in owner gets a small Admin link in the footer. After signing in or out you come back to the very same page (folder, open photo, open map); once you are in it shows open, and pressing the open lock locks the private items again in that browser. Whoever is signed in sees it open, the owner included, and pressing it signs them out: a viewer forgets the private-view password, and the owner's admin session ends too.
- **"Hide" is now "private" everywhere** in the admin and docs (Private switch, "Make this entire folder private", the red **Private** entry and page), matching the private-view password it pairs with.
- **A photo's privacy and location visibility are switches that save themselves**, in place of two dropdowns plus a Save button. **Private** is on when the photo is private (including by its folder); **Show its location** is on when its location is shown. Turning Private on, or a location off, is always stored on the photo itself, so it stays that way even if its folder's setting changes later. Flipping a switch no longer makes the caption form look out of date.
- **Password rules.** The admin password needs at least 8 characters with a letter and a number (it was 12 characters of anything); the private-view password may be any length (it was 6 or more).

### Changed
- **Adding a place from elsewhere on the server now puts its folders at the top of the gallery.** Adding `/space/trip` (holding `Paris` and `StTropez`) used to create a folder named after what you typed, with Paris and StTropez nested inside it. With only a path, the folders inside it now appear at the top, as if they lived in the gallery: Paris and StTropez, nothing in between. Give the place a name and it still shows as one folder with that name, as before. A real folder of the same name wins; photos lying directly in the added place are not shown (a setup notice counts them). In Site settings the row now takes a path and an optional name; in the settings file the new list is `EXTRA_ROOTS` (`EXTRA_FOLDERS` keeps its named form, so existing settings work unchanged).

## [2.0.1] - 2026-10-10

### Added
- **A settings file that survives updates.** Your settings live in `.gallery-config.php` next to `index.php` and override the defaults in `index.php`, so replacing `index.php` with a newer version no longer resets them. It is a one-line guard (a direct request answers 404) followed by plain JSON, like the gallery's other data files: never executed, so it can't run code and no cache can serve a stale copy. It lists only what differs from the defaults, so an improved default in a later release still reaches you. Hand-editing is forgiving (`//` notes, a trailing comma). A misspelt setting, a value of the wrong kind or one that isn't an allowed choice, an unreadable file or one that isn't valid JSON are each ignored with a note in the setup-notices banner, never a broken site. `GALLERY_VERSION` and the cookie name are not settable. `gallery-config.example.php` is a ready-to-edit template.
- **First-run setup: choose the admin password in the browser.** With no admin password `?admin` is still a 404, except for five minutes after `index.php` was last uploaded (or whenever an empty `.gallery-setup` file sits beside it): then it shows a one-time "Set up your gallery" page. Choosing a password (typed twice, 12+ characters) writes it into `.gallery-config.php`, signs you in on Site settings, and removes `.gallery-setup`; the page never appears once a password exists. Nothing on the public page hints that it is open, it needs HTTPS (or localhost) like the admin, it keeps any settings already in the file and refuses to overwrite one it can't read, and the claim is made under a lock so simultaneous visitors can't both win (six at once on nginx and on Apache: exactly one got in). If the folder isn't writable it shows the exact file to create by hand. Before this, getting into the admin at all meant editing `index.php` or writing a settings file by hand.
- **A "Site settings" screen in the admin** (sidebar) that saves as you go: there is no Save button to scroll to, each switch, choice or number is written the moment it changes (with a "Saved." beside it, one request at a time so quick changes build on each other; browsers without JavaScript get a Save button). Turning **on** something that publishes content or contacts a third party asks first, and turning **off** something visitors see (subfolders, videos, locations, the map, thumbnails) asks too, saying plainly that nothing is deleted; answering no puts the switch back. Each password has its own button beside its fields. The screen covers the gallery-wide switches: subfolders, folder style, videos, grouping by filename, photo order, thumbnails, view counting and public counts, photo locations, the map and its pin grouping, plus changing the admin password (typed twice, 12+ characters, you stay signed in) and setting or removing the private-view password, which are never shown back. **It writes only `.gallery-config.php`**: photos, captions, locations, hide flags, notes, folder settings and view counts are never read or changed, and switching a setting off only hides things. Only values that differ from the defaults are stored; turning on something that publishes content or contacts a third party asks first; `EXTRA_FOLDERS` and the nginx prefix stay file-only (shown read-only, kept untouched by a save, as is any key added by hand). It refuses to overwrite a settings file it can't read, or one changed since the page loaded; writes to a temporary file, reads it back to check it, and moves it into place; and, if the folder isn't writable, shows the exact text to create by hand.
- A setup notice when video files exist but `ENABLE_VIDEO` is off. A trip's `Videos/` folder used to vanish without a word: with video off the gallery sees nothing in it, so the folder never appeared. The collapsed "setup notices" banner now says how many `.mov`/`.mp4` files it found and ignored, and that `ENABLE_VIDEO` is the switch. It's a count only, never a folder or file name (a folder of nothing but ignored videos isn't one the owner has published, and the banner is visible to every visitor). The search covers the gallery root, its subfolders and `EXTRA_FOLDERS`, and is capped at 40 folders so a gallery dropped into a big existing site never walks all of it. Nothing changes when `ENABLE_VIDEO` is on, and nothing is written to disk either way.

- A clearer setup notice for `{photos:}`: one that names a photo inside a folder (the directive only reaches photos directly in the notes' own folder) used to report `Unknown file "eiffel.jpg"`, as if the file didn't exist; it now says the photo is inside a folder and what to write instead.

### Fixed
- **A `{color:}` on a single photo drew its ring underneath the picture, so you never saw it.** The ring is now drawn over the photo (cards for sold and reserved photos get the same).
- **A link copied from a paragraph on a folder's page pointed at the front page.** It dropped the `?folder=`, so the anchor didn't exist where it landed; it now keeps the folder.
- **A folder marked `{sold}` lost its SOLD ribbon once the picture loaded.** The greyed picture painted over it; the ribbon is now lifted above it (`{reserved}` was unaffected, since that picture isn't greyed).
- **The notes editor hid the `{gallery}` line, so saving any change switched the note off.** The editor now shows the file exactly as stored, and saving text with no `{gallery}` first line says the file is not active.
- **Number boxes in the admin (such as the pin grouping) had black arrows on a black background.** They now use the dark control style.
- **The site-wide counter was nearly meaningless: it counted every page load.** Opening the front page and two folders was three "views", a reload was another, and the owner's own clicking counted too, so the total ran several times the number of people. It now counts **visits**: one per visitor per half hour, however many pages they open (a small first-party cookie holds the time of their last page, and each page slides the half hour forward). It no longer counts the admin's own browser, link-preview and search bots, prefetches or prerenders, or `HEAD` requests, and the admin's own photo views are left out as well. The footer and the admin now say "visits", and the admin explains what is counted. Per-photo counts were already once per photo per half hour and are unchanged. Existing totals are kept, not reset, so the old inflated figure simply grows far more slowly from here; deleting `.gallery-stats.*` starts a clean count (and clears photo counts too).
- **The admin couldn't see its own hidden photos unless a private-view password existed.** A logged-in admin got a 404 for a hidden photo's thumbnail (broken thumbnails in the editor) and didn't see hidden items when browsing the gallery, because "admin counts as revealed" only worked through the private-view cookie. The admin now has its own reveal token, derived from the admin password so it can't be forged, set at every login (the form, a script's Basic header, first-run setup, and after a password change) and cleared at logout.
- **A saved Basic Auth password from an older version could bring the browser's login dialog back.** A browser keeps re-sending a password it saved when an older version asked for one; if that no longer matched, the gallery answered with a `WWW-Authenticate` challenge and the browser opened its own dialog again. The gallery never sends that header now: a wrong saved password gets the normal login form (HTTP 401) saying so, and typing the current password still logs you in.
- **The second photo's editor had an extra bar and padding above it** that the first didn't. A rule meant for the no-JavaScript fallback (where every photo's form is listed in turn) also applied with JavaScript.
- **A warning dialog read "This the map loads Leaflet…"** (a fragment spliced onto a fixed lead-in). Every warning is now a complete sentence used exactly as written, and a test fails if one isn't.
- **Captions, locations and hide flags could be deleted by switching a setting off.** The cleanup of stored entries for deleted photos treated any file the gallery wasn't currently showing as deleted. Switching `ENABLE_VIDEO` off hides every video, and switching the thumbnail cache off hides every HEIC photo; on the next page load the stored caption, location and hide flag of each of those files was removed. An entry is now removed only if its file is really gone from the disk. This mattered little while changing a setting meant editing the file, but the admin's new Site settings screen makes it one click.

### Changed
- **Maps are opt-in for the visitor, and the map no longer lands on top of the photo viewer.** The page map starts closed behind a *Show map* button (remembered per browser) and loads nothing from its third parties until pressed; before, a large map sat above the folders on every page. A Leaflet z-index bug that drew that map over the open viewer is fixed.
- **The map's two buttons are one joined control of two line drawings**: a folded map to show or hide it, and expand arrows to open it large, with a divider between them (the words are tooltips and for screen readers). **"View full map" now opens a large map over the page** that closes on a click outside it, Escape, or the cross; before, it left for a separate page whose only way back was a link, with its button at the far right of the screen. The map has no separate page any more: `?map` (and `?map&folder=X`) is the gallery page with the overlay open, with its own link preview (the map icon), so one link shows the map over the page it belongs to. The address bar follows the overlay, so copying it shares the map (there is also a *Copy link* button), and the browser's Back button closes it.
- **A small map in the photo viewer.** A photo with a visible location shows where it was taken in the top left corner of the photo, about half a mile across; click it to enlarge it (with *Open in OpenStreetMap*), and use the pin button beside the caption to turn it off or on (on by default, remembered). Only present when `ENABLE_MAP` is on, and the map library is requested only when such a photo is opened.
- **Line drawings instead of emoji, everywhere.** The map button, the caption, location, web-link and permalink badges, view counts, the "copied" tick, warnings, the video play tile and the cover star are one consistent set of small outline icons that take the text colour, so they look the same on every device (emoji rendered differently, and some were nearly invisible).
- **The photo's web link is in the viewer**, beside the permalink icon, drawn as a globe (the old ℹ️ was nearly invisible), on the cards too.
- **The viewer stays inside a folder.** The arrows and the "n / total" counter now cover only the open photo's own folder; before, Next ran from one folder straight into the next (or into photos a cover card was hiding).
- **Notes work the same everywhere.** A folder's own notes now read `{photos:}` and `{group:}` (they were ignored there), through the same code as the top-level notes, and order their photos the same way. Overview cover cards take a paragraph's `{sold}`, `{reserved}` and `{color:}`. A paragraph that mentions a folder in overview mode no longer adds a strip of thumbnails (the cover card is on the page). A `{photos:}` that names a photo inside a folder says so instead of calling it unknown.
- **A note's colour reaches the map.** A folder or group coloured with `{color:}` has its pins in that colour on the page map and on `?map` (and in the legend); `{sold}` and `{reserved}` give its pins the ribbon's red and orange.
- **A `{color:}` in a paragraph that mentions no photo or folder now shows**, as a coloured bar beside the paragraph, and the same bar sits beside the text whenever a paragraph colours a photo or folder too, so the two match; it used to do nothing at all when there was nothing to box.
- **The notes reference is split into six short tabs** (Start here with a complete example, Formatting, Directives, Photos, Folders, Fixing) instead of one long page.
- **Folder dates are suggested.** A folder's (or the gallery's) settings show the span of its photos' capture dates, or file dates when they carry none, with a *Use these dates* button that fills the box (as `05/02/2026–05/09/2026`, numeric and without spaces so it stays on one line on a cover card); nothing is saved or shown until you save, so you can still change or blank it.
- **The `?about` page describes what the gallery does today.**
- **"Gallery" in a folder's admin returns to that folder**, not the front page.
- **Single switches save the moment you flip them, and nothing asks for confirmation.** A folder's or the gallery's **Map** and **Show photo locations** settings used to be a tick box plus a Save button; they are now switches that save in place (a number such as the pin grouping saves when you leave it, and a bad value goes back with the reason beside it). The confirmation dialogs in Site settings (publishing something, switching something off, adding or removing an extra folder, setting the nginx prefix, removing the private-view password) are gone: every warning is orange text on the page, and what switching something *off* does appears beside the switch once it is off. Only deleting a notes file and overwriting one with "Save as" still ask, because those destroy a file. A browser without JavaScript still gets Save buttons.
- **Each folder, and the gallery front page, can have its own map, with its own settings.** In its settings: whether to show a map of its photos on its page (the front page is on unless turned off, as before; a folder is off until turned on, because turning it on makes the page load a third-party map) and **how close photos must be to share a pin** (blank uses the site-wide setting). A folder's map plots just the photos in it and below it that have a visible location, coloured by sub-folder, and has its own shareable page at `?map&folder=Paris`. Hidden photos and folders with locations off never appear for visitors, and the admin sees their own hidden photos.
- **A folder's description no longer appears on its cover card**, where it was cramped and messy. It lives on the folder's own page, in the centered box, and in shared-link previews.
- **The Notes tab explains everything.** The directive reference is no longer a collapsed list repeated in every editor. ## [2.0.0] - 2026-10-10

A large release, built and tested in phases on one branch and shipped as one version. **Everything new is off by default, behind its own constant** — a deployment that just swaps in the new file behaves like 1.1.1, apart from the one breaking change below and the two upgrade notes under it.

### Breaking changes
- **PHP 8.3 or newer is now required** (1.x stated 7.4). PHP 7.4 has been unsupported since 2022 and was never tested against this release; 8.1 and 8.2 are out of (or about to leave) security support. The minimum is 8.3, the oldest version still receiving security fixes (until the end of 2027), and it is a tested claim: the full test suite, the fuzzer, the cross-site-scripting check and the real-browser run all pass on PHP 8.3.32 as well as 8.4.26. On an older PHP the page stops with a one-line message saying so.
- **`?download` no longer serves the script.** It now redirects (302) to the GitHub repository. It used to `readfile()` the running `index.php` to anyone who asked; once `ADMIN_PASSWORD` lives in that same file, that would have handed the password to any visitor, and scrubbing secrets out of the output is a fix that has to be remembered forever. Removing the endpoint closes the whole class at once. An old bookmarked link lands on the repository rather than a dead end. `?about`'s download button now points at GitHub too.

### Upgrading from 1.x
- **Your view counts carry over automatically.** 1.x kept them in `.gallery-stats.json` (or a SQLite file with readable filenames). On the first request with `TRACK_VIEWS` on, 2.0 imports the per-photo counts and the sitewide total into its new stores, then removes the old JSON file (or drops the old SQLite table and compacts the file, so the old filenames don't linger in it).
- **You may see one new setup notice** if your folder has subfolders containing photos while `AUTO_GROUP_BY_FOLDER` is off: the collapsed "setup notices" banner says how many photos in subfolders aren't shown (a count, never a name).

### Added — folders
- **Nested folders, to any depth** (`AUTO_GROUP_BY_FOLDER`, off by default). A root like `/trip` with `Europe/France/Paris` underneath shows each subfolder as its own group. With `FOLDER_DISPLAY_MODE = 'overview'` (the default) each level shows one **cover card per subfolder** — a highlight photo, a label and a *recursive* photo count — plus any photos loose at that level, and clicking a card opens `?folder=Europe/France` and repeats. `'inline'` instead shows every folder's photos in one box, for people who use folders only to stay organized. A breadcrumb links through every ancestor.
- `?folder=` is validated against the script's own file list, never trusted: `../`, leading/trailing slashes, a file path, an empty value, a nonexistent folder, and a hidden folder all return 404. Symlinked subfolders are refused outright.
- `EXTRA_FOLDERS`: an explicit, admin-written map of virtual folder names to real paths (for archiving an old trip on another disk) — declared in code you control, so no symlink is involved.
- Per-folder **display name, description, a typed date-range subtitle, a chosen cover photo, and a position among sibling folders**, all editable in `?admin`. Stored inside the folder they describe, so they survive a real rename. The date range is deliberately never derived from EXIF: that would publish when you were away from home.
- A folder may carry its own `{gallery}`-marked `.md`, becoming a note box on that folder's page, scoped to that folder's photos only.
- A `.md` mention of a folder links to its `?folder=` page in overview mode.
- Stats, the thumbnail cache and per-item data are **colocated in each folder**, so two cameras' `IMG_0001.jpg` in different folders never collide, and a real folder rename carries its data along.
- A **"Last updated"** date in the header, derived from the newest file modification time across photos and notes — not a separately maintained marker, so it also reflects files uploaded by FTP.
- A setup notice when photos exist in subfolders but `AUTO_GROUP_BY_FOLDER` is off, so a first-time owner isn't left with a silently sparse gallery (a count only; the search is capped at 40 folders).
- Sibling folders order by an admin-set position, then naturally by name (Day 2 before Day 10), or by folder mtime under `PHOTO_SORT_ORDER = 'mtime'`.
- `?img=` and `?video=` validate the one claimed path directly instead of scanning the whole tree first — one tree walk per thumbnail is what made large, deep galleries slow (measured on 3,000 photos in 200 folders with PHP's built-in server: about 35 ms per `?img=` request before, about 9 ms after). The check rejects `..`, doubled/leading slashes, backslashes, NULs, folders, the script itself, `.gallery-cache`, symlinked folders, non-media extensions, and any name that isn't an exact-case match for a real file (so a case-insensitive filesystem can't dodge a per-photo hide flag). `?track=` and page loads still scan, since they need the whole group.

### Added — video
- `ENABLE_VIDEO`: `.mov` and `.mp4` are served as gallery items. No transcoding, no frame extraction. Tiles and share previews use one generic placeholder graphic; the lightbox plays the clip in a native `<video>`. Seeking works: real HTTP `Range` support (`206`, `416` past the end, malformed ranges ignored). A **duration badge** is read straight from the container's `mvhd` box.

### Added — captions, location, and the admin editor
- **Per-item captions, a web link, and a location**, one per photo or video. The lightbox shows the caption (or just a position counter) — **it no longer prints the raw filename.** Grid badges (caption, location, link) sit along the bottom edge.
- **`ENABLE_PHOTO_LOCATION`** (off by default) is the first of three gates: also needed are a per-folder switch and a per-photo setting (inherit / always show / always hide), all closed by default. GPS is auto-filled from EXIF for JPEG and HEIC where present; coordinates are validated before they reach any URL.
- **Two admin tabs can't silently overwrite each other:** a save whose record changed since the page loaded is refused with an explanation (per record, so different photos never conflict).
- The caption badge is a tap target that opens a popover on a phone, not just a hover tooltip.
- **`?admin`** (`ADMIN_PASSWORD`, empty = the code path doesn't exist): HTTP Basic Auth compared with `hash_equals()`, refused over plain HTTP except on localhost (with a page explaining why), CSRF-protected saves, a 4-hour session, and a failed-login throttle (5 wrong passwords from one address in 15 minutes imposes a 60-second delay; a request with no credentials — the normal first step of any login — doesn't count). Usable from a phone. It edits every item's caption/link/location, folder settings, every `.md` in the folder (raw text, saved byte-for-byte; **Save**, **Save As** and **Delete** are separate actions, and Save As and Delete ask for confirmation; a one-click fix for a missing `{gallery}` marker), and exports each folder's saved data (`.gallery-items.php`) as plain JSON, for one folder or the whole tree. Stale entries for deleted photos are cleaned up and reported.

### Added — hiding items, and Private view
- A **hide flag** per item and per folder (at any depth) in the admin. A hidden item is removed from the page, counts, lightbox list and every endpoint (`?img=`, `?photo=`, `?track=`, `?folder=`, `?video=`) for an unrevealed visitor — not merely styled invisible. A group whose members are all hidden disappears rather than showing "0 photos". Each item can also be forced *public* inside a hidden folder.
- **`PRIVATE_VIEW_PASSWORD`** and a discreet "Private view" footer link (`?reveal`): a password, deliberately not a secret link, since links pasted into chat get crawled. Same HTTPS requirement and throttle as the admin. A valid admin login counts as revealed too.
- An admin **"Hidden items"** summary across the whole tree in three tiers, and a persistent warning that hiding doesn't stop someone who already knows a file's URL unless the web server is locked down.
- **`NGINX_ACCEL_REDIRECT_PREFIX`** hands matching files to nginx via `X-Accel-Redirect`, so an nginx `internal` rule can make the bare file URLs unreachable. See the README for the nginx and Apache setups.

### Added — trip map
- **`ENABLE_MAP`** (off by default): every visible, located photo on one Leaflet + OpenStreetMap map, at its own shareable **`?map`** URL with a condensed preview on the gallery root. Photos within `MAP_CLUSTER_RADIUS_MILES` (default 50) merge into one numbered pin that zooms in when clicked; pins are colored per top-level folder with a legend; a pin opens a popup (thumbnail, label, link) rather than navigating. Hidden items are never plotted. `?map` has its own Open Graph tags and a generic map-pin preview image. **This is the first feature that makes third-party requests** (Leaflet from cdnjs, tiles from OpenStreetMap), which is why it is opt-in.

### Added — walkthroughs
- **README: "Recipes — start here"** with a decision table and one tested walkthrough per use case (plain gallery, for-sale listing, trip album, family photos with private items, an archive on another disk, iPhone photos), plus a **"What affects what"** pair of tables mapping every setting in `index.php` and every admin control to its effect on visitors. Each recipe was followed step by step against the real script, through the admin's real forms, as part of the test suite.
- The admin now shows, when `TRACK_VIEWS` is on, the sitewide page-load total and "👁 N views" under every photo — so `SHOW_VIEW_COUNTS_PUBLICLY = false` really means "count them, show only me".

### Added — other
- `SHOW_VIEW_COUNTS_PUBLICLY` (default `true`): track views for yourself while hiding the public badges.
- View counts are debounced per browser (30 minutes, per photo), so reloading a photo no longer inflates it. A debounced request still returns the current total.
- The SQLite view-stats store keys its rows by a SHA-256 of each photo's path rather than the filename, because that binary file can be fetched by URL and can't carry the PHP guard the JSON files do. Hidden items are counted like any other; no filename appears in the file.

### Security
- **Apache rules are now tested on a real Apache** (2.4.68 + PHP-FPM) and Apache pretty folder URLs are documented (`RewriteRule … [B,L,QSA]`; the `B` flag is needed for names with spaces or `&+#`). Along the way:
- **Apache: the documented `.htaccess` rule missed upper-case extensions** (`IMG_0412.JPG`, `.Jpeg`) because `FilesMatch` is case-sensitive, so those photos — hidden ones included — stayed reachable by address even with the rule installed. Fixed with `(?i)`. Found by running the rules on a real Apache (2.4.68 + PHP-FPM), which also confirmed that `AllowOverride None` silently disables them, and that the admin and Private view login needs `CGIPassAuth On` on Apache with PHP-FPM/CGI (documented).
- **Hidden photos and videos are never cacheable** (`Cache-Control: private, no-store`), as are pages rendered for a revealed viewer (with `Vary: Cookie`) — previously every photo, hidden or not, was `public, immutable`, so a CDN or proxy could have kept a hidden photo and served it to anyone.
- Admin and private-view responses send `Cache-Control: no-store`, `X-Frame-Options: DENY` and a CSP (`frame-ancestors 'none'; form-action 'self'; base-uri 'none'; object-src 'none'`); every response sends `X-Content-Type-Options: nosniff`.
- The admin session has its own cookie name (it no longer shares `PHPSESSID` with a host site) and rejects session ids the server didn't issue (`session.use_strict_mode`).
- A malformed `Host` header is no longer echoed into absolute URLs.
- Verified by a cross-site-scripting canary test (payloads planted in every admin field, notes, file and folder names, query strings and headers; no raw payload came back on ~290 pages) and by PHPStan static analysis (no real findings). The `README`'s new "Security notes" lists what is and isn't protected.

### Fixed
- **Replacing a photo under the same name now shows the new picture.** Photos and videos are cached by browsers for a year, and their address never changed, so anyone who had seen `rack.jpg` kept seeing the old one after you swapped it (this dates from 1.x). Image and video addresses now carry a tag (`&v=…`) hashed from the file's modification time and size, so a replaced file gets a new address while untouched photos keep theirs; link-preview images pick it up too. Checked in a real browser: without the tag the swapped photo kept showing the old picture; with it the new one appears on a normal page load.
- The link inside the admin's red "Hidden items exist" warning was dark blue on dark red (contrast about 1.8:1, nearly unreadable); it now inherits the box's colour.
- **A pasted `?folder=` link now previews with the cover photo chosen in the admin** (it used the folder's first file). One shared function picks the cover for both the card and the preview.
- **Two galleries on one domain no longer sign each other's viewers out.** The "Private view" cookie used one fixed name for the whole domain; it is now named and signed from each copy's own folder, so every gallery keeps its own (and one gallery's cookie is no longer valid in another that merely shares the password).
- **The sitewide "N views" total no longer shows in the public footer when `SHOW_VIEW_COUNTS_PUBLICLY` is off.**
- **The admin no longer says "Saved" when it couldn't write** (a folder the web server can't write to — very common on shared hosting). It says "Nothing was saved" and what to change.
- `examples/example-forsale.md` did what its text promised only by accident: it claimed the filename prefix `widgeta` matches "Widget Model A", which it doesn't, so none of its items got photos. Rewritten (Alpha/Bravo/Charlie), and the claim corrected.
- Directive examples written inside `` `inline code` `` in a notes file were parsed as real directives (so documenting the syntax raised "unknown file" notices on the public page, including the shipped example's own explanation). Braces inside inline code are now inert and shown literally; real directives in the same paragraph still work.
- `?img=...&size[]=x` (an array where a size is expected) was a fatal error; it now falls back to the default size. This one dates from 1.x.

### Notes
- **The generated data files are guarded PHP files, not plain JSON.** `.gallery-items.php`, `.gallery-stats.php` and `.gallery-login-attempts.php` begin with a one-line `<?php http_response_code(404); exit; ?>`, so asking a web server for one by URL returns 404 and nothing else — captions, GPS and the filenames of hidden items are never sent, on any host that runs PHP, with no server rule. They're read as plain text (never executed), and are written with `<`/`>` escaped so a caption can't inject PHP. The one file that can't carry the guard is the optional binary `.gallery-stats.sqlite`, which is why it holds only hashed keys and counts; the README's nginx/Apache rule blocking `.gallery-*` is worth adding as a second layer over all of these. The nginx rules were tested against nginx 1.26 + php-fpm 8.4; the Apache rules were not.
- The original photo files are served untouched, so **embedded EXIF GPS in the full-size image is not stripped** — the location gates control what the gallery shows, not what a saved original contains. See the README.
- `tests/run.php` now has 463 checks, including recipe walkthroughs that drive the admin through its own forms the way a browser submits them, an upgrade from the *real* 1.1.1 script (not an imitation of its data), and iPhone-style big-endian GPS, including a real 1.x-to-2.0 stats upgrade in both storage flavours. The project was also fuzzed with ~2,300 hostile requests across every endpoint (anonymous, revealed and admin, PHP with all errors on): it found and fixed the fatal above, a fatal on a NUL byte in a notes filename, and PHP warnings from array-valued admin form fields. The inline JavaScript was syntax-checked and its logic executed against a fake DOM and Leaflet, and the whole gallery was driven in a real headless Chromium (lightbox and keys, caption popover, folder navigation, the map with real Leaflet and a clickable pin, phone-width layouts, the admin including a real form submit under its Content-Security-Policy, and that the admin cannot be framed). The suite also no longer leaks processes: each run used to orphan its `php -S` servers (~350 MB for ten), which accumulated over a long session and exhausted a small host — and it no longer follows directory symlinks when cleaning up its fixtures.
- Also verified with real tools rather than assumed: swipe gestures with real touch events (left/right/ignored-if-short/up-doesn't-close/down-closes); real H.264 clips with the metadata at the end of the file (as phones write it), at the start, and as a QuickTime `.mov` — duration badge, decoding, **seeking** and playback in Chromium; 400 simultaneous view pings and 30 simultaneous admin saves on php-fpm, counted exactly on both stats backends; the whole suite, the fuzzer, the cross-site-scripting check and the browser run on PHP 8.3 and 8.4; the nginx and Apache rules on the real servers.

## [1.1.0] - 2026-09-07

### Breaking changes
- **A `.md` file is only read if its first line is exactly `{gallery}`.** Any existing `forsale.md` (or similar) needs that line added, or it will silently stop being parsed. This is a hard requirement, not a toggle — added so this script can be dropped into a folder that already has its own unrelated `.md` files (notes, a README) without swallowing them.
- **`TRACK_VIEWS` now defaults to `false`** (was `true`). Set it to `true` to get view-count badges/stats back.
- **`ENABLE_THUMBNAIL_CACHE` (new) defaults to `false`.** Without it, every photo is served at full original resolution as its own "thumbnail," and HEIC/HEIF photos are excluded from the gallery entirely — even with Imagick installed. Set it to `true` for real deployments.
- **`AUTO_GROUP_BY_FILENAME` (new) defaults to `false`** (auto-grouping by a `_01`/`-02` filename suffix was previously always on). Set it to `true` if your photos use that multi-angle naming convention.

Reasoning for all three defaults: this script writes nothing to a folder's disk, and assumes nothing about a folder's filename conventions, unless explicitly told to.

### Added
- Explicit photo grouping in a `.md` file via `{group: Name}` and `{photos: a.jpg, b.jpg, ...}` directives — works regardless of filename, for a folder of photos with no naming convention at all. See the README for the full behavior matrix (boxed vs. unboxed, with/without text, permalinks, positional clustering).
- `{photos:}` used without `{group:}` repositions the listed files adjacent to each other in the gallery, without boxing them or creating an aggregate view count. With prose, they're positioned early (by where that text sits in the `.md`); textless, they fall back to natural order, anchored on the first-listed file.
- `{group:}` used alone (no `{photos:}` in the same paragraph) renames an already auto-detected group's display label.
- `PHOTO_SORT_ORDER` constant: `'filename'` (default, natural sort) or `'mtime'` (file modification time, oldest first).
- A "⚠ N setup notices for the gallery owner" banner, collapsed by default, listing anything that didn't resolve cleanly: a `.md` file missing its `{gallery}` marker (reported as a count only, deliberately never by filename — see Fixed below), an unknown filename referenced in `{photos:}`, a duplicate `{group:}`/`{photos:}` claim, or a directive that isn't attached to the description it was probably meant to go with (see the next bullet). Shown at the top of the notes box if one exists, or right below the page header if no `.md` qualified at all — addressed explicitly to the gallery owner, so it's not alarming to a normal visitor. The same list is also still in an HTML comment near the top of the page source.
- A directive-only paragraph (no prose of its own) immediately following a plain, unclaimed description — separated only by a blank line — is flagged in that notice banner, since it's easy to write by accident and silently changes both what shows in the notes box and where the item sorts. Not flagged when the preceding paragraph already has its own directive, or when a header/list/blockquote sits in between.

### Fixed
- Two unrelated files sharing a base name but differing only in extension (e.g. `topology.jpg` and `topology.png`) could silently merge into a box, regardless of `AUTO_GROUP_BY_FILENAME` — a coincidence, not an intentional grouping signal, since neither file needed any suffix stripped to arrive at that shared name. A real multi-angle group (`dp104_01.jpg`/`dp104_02.jpg` → `dp104`) is unaffected, since stripping is what makes those converge. (An initial fix keyed every file by its full filename including extension, which inadvertently broke classic mention-based auto-linking — a paragraph mentioning "zebra" could no longer match `zebra.jpg`. Fixed properly in the same release.)
- The gallery grid no longer splits into separate fragments around a group box. Previously, standalone single photos were batched into their own `<div class="grid">` blocks that broke every time a box appeared between them, so a short run of singles right before a box rendered as a sparse, incomplete-looking row. The whole gallery is now one continuous grid; a box is simply a grid item spanning the full row width.
- Layout is now two zones: every box (auto-detected or explicit) always renders before every single and unboxed cluster, regardless of where its directive/mention sits in the `.md`. Even the previous fix above couldn't fully prevent a box from landing mid-row and leaving a gap when it interrupted an uneven number of singles — putting every box first eliminates that possibility structurally, since a full-width row always ends cleanly.
- Mention-matching now searches prose only. Previously it scanned raw `.md` content directly, so a filename referenced inside a *different* paragraph's `{photos: a.jpg, b.jpg}` list could falsely count as a mention of its own name if that name happened to appear with valid word boundaries inside the directive text — most obvious with short filenames, but not limited to them.
- A mentioned standalone single's "View 1 photo ↓" note-box link now actually works. It always pointed at `#group-<slug>`, but only a boxed group's container ever carried that id — a plain single card never did, so the link was dead for any mention that didn't turn out to be a real multi-photo group. Every card gets the anchor now.
- The missing-`{gallery}`-marker notice no longer names the rejected `.md` file. Every other notice only ever references a filename the folder owner themselves typed into their own gallery `.md`, already meant to be public — but a `.md` missing the marker is, by definition, one they *didn't* choose to expose. Since a `.md` is served as a plain static file with no access control tied to the marker, naming it handed a visitor the literal URL to go read its contents directly. Now reported as a count only ("N .md files were found but ignored...").
