# Changelog

All notable changes to this project are documented here. Versions correspond to the `GALLERY_VERSION` constant in `index.php`.

## [2.3.0] - 2026-10-20

### Added
- **Share links.** Temporary links that let someone see private things without a password. Switch on *Allow share links* in Settings (it is off by default), then make links in the new **Share links** tab or straight from the gallery. Each link has a name only you see and can be limited by **how many times it opens**, **when it starts and stops** and **what it covers**: everything private (including what you add later), only chosen folders (each with everything inside it), or only chosen photos. Someone using a link is never the owner: no pencils, locks or sign-in lock, no Private tab, no view counts, and nothing that says other private things exist. Wrong addresses are throttled like wrong passwords.
- **Folders are remembered by a hidden id** kept in the folder's own `.gallery-items.php` (stamped when a link first covers it), not by name: renaming or moving a folder keeps its links working, a new folder with the same name is not covered, a copied folder (the same id twice) is ambiguous and fails closed, and a folder the server can't write to can't be used (it says so). A folder that has gone shows **Folder missing** on the link, with *Take it out of this link*.
- **The opening page** is one button, **Open the gallery**, and pressing it is what counts as one use, so a message app's link preview can't use it up. The same address opening again within 15 minutes (an app's own browser, then Safari) is not a second use. Every link that doesn't work (expired, used up, paused, revoked, mistyped, switched off) shows the same page, "This link isn't valid", with nothing to press. The title can be the gallery's, "A shared gallery" or your own text, with an optional note; the page is `noindex`, not stored and sends no referrer.
- **Statuses and changes:** Active, Paused (*Resume*), Used up, Expired (*Extend…*) and Revoked, plus *Replace address…* (a new address, the old one stops at once, name, settings and log stay) and *Delete…*. The sign-in cookie is bound to the link and checked against its record on every request, so pausing, revoking, replacing or letting it expire cuts off people who are already in.
- **Per link:** original downloads and ZIPs (off, everywhere it covers, or only in some folders), photo locations (**as the public sees them**, the default, or all saved locations; hidden locations are removed from every download and ZIP it hands out), when it starts, when it stops, and a heads-up line at the top of the gallery ("The link being used to access this media expires on …", amber in the last day, dismissable; a site default with a per-link override).
- **Making one, five ways.** A **Share button** in the icon strip of a private folder's page and on that folder's card, **Share…** on each folder row of the Private tab, **Share…** in Select mode, the viewer's link button on a private photo (it asks *Share just this photo…* or *Copy link*), and **+ New link** in the tab. The first four open a short form (name, opens, when it stops) already set to what you were looking at, with **More options…** to carry on in the full form.
- **Copy, Share… and a QR code.** Each link's address has Copy, Share… (the phone's own share sheet, where there is one) and **QR code**, drawn in the browser with the gallery's icon in the middle, with **Show large** (a full-screen white code to hold up to someone's camera), **Copy image** and **Save image**.
- **Preview as this link** opens a new tab showing the gallery exactly as the link does (the same checks and pages, no owner tools), with a strip that says whose view it is, lists what the link includes and what it doesn't (**What's included**) and has **Exit preview**. Nothing you do in a preview is counted or logged. While a preview is on, every gallery page in that browser shows the link's view (each with the strip), the admin pages stay yours and the Share tab says a preview is open, with **End preview**; it ends by itself after four hours.
- **Only some photos** in the full form: thumbnails with a × and **+ Add photos**, a picker that lists a folder's photos (what you tick stays ticked while you look in another folder).
- **A log for every link, kept until you delete the link** (never lost when it is revoked, paused or expires): each visitor (an address with a browser, named plainly: "Safari on iPhone"), what they **saw** (on their screen, even as a thumbnail), **opened** (large, in the viewer), **played** and **saved** (an original or a ZIP), and the folders they looked at. The tab shows it as Visitors, Folders and Photos for each link, a page for each address (Folders, Media, Timeline), and a list of every address with the links each used; turned-away tries are logged with the reason; **new activity** since you last looked shows on the link and as a count in the sidebar. The timeline keeps the latest 300 lines and 200 visitors per link (older visitors are folded into a count; the per-folder and per-photo tallies stay exact). **Export log** gives CSV (visitors, what they looked at, everything in order, or one address); cells that start with `=`, `+`, `-` or `@` can't run as a spreadsheet formula.
- **The tidy address.** A link looks like `https://example.com/trip/k7QpR2mXv9LwTb4e` once the matching nginx or Apache rule is in place (the tab writes it for your gallery's address and checks it); until then `…/?link=k7QpR2mXv9LwTb4e` works as it is.
- **Visitors' real addresses behind Cloudflare or another proxy.** New settings `TRUSTED_PROXY` (*The connection*, *Cloudflare* or *Another proxy*) and `TRUSTED_PROXY_RANGES`. The header Cloudflare adds is believed only when the request really comes from Cloudflare's own ranges (built in), so a visitor can't make one up. This also fixes the sign-in throttle, which behind Cloudflare saw only Cloudflare's addresses.
- New settings `ENABLE_SHARE_LINKS` (off) and `SHARE_HEADS_UP` (off); new data files `.gallery-links.php` and `.gallery-linklog-*.php`, both guarded and covered by the `.gallery-` server rules.

- **Prepare media** (it replaces *Prepare thumbnails*). One resumable action for the whole gallery, with a progress bar, that makes every photo's thumbnails and reads what every photo and video says about itself (when it was taken, where). Those answers are kept **in the thumbnail cache** (`.gallery-cache/meta1.php`, a guarded file, not part of the Export), keyed by the file's name, modified time and size: a file that changes is read again by itself, a file that couldn't be read is tried again, and nothing is ever remembered as "checked, no location". Every file is read once, whatever the location switches say, when its thumbnails are first made or by Prepare media; the switches decide only what is *shown*. Nothing is copied into folder data: a location from the file stands in only for photos where you set none, and what you typed in or cleared always wins. *What the gallery knows about each folder* lists, per folder, the files, thumbnails, locations found / without / couldn't be read (with the file names) / not read yet, capture dates and the locations that are yours; each folder's settings say the same in a line under the location switch. **Read everything again** (with an optional *Also make the thumbnails again*) reads every file anew and also reads photos an older version marked "checked, nothing found" (which can't be told from ones you cleared on purpose, so they are otherwise left alone). With the thumbnail cache off nothing can be recorded, and the settings say so. The suggested folder dates now use HEIC capture dates too. This replaces the per-folder reading on switch-on and on opening the admin, and the short-lived *Check the photos for locations again* button.
- **Tidy up saved locations** (in Prepare media). Older versions copied photos' locations from their files into the folder data. A preview, then the real thing, compares each saved location with its file and removes the copies and the redundant "checked" marks, backing up each changed folder first (`.gallery-items.before-tidy-<date>.php`). It changes nothing else: captions, links, private flags, covers, each photo's Location switch and locations removed on purpose are never touched. *Careful* (the default) keeps anything that differs from its file or has a label; *Refresh from the files* (for galleries where no location was typed) also removes ones that differ. The report is clearer too: thumbnails and reading are counted separately, "saved in the folder's data" replaces "typed in", and the folder list is stacked blocks on a phone.

- **An Edited tab, in place of Private.** One place that lists only what you set by hand: private and public flags, captions, information links, places you typed, labelled or removed on purpose, a photo's own location switch, and each folder's own settings (hidden, name, description, dates, position, location and map switches, photo order, groups; a folder's cover is shown as a picture, and stacks are not listed). What the gallery read from the files is never listed. A summary line, filter chips (*All, Private, Captions, Links, Locations, Folder settings*, each with a count) and one card per folder that has anything, **closed until pressed**, its header saying what is inside it (as filtered). An open card has the folder's **cover as a picture** with the cover star (press it and the folder opens scrolled to that photo, ringed for a moment, so you can pick another), *Open folder* and *Folder settings*, and the settings as pills; for a **private folder**, what opening it would do ("3 photos stay private · 39 photos become public when opened"), **Make public…** (asks first, with the counts) and **Share…**; a row with an **Edit** button for each photo with a caption, link or place (the editor opens in the photo's own folder, so closing it leaves you on that folder's grid); a photo's thumbnail, here and in the Health check's file lists and the Share tab's Photos lists, **shows the photo in its folder**: the grid scrolled to it and ringed for a moment in periwinkle (the cover's ring is gold); and the photos whose only edit is their privacy as thumbnails with the **lock that works** (press it to make the photo public, with *Undo*; an open lock is a photo public inside a private folder), as many as fill two rows for the card's width and the rest behind **+N**. *Expand all* / *Collapse all*. The separate Private folders list is gone, and so is the green "Private is locked" banner (the Health check says it): the "Private isn't locked" warning, with the rules, shows at the top only when it isn't. The tab shows when anything is private or set; the old `#hidden` and `?hidden` addresses still lead to it.
- **Prepare media also looks after videos.** It makes each video's poster frame, hover clip and scrub strip with ffmpeg, one video per request (they take seconds each), counted with the other files (*Prepared: 480 of 497 files*, or *Everything is prepared*); the folder list has a Videos column. A video ffmpeg can't handle is not tried again for six hours and shows in the Health check.
- **Tabs renamed.** *Share links* is **Share** and *Site settings* is **Settings** (in the sidebar, in every message and in the docs); the tab for a folder's own settings is **Folder settings** everywhere, the Root included; and the Root's card on the Edited tab is called **Root** (its line underneath still says *the main page*).
- **Five or six folders and nothing else** use the larger-card layout too, so the cards share the whole width (before, a wide window made room for seven columns and left two empty).
- **Buttons answer a mouse and a press everywhere.** The link icon on a folder card answers like the badges on a tile (a ring, the accent colour, a little larger); plain and grey admin buttons (Copy link, Resume, Save…) get a visible hover and sink when pressed; the Edited tab's filter pills and +N, the round close buttons over a map, inline link icons, the share notice's close and the viewer's close and arrows follow.
- **The way back and the folder pills stay at the top** while you scroll a folder, with the icon strip just under them (phone and desktop), and a down arrow and an up arrow at the right, once you have scrolled, that jump to the bottom and the top of the page. The main page has neither.
- **The tidy share address moved to Settings → Server setup and the Health check**, with the other server checks: a row with its rules and a status line, and a quiet "optional" Health row with a link there. The Share tab no longer carries the dropdown or the banner (a link still shows the short form once the rule works).
- **The Health check's Media rows** say what needs looking at and nothing else: amber rows for files that couldn't be read, old "nothing found" marks and videos ffmpeg couldn't make pictures for, each folding open to its file names (linked to each file's editor); quiet rows, shown under *Show all checks*, for files not read yet, videos not made yet, files with no capture date and saved locations that differ from their file; *All prepared* when it is. *Open Prepare media* switches to Settings and scrolls to the panel. A quiet row says when video pictures are switched off in Settings.
- **Tidy up shows only when there is something to tidy**, and a line under Prepare media lists how many **backups** it made (`.gallery-items.before-tidy-<date>.php`) with **Delete the backups…** (after a yes; only files named exactly like the backups, never anything else).
- **A link can show only its own things.** *Show only these photos* in the short form (on to start with for a link made from one photo or from Select) and *Show only what they can see here* in the full form (ticked for photos, unticked for folders, changeable with *Edit*): the pages the person sees list nothing but what the link covers, not the public rest of the gallery, so a private photo shared from a big public folder doesn't open the folder to browse. It is a tidy view, not a lock: a public photo can still be opened by anyone who knows its address, and the form says so. Without it, a link to a private photo in a public folder shows that folder's public photos too (as it always did; the notes now say so).
- **Trim the log**: one link or all, older than 7, 30 or 90 days or a date; it says what would go (timeline lines, visitors, records of what was looked at, turned-away tries) before it does anything, then removes it after a yes. Opens, views and the number of visitors stay (a trimmed visitor is added to the "earlier visitors" count), and the CSV downloads are offered first. It is in the *IP addresses* view beside *Export everything as CSV*, and in each link's *Export log* menu (that link first).

### Changed
- **The *Export log* menu closes** when you press elsewhere, press Escape, choose an item or open another link's menu (it stayed open before).
- **Copy image says *Copied* on its own button**, like Copy (a failure says so on the button too), instead of a banner at the bottom of the screen, and the grey note under the QR buttons is gone.
- **The photo editor no longer offers to save a copy of a location the file already has.** For a photo whose location comes from its file it says *From the photo's file*, with a hint that nothing needs saving (type a label to name the place, or change the numbers to set your own); *Keep the location from the photo*, which wrote the duplicate that Tidy up removes, is gone.
- **A link's log keeps much more:** 5,000 timeline lines, 2,000 visitors, 500 turned-away tries and 50,000 records of what was looked at, per link (it was 300, 200, 100 and 20,000); each report rewrites the file, so there is still a ceiling, and the log says when it has been reached. Nothing is removed unless you trim it.
- **Every share link starts at 10 opens and 1 week** (a link from one photo started at once, one from a folder at 30 days). The short form's line says what the person really sees: what you picked, and everything already public unless the box is ticked.
- **The tab's check of the tidy address no longer leaves a 404 line in the browser's console:** the one fixed address it asks for answers 200 with the same page and header; a mistyped link is still a 404.
- **The "came through a proxy" line under *Where visitors' IP addresses come from*** appears only when the connection itself is a proxy's (a Cloudflare address, or a private one with a forwarding header). A web server that already passes the real address on leaves a Cloudflare header behind and is right as it is; the help says the Visitors tab then shows no country (that comes from Cloudflare).
- **The link button on a private photo or a private folder's card.** For you it asks what you mean (share just this, or copy); for everyone else it is gone, because a plain link to a private thing opens nothing for someone without access. Public photos and folders keep it.
- **Copy buttons never fail on the first press.** The share form's Copy, the Share tab's Copy buttons and the copy buttons on the server-rule snippets try the older, always-allowed way first and the newer clipboard call second, and say so only if both are refused (Safari refused the newer call on a first press). **Copy image** works in Safari (the picture is made ahead of time and handed over inside the click). The heads-up line is centered.
- **The nginx rule for the tidy address is quoted** (`location ~ "^/trip/[A-Za-z0-9]{16}$"`): nginx reads an unquoted `{` as the start of a block and refused the unquoted rule. Checked against real nginx and Apache.
- **Test tools:** the fuzz and XSS tools add the link holders' and the preview's views of the gallery and the new routes; a reference QR encoder and decoder (`tests/tools/qr`) checks the page's code module for module; the browser tool no longer leaves Chromium profiles behind when a run is killed (they used to fill `/tmp`, which is RAM on some servers, and could get the whole run killed).

## [2.2.0] - 2026-10-19

### Added
- **A private folder can be gone through before it is opened.** A photo in a private folder now has three states, and each is drawn differently: a dashed **Folder** lock (private only because its folder is), a solid red **Private** (kept private on its own, so it stays private when the folder opens) and an open lock (public, though its folder is private). The lock on a tile, the lock in the viewer and the editor's *Private* pill all go round Folder, Private, Public, Folder; and *Select* in a private folder offers three equal buttons, *Private*, *Public* and *Folder* (back to following the folder), instead of the two. Nothing new is stored: a photo that follows its folder still has no setting of its own.
- **A banner on a private folder's page** (owner only): "3 photos will stay private · 39 photos become public when you open it", kept in step with every change you make there. **The whole banner is a button:** pressing it asks (with the same counts) whether to make the folder public, and only a yes does.
- **Opening a private folder asks first, with the counts.** Switching *Private folder* off shows "3 photos stay private, 39 photos become public" with *Cancel* and *Make public*. Photos inside another private folder count as staying private; everything beneath the folder is counted.
- **The main page marks private folders for the owner.** A folder card gets a red **Private** pill (a dashed **Folder** pill when only a folder above it is private), the folder buttons at the top of a folder's page get a small lock in each private folder, and a card's count line ends with how many photos are private inside ("253 photos · 7 videos (2 private ›)", "36 photos · 6 videos (3 stay private ›)"). Pressing that bracket opens the folder with those photos first, in its usual order, for that visit only. A visitor sees none of it.
- **The Private tab is one line per folder.** *What is private* has a short summary and two groups, *Private folders* (with what opening each would do) and *Public folders with private photos*. A line opens to the private photos as thumbnails whose locks work (public in one press, with an Undo), *Show all* when there are more than twelve, and the links *See them in the gallery*, *Make public…* (asks first, with the counts) and the folder's settings. It replaces the three flat lists of file names.
- **The red Private pill on a folder's card asks whether to make the folder public** (with the counts), like the banner on the folder's own page.
- **`?admin&folder=NAME&privcounts=1`** returns those counts (owner only); a photo's record from `?admin&item=` now says what it has of its own (`own`), and `set_item_flag` / `bulk_item_flag` take `state=private|public|inherit`.

### Changed
- **Private items first** puts the photos marked private on their own first. Before, in a private folder (where everything is hidden) it set none of them apart.
- **Prepare media spells out the time left** ("about 15 seconds left", "about 2 minutes left", "about 1 hour 5 minutes left") instead of "15 s" and "2 min".
- **Folder settings save by themselves.** There is no Save button: a text field (display name, dates, position, description) saves when you leave it or a second after you stop typing, the order of the photos (Order, Direction, Put first and its list) and every switch as soon as you change them, and each says *Saving…* or *Saved* beside its own label. An invalid value (a position that isn't a whole number) is marked and not saved. Each save is checked against the record's fingerprint, so a change made in another tab is refused, not overwritten; and only the field you changed is sent, so nothing else is touched (the display name used to be reset by a save that left it out). A browser without JavaScript keeps the Save buttons.
- **Privacy in folder settings is one section of three alike rows**: *Private folder*, *Show photo locations publicly* and, indented under it because the map shows only photos whose location is public, the map (dimmed, with a note, while locations are off). The *Private folder* switch replaces the red button; the Map heading is gone.

## [2.1.0] - 2026-10-17

### Added
- **A pencil on every tile, and an editor in the viewer.** For the signed-in owner each tile has a pencil in its lower left corner (on hover on a desktop), and the viewer's toolbar has one too. It opens the viewer on that photo with its editor: *Caption*, *Information link*, the *Private*, *Location* and *Cover* switches on one row, and the place (latitude, longitude, label) below. On a phone the editor is a sheet under the photo, so the photo stays in view (above the keyboard too), with a *Hide keyboard* button; on a wide screen it is a panel beside the photo. There is no Save button: the switches save as you press them; the text saves when you leave a field, a second after you stop typing, and when you press *Prev*, *Next* or *Done*, so a folder's photos can be captioned one after another. A link without `http://`/`https://` or a bad latitude/longitude is marked and not saved (and *Next* waits). A place read from the photo's GPS but not yet kept is offered with *Keep the location from the photo*; a caption saved meanwhile never keeps it by accident. The tile's badges and the viewer's caption, link and map follow each save without a reload. `?photo=NAME&edit=1` opens a photo with its editor up.
- **Select picks photos in every layout.** The strip's button works wherever there are photos (also in filename groups, notes layouts and inside group boxes): a bar at the bottom has *Select all*, *Clear*, **Make private**, **Make public** and *Done*, and the locks on the tiles follow at once.

### Changed
- **The phone viewer's top row can't lose its counter or the close button.** The counter ("3 / 52") is always whole at the left (a photo's caption, if it has one, comes after it and gives way first) and the close button is at the right; the buttons between them are a strip you swipe sideways, with a small arrow at whichever end has more to swipe to. Nothing of a scrolled-off icon shows beside an arrow, and the arrow follows the strip as it is now (the editor hides the zoom button, so nothing is left to swipe to).
- **The editor never squashes the photo.** Under the sheet the photo is given its exact size from its own shape (Safari kept a photo's width while clamping its height, which squashed it, and it stayed squashed afterwards), and the viewer's photo is always drawn in its own shape. The sheet is lower on a phone so the photo has more room, and its handle works: pull it down (or its title row) and it saves and closes like Done, or springs back.
- **The little map's pin button stays while the editor is open.** The map starts off when the editor opens (it would cover a photo made small for the editor); the pin turns it on, smaller, and it follows the place as you edit it. Closing the editor puts the map back as you had it.
- **Select replaces Arrange.** The strip's Arrange button (four arrows) is now *Select* (a tick in a circle); placing photos next to each other by drag and drop is part of its bar, where the photos are laid out one by one (the *Release* and *Reset folder* buttons are there too). Nothing stored changes.
- **The admin has no Photos (Media) tab any more.** Everything it did is done on the gallery itself (the pencil, the lock, the star, *Select*). Folder settings (*Settings* at the top level) is the first tab; the Private tab's links open the photo's editor; the notice about photos whose GPS isn't saved yet sits on the settings tab. The admin page loads lighter, since it no longer carries a form for every photo.
- **The admin's save for one photo answers JSON when the page asks for it** (with the new fingerprint, or "changed somewhere else"), and `?admin&item=` returns one photo's record for the editor.

## [2.0.11] - 2026-10-17

### Added
- **Arrange: place photos by hand, by drag and drop.** For the signed-in owner an Arrange button (four arrows) joins the icon strip. In Arrange mode a tap selects tiles (a tick shows) and dragging one selected tile beside another photo of the same folder moves everything selected there, in order; a line shows where it will land, and on a phone a tile is picked up with a short hold so scrolling still works. The placed photos become a *stack* saved in the folder's own settings: they stay together, in the order you set, wherever the sort puts the photo they were dropped beside, so the church shots taken on other days sit with the first one under name, date, either direction and the "first" choices, for every visitor. *Release* frees the selected photos, *Reset folder* clears the folder, *Done* leaves Arrange. Not offered with grouping by filename or a notes-file layout. Other settings never touch the stacks, and a deleted or renamed photo just drops out.
- **A family member can add the gallery to their Home Screen.** The Home Screen tags (so it opens as an app with no browser bars) now go to anyone signed in, the owner or a viewer with the private-view password, not only the owner. A visitor who isn't signed in doesn't get them. Signing in lasts a year; an iPhone keeps a Home Screen app's cookies apart from Safari's, so sign in once inside the app.
- **The owner always sees view counts.** While signed in as the owner, each tile shows its view count (an eye and a number, left of the caption/location/link badges, a zero too), and the folder totals and the visit total show as well, even with *Show view counts to visitors* off. Visitors still see only what that setting allows.

### Changed
- **Prepare thumbnails is faster and shows live progress.** It now works as fast as the server allows: three requests share the photos (each takes every third one) and ask again the moment they are answered, in slices of about a second instead of eight, so the bar and a live line ("Preparing… 42% (252 of 600 photos made, about 1 min left)") move steadily instead of seeming stuck between batches. The percentage is of the photos that were missing. *Stop* finishes the photos in hand, says so, and offers *Carry on*; what is done stays done. The save releases the admin session first, so the parallel requests never wait for each other.
- **Opening a folder no longer jumps to its cover photo.** The page opens at the top, as for every other folder (the jump to the chosen cover photo was more annoying than helpful). Choosing a cover photo still sets the folder card's picture.
- **The strip of buttons stays in view.** The icon strip above the photos now sticks to the top of the screen while the photos scroll under it, so Arrange, sort, the map buttons, download and the lock are always at hand (on a solid background with a soft edge once the page has scrolled; a link that scrolls to a photo or the map stops just below it).
- **The visit total moved out of the icon strip** into the line under the title, after the media count and before *Last updated* ("12 photos · 340 visits · Last updated October 14, 2026"), which frees the strip for the buttons.
- **The Home Screen icon is the gallery icon.** The app icon from Add to Home Screen is now the same line drawing as the gallery icon in the icon strip (a rounded frame, a sun, a hill line), light on the gallery's dark background, instead of a filled mountain picture. It is still drawn by the script itself (no image file to add). An app already on a Home Screen keeps the icon it was added with; remove it and add it again to get the new one.

## [2.0.9] - 2026-10-14

- **The lock is an icon in the strip, not beside the title.** The same line-drawn lock (closed to sign in, open and green to sign out) now sits in the row of icons under the title, joined to the archive-download icon when there is one and just before the gallery icon, so it looks and behaves like the others. ## [2.0.8] - 2026-10-14

### Added
- **A link that opens the page with the small overview map showing.** End a gallery or folder address with `#map`: the small map opens, scrolls into view and gets the highlight border a photo gets when a link snaps to it (not the full-screen map, so nothing to close on a phone, and it isn't remembered as that visitor's choice). A small link icon in the open map's top right corner copies the address; the full-screen map has the same icon in its bottom left corner (copying its `?map` link) instead of a text button.

### Changed
- **Photos and videos now run by date taken, oldest first, by default** (before, by file name). A gallery that has never had its photo order set changes order on upgrade; pick **Name** in Site settings (or `"PHOTO_SORT_ORDER": "filename"`) to keep the old order. A gallery that already chose one keeps it, and so does one that groups its photos by filename (the default is still name there, which keeps a group's files in sequence). A video sits among the photos it was shot with.

## [2.0.0] - 2026-10-10

A large release, built and tested in phases on one branch and shipped as one version. **Everything new is off by default, behind its own constant** — a deployment that just swaps in the new file behaves like 1.1.1, apart from the one breaking change below and the two upgrade notes under it.

### Breaking changes
- **PHP 8.3 or newer is now required** (1.x stated 7.4). PHP 7.4 has been unsupported since 2022 and was never tested against this release; 8.1 and 8.2 are out of (or about to leave) security support. The minimum is 8.3, the oldest version still receiving security fixes (until the end of 2027), and it is a tested claim: the full test suite, the fuzzer, the cross-site-scripting check and the real-browser run all pass on PHP 8.3.32 as well as 8.4.26. On an older PHP the page stops with a one-line message saying so.
- **`?download` no longer serves the script.** It now redirects (302) to the GitHub repository. It used to `readfile()` the running `index.php` to anyone who asked; once `ADMIN_PASSWORD` lives in that same file, that would have handed the password to any visitor, and scrubbing secrets out of the output is a fix that has to be remembered forever. Removing the endpoint closes the whole class at once. An old bookmarked link lands on the repository rather than a dead end. `?about`'s download button now points at GitHub too.

### Upgrading from 1.x
- **Your view counts carry over automatically.** 1.x kept them in `.gallery-stats.json` (or a SQLite file with readable filenames). On the first request with `TRACK_VIEWS` on, 2.0 imports the per-photo counts and the sitewide total into its new stores, then removes the old JSON file (or drops the old SQLite table and compacts the file, so the old filenames don't linger in it).
- **You may see one new setup notice** if your folder has subfolders containing photos while `AUTO_GROUP_BY_FOLDER` is off: the collapsed "setup notices" banner says how many photos in subfolders aren't shown (a count, never a name).

### Added — folders
- **Nested folders, to any depth** (`AUTO_GROUP_BY_FOLDER`, off by default). A root like `/trip` with `Europe/France/Paris` underneath shows each subfolder as its own group. With `FOLDER_DISPLAY_MODE = 'overview'` (the default) each level shows one **cover card per subfolder** — a highlight photo, a label and a *recursive* photo count — plus any photos loose at that level, and clicking a card opens `?folder=Europe/France` and repeats. `'inline'` instead shows every folder's photos in one box, for people who use folders only to stay organized. A breadcrumb links through every ancestor.
- `?folder=` is validated against the script's own file list, never trusted: `../`, leading/trailing slashes, a file path, an empty value, a nonexistent folder, and a hidden folder all return 404. Symlinked subfolders are refused outright.
- `EXTRA_FOLDERS`: an explicit, admin-written map of virtual folder names to real paths (for archiving an old trip on another disk) — declared in code you control, so no symlink is involved.
- Per-folder **display name, description, a typed date-range subtitle, a chosen cover photo, and a position among sibling folders**, all editable in `?admin`. Stored inside the folder they describe, so they survive a real rename. The date range is deliberately never derived from EXIF: that would publish when you were away from home.
- A folder may carry its own `{gallery}`-marked `.md`, becoming a note box on that folder's page, scoped to that folder's photos only.
- A `.md` mention of a folder links to its `?folder=` page in overview mode.
- Stats, the thumbnail cache and per-item data are **colocated in each folder**, so two cameras' `IMG_0001.jpg` in different folders never collide, and a real folder rename carries its data along.
- A **"Last updated"** date in the header, derived from the newest file modification time across photos and notes — not a separately maintained marker, so it also reflects files uploaded by FTP.
- A setup notice when photos exist in subfolders but `AUTO_GROUP_BY_FOLDER` is off, so a first-time owner isn't left with a silently sparse gallery (a count only; the search is capped at 40 folders).
- Sibling folders order by an admin-set position, then naturally by name (Day 2 before Day 10), or by folder mtime under `PHOTO_SORT_ORDER = 'mtime'`.
- `?img=` and `?video=` validate the one claimed path directly instead of scanning the whole tree first — one tree walk per thumbnail is what made large, deep galleries slow (measured on 3,000 photos in 200 folders with PHP's built-in server: about 35 ms per `?img=` request before, about 9 ms after). The check rejects `..`, doubled/leading slashes, backslashes, NULs, folders, the script itself, `.gallery-cache`, symlinked folders, non-media extensions, and any name that isn't an exact-case match for a real file (so a case-insensitive filesystem can't dodge a per-photo hide flag). `?track=` and page loads still scan, since they need the whole group.

### Added — video
- `ENABLE_VIDEO`: `.mov` and `.mp4` are served as gallery items. No transcoding, no frame extraction. Tiles and share previews use one generic placeholder graphic; the lightbox plays the clip in a native `<video>`. Seeking works: real HTTP `Range` support (`206`, `416` past the end, malformed ranges ignored). A **duration badge** is read straight from the container's `mvhd` box.

### Added — captions, location, and the admin editor
- **Per-item captions, a web link, and a location**, one per photo or video. The lightbox shows the caption (or just a position counter) — **it no longer prints the raw filename.** Grid badges (caption, location, link) sit along the bottom edge.
- **`ENABLE_PHOTO_LOCATION`** (off by default) is the first of three gates: also needed are a per-folder switch and a per-photo setting (inherit / always show / always hide), all closed by default. GPS is auto-filled from EXIF for JPEG and HEIC where present; coordinates are validated before they reach any URL.
- **Two admin tabs can't silently overwrite each other:** a save whose record changed since the page loaded is refused with an explanation (per record, so different photos never conflict).
- The caption badge is a tap target that opens a popover on a phone, not just a hover tooltip.
- **`?admin`** (`ADMIN_PASSWORD`, empty = the code path doesn't exist): HTTP Basic Auth compared with `hash_equals()`, refused over plain HTTP except on localhost (with a page explaining why), CSRF-protected saves, a 4-hour session, and a failed-login throttle (5 wrong passwords from one address in 15 minutes imposes a 60-second delay; a request with no credentials — the normal first step of any login — doesn't count). Usable from a phone. It edits every item's caption/link/location, folder settings, every `.md` in the folder (raw text, saved byte-for-byte; **Save**, **Save As** and **Delete** are separate actions, and Save As and Delete ask for confirmation; a one-click fix for a missing `{gallery}` marker), and exports each folder's saved data (`.gallery-items.php`) as plain JSON, for one folder or the whole tree. Stale entries for deleted photos are cleaned up and reported.

### Added — hiding items, and Private view
- A **hide flag** per item and per folder (at any depth) in the admin. A hidden item is removed from the page, counts, lightbox list and every endpoint (`?img=`, `?photo=`, `?track=`, `?folder=`, `?video=`) for an unrevealed visitor — not merely styled invisible. A group whose members are all hidden disappears rather than showing "0 photos". Each item can also be forced *public* inside a hidden folder.
- **`PRIVATE_VIEW_PASSWORD`** and a discreet "Private view" footer link (`?reveal`): a password, deliberately not a secret link, since links pasted into chat get crawled. Same HTTPS requirement and throttle as the admin. A valid admin login counts as revealed too.
- An admin **"Hidden items"** summary across the whole tree in three tiers, and a persistent warning that hiding doesn't stop someone who already knows a file's URL unless the web server is locked down.
- **`NGINX_ACCEL_REDIRECT_PREFIX`** hands matching files to nginx via `X-Accel-Redirect`, so an nginx `internal` rule can make the bare file URLs unreachable. See the README for the nginx and Apache setups.

### Added — trip map
- **`ENABLE_MAP`** (off by default): every visible, located photo on one Leaflet + OpenStreetMap map, at its own shareable **`?map`** URL with a condensed preview on the gallery root. Photos within `MAP_CLUSTER_RADIUS_MILES` (default 50) merge into one numbered pin that zooms in when clicked; pins are colored per top-level folder with a legend; a pin opens a popup (thumbnail, label, link) rather than navigating. Hidden items are never plotted. `?map` has its own Open Graph tags and a generic map-pin preview image. **This is the first feature that makes third-party requests** (Leaflet from cdnjs, tiles from OpenStreetMap), which is why it is opt-in.

### Added — walkthroughs
- **README: "Recipes — start here"** with a decision table and one tested walkthrough per use case (plain gallery, for-sale listing, trip album, family photos with private items, an archive on another disk, iPhone photos), plus a **"What affects what"** pair of tables mapping every setting in `index.php` and every admin control to its effect on visitors. Each recipe was followed step by step against the real script, through the admin's real forms, as part of the test suite.
- The admin now shows, when `TRACK_VIEWS` is on, the sitewide page-load total and "👁 N views" under every photo — so `SHOW_VIEW_COUNTS_PUBLICLY = false` really means "count them, show only me".

### Added — other
- `SHOW_VIEW_COUNTS_PUBLICLY` (default `true`): track views for yourself while hiding the public badges.
- View counts are debounced per browser (30 minutes, per photo), so reloading a photo no longer inflates it. A debounced request still returns the current total.
- The SQLite view-stats store keys its rows by a SHA-256 of each photo's path rather than the filename, because that binary file can be fetched by URL and can't carry the PHP guard the JSON files do. Hidden items are counted like any other; no filename appears in the file.

### Security
- **Apache rules are now tested on a real Apache** (2.4.68 + PHP-FPM) and Apache pretty folder URLs are documented (`RewriteRule … [B,L,QSA]`; the `B` flag is needed for names with spaces or `&+#`). Along the way:
- **Apache: the documented `.htaccess` rule missed upper-case extensions** (`IMG_0412.JPG`, `.Jpeg`) because `FilesMatch` is case-sensitive, so those photos — hidden ones included — stayed reachable by address even with the rule installed. Fixed with `(?i)`. Found by running the rules on a real Apache (2.4.68 + PHP-FPM), which also confirmed that `AllowOverride None` silently disables them, and that the admin and Private view login needs `CGIPassAuth On` on Apache with PHP-FPM/CGI (documented).
- **Hidden photos and videos are never cacheable** (`Cache-Control: private, no-store`), as are pages rendered for a revealed viewer (with `Vary: Cookie`) — previously every photo, hidden or not, was `public, immutable`, so a CDN or proxy could have kept a hidden photo and served it to anyone.
- Admin and private-view responses send `Cache-Control: no-store`, `X-Frame-Options: DENY` and a CSP (`frame-ancestors 'none'; form-action 'self'; base-uri 'none'; object-src 'none'`); every response sends `X-Content-Type-Options: nosniff`.
- The admin session has its own cookie name (it no longer shares `PHPSESSID` with a host site) and rejects session ids the server didn't issue (`session.use_strict_mode`).
- A malformed `Host` header is no longer echoed into absolute URLs.
- Verified by a cross-site-scripting canary test (payloads planted in every admin field, notes, file and folder names, query strings and headers; no raw payload came back on ~290 pages) and by PHPStan static analysis (no real findings). The `README`'s new "Security notes" lists what is and isn't protected.

### Fixed
- **Replacing a photo under the same name now shows the new picture.** Photos and videos are cached by browsers for a year, and their address never changed, so anyone who had seen `rack.jpg` kept seeing the old one after you swapped it (this dates from 1.x). Image and video addresses now carry a tag (`&v=…`) hashed from the file's modification time and size, so a replaced file gets a new address while untouched photos keep theirs; link-preview images pick it up too. Checked in a real browser: without the tag the swapped photo kept showing the old picture; with it the new one appears on a normal page load.
- The link inside the admin's red "Hidden items exist" warning was dark blue on dark red (contrast about 1.8:1, nearly unreadable); it now inherits the box's colour.
- **A pasted `?folder=` link now previews with the cover photo chosen in the admin** (it used the folder's first file). One shared function picks the cover for both the card and the preview.
- **Two galleries on one domain no longer sign each other's viewers out.** The "Private view" cookie used one fixed name for the whole domain; it is now named and signed from each copy's own folder, so every gallery keeps its own (and one gallery's cookie is no longer valid in another that merely shares the password).
- **The sitewide "N views" total no longer shows in the public footer when `SHOW_VIEW_COUNTS_PUBLICLY` is off.**
- **The admin no longer says "Saved" when it couldn't write** (a folder the web server can't write to — very common on shared hosting). It says "Nothing was saved" and what to change.
- `examples/example-forsale.md` did what its text promised only by accident: it claimed the filename prefix `widgeta` matches "Widget Model A", which it doesn't, so none of its items got photos. Rewritten (Alpha/Bravo/Charlie), and the claim corrected.
- Directive examples written inside `` `inline code` `` in a notes file were parsed as real directives (so documenting the syntax raised "unknown file" notices on the public page, including the shipped example's own explanation). Braces inside inline code are now inert and shown literally; real directives in the same paragraph still work.
- `?img=...&size[]=x` (an array where a size is expected) was a fatal error; it now falls back to the default size. This one dates from 1.x.

### Notes
- **The generated data files are guarded PHP files, not plain JSON.** `.gallery-items.php`, `.gallery-stats.php` and `.gallery-login-attempts.php` begin with a one-line `<?php http_response_code(404); exit; ?>`, so asking a web server for one by URL returns 404 and nothing else — captions, GPS and the filenames of hidden items are never sent, on any host that runs PHP, with no server rule. They're read as plain text (never executed), and are written with `<`/`>` escaped so a caption can't inject PHP. The one file that can't carry the guard is the optional binary `.gallery-stats.sqlite`, which is why it holds only hashed keys and counts; the README's nginx/Apache rule blocking `.gallery-*` is worth adding as a second layer over all of these. The nginx rules were tested against nginx 1.26 + php-fpm 8.4; the Apache rules were not.
- The original photo files are served untouched, so **embedded EXIF GPS in the full-size image is not stripped** — the location gates control what the gallery shows, not what a saved original contains. See the README.
- `tests/run.php` now has 463 checks, including recipe walkthroughs that drive the admin through its own forms the way a browser submits them, an upgrade from the *real* 1.1.1 script (not an imitation of its data), and iPhone-style big-endian GPS, including a real 1.x-to-2.0 stats upgrade in both storage flavours. The project was also fuzzed with ~2,300 hostile requests across every endpoint (anonymous, revealed and admin, PHP with all errors on): it found and fixed the fatal above, a fatal on a NUL byte in a notes filename, and PHP warnings from array-valued admin form fields. The inline JavaScript was syntax-checked and its logic executed against a fake DOM and Leaflet, and the whole gallery was driven in a real headless Chromium (lightbox and keys, caption popover, folder navigation, the map with real Leaflet and a clickable pin, phone-width layouts, the admin including a real form submit under its Content-Security-Policy, and that the admin cannot be framed). The suite also no longer leaks processes: each run used to orphan its `php -S` servers (~350 MB for ten), which accumulated over a long session and exhausted a small host — and it no longer follows directory symlinks when cleaning up its fixtures.
- Also verified with real tools rather than assumed: swipe gestures with real touch events (left/right/ignored-if-short/up-doesn't-close/down-closes); real H.264 clips with the metadata at the end of the file (as phones write it), at the start, and as a QuickTime `.mov` — duration badge, decoding, **seeking** and playback in Chromium; 400 simultaneous view pings and 30 simultaneous admin saves on php-fpm, counted exactly on both stats backends; the whole suite, the fuzzer, the cross-site-scripting check and the browser run on PHP 8.3 and 8.4; the nginx and Apache rules on the real servers.

## [1.1.0] - 2026-09-07

### Breaking changes
- **A `.md` file is only read if its first line is exactly `{gallery}`.** Any existing `forsale.md` (or similar) needs that line added, or it will silently stop being parsed. This is a hard requirement, not a toggle — added so this script can be dropped into a folder that already has its own unrelated `.md` files (notes, a README) without swallowing them.
- **`TRACK_VIEWS` now defaults to `false`** (was `true`). Set it to `true` to get view-count badges/stats back.
- **`ENABLE_THUMBNAIL_CACHE` (new) defaults to `false`.** Without it, every photo is served at full original resolution as its own "thumbnail," and HEIC/HEIF photos are excluded from the gallery entirely — even with Imagick installed. Set it to `true` for real deployments.
- **`AUTO_GROUP_BY_FILENAME` (new) defaults to `false`** (auto-grouping by a `_01`/`-02` filename suffix was previously always on). Set it to `true` if your photos use that multi-angle naming convention.

Reasoning for all three defaults: this script writes nothing to a folder's disk, and assumes nothing about a folder's filename conventions, unless explicitly told to.

### Added
- Explicit photo grouping in a `.md` file via `{group: Name}` and `{photos: a.jpg, b.jpg, ...}` directives — works regardless of filename, for a folder of photos with no naming convention at all. See the README for the full behavior matrix (boxed vs. unboxed, with/without text, permalinks, positional clustering).
- `{photos:}` used without `{group:}` repositions the listed files adjacent to each other in the gallery, without boxing them or creating an aggregate view count. With prose, they're positioned early (by where that text sits in the `.md`); textless, they fall back to natural order, anchored on the first-listed file.
- `{group:}` used alone (no `{photos:}` in the same paragraph) renames an already auto-detected group's display label.
- `PHOTO_SORT_ORDER` constant: `'filename'` (default, natural sort) or `'mtime'` (file modification time, oldest first).
- A "⚠ N setup notices for the gallery owner" banner, collapsed by default, listing anything that didn't resolve cleanly: a `.md` file missing its `{gallery}` marker (reported as a count only, deliberately never by filename — see Fixed below), an unknown filename referenced in `{photos:}`, a duplicate `{group:}`/`{photos:}` claim, or a directive that isn't attached to the description it was probably meant to go with (see the next bullet). Shown at the top of the notes box if one exists, or right below the page header if no `.md` qualified at all — addressed explicitly to the gallery owner, so it's not alarming to a normal visitor. The same list is also still in an HTML comment near the top of the page source.
- A directive-only paragraph (no prose of its own) immediately following a plain, unclaimed description — separated only by a blank line — is flagged in that notice banner, since it's easy to write by accident and silently changes both what shows in the notes box and where the item sorts. Not flagged when the preceding paragraph already has its own directive, or when a header/list/blockquote sits in between.

### Fixed
- Two unrelated files sharing a base name but differing only in extension (e.g. `topology.jpg` and `topology.png`) could silently merge into a box, regardless of `AUTO_GROUP_BY_FILENAME` — a coincidence, not an intentional grouping signal, since neither file needed any suffix stripped to arrive at that shared name. A real multi-angle group (`dp104_01.jpg`/`dp104_02.jpg` → `dp104`) is unaffected, since stripping is what makes those converge. (An initial fix keyed every file by its full filename including extension, which inadvertently broke classic mention-based auto-linking — a paragraph mentioning "zebra" could no longer match `zebra.jpg`. Fixed properly in the same release.)
- The gallery grid no longer splits into separate fragments around a group box. Previously, standalone single photos were batched into their own `<div class="grid">` blocks that broke every time a box appeared between them, so a short run of singles right before a box rendered as a sparse, incomplete-looking row. The whole gallery is now one continuous grid; a box is simply a grid item spanning the full row width.
- Layout is now two zones: every box (auto-detected or explicit) always renders before every single and unboxed cluster, regardless of where its directive/mention sits in the `.md`. Even the previous fix above couldn't fully prevent a box from landing mid-row and leaving a gap when it interrupted an uneven number of singles — putting every box first eliminates that possibility structurally, since a full-width row always ends cleanly.
- Mention-matching now searches prose only. Previously it scanned raw `.md` content directly, so a filename referenced inside a *different* paragraph's `{photos: a.jpg, b.jpg}` list could falsely count as a mention of its own name if that name happened to appear with valid word boundaries inside the directive text — most obvious with short filenames, but not limited to them.
- A mentioned standalone single's "View 1 photo ↓" note-box link now actually works. It always pointed at `#group-<slug>`, but only a boxed group's container ever carried that id — a plain single card never did, so the link was dead for any mention that didn't turn out to be a real multi-photo group. Every card gets the anchor now.
- The missing-`{gallery}`-marker notice no longer names the rejected `.md` file. Every other notice only ever references a filename the folder owner themselves typed into their own gallery `.md`, already meant to be public — but a `.md` missing the marker is, by definition, one they *didn't* choose to expose. Since a `.md` is served as a plain static file with no access control tied to the marker, naming it handed a visitor the literal URL to go read its contents directly. ## [1.0.0] - 2026-09-06

Initial release.

### Added
- Drop-in single-file gallery: scans its own folder for jpg/jpeg/png/gif/webp/bmp (and heic/heif when Imagick is available)
- Automatic photo grouping by filename suffix (`name_01`, `name-02`, etc.)
- Full-screen lightbox with keyboard navigation and mobile swipe gestures (left/right/down)
- Optional `.md` notes box with a deliberately small Markdown subset
- Auto-linked thumbnails: a paragraph mentioning a group's name automatically gets a thumbnail preview, view count, and jump link
- Inline directives: `{color: value}`, `{sold}`, `{reserved}` / `{held}` — status directives override a custom color
- Gallery display order mirrors the order groups are first mentioned in the `.md`, falling back to filename order with no `.md`
- Page title derived from the first `.md` file's leading `# Heading`
- View stats: per-photo, per-group, and total page-load counts, updating live via a background ping; SQLite auto-detected with a JSON-file fallback; known preview bots excluded from counts; toggleable via `TRACK_VIEWS`
- Thumbnail generation and caching (Imagick or GD), with HEIC/HEIF conversion for both grid and lightbox
- Deep linking: `?photo=filename` (with a context-aware Open Graph preview), `#group-name`, and `#item-name` anchors, each with one-click copy-to-clipboard permalinks
- Open Graph / Twitter Card meta tags for link previews
- `?about` page with full in-app documentation and a download link; `?download` serves the script itself
- `GALLERY_VERSION` constant for version tracking
