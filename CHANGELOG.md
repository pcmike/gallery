# Changelog

All notable changes to this project are documented here. Versions correspond to the `GALLERY_VERSION` constant in `index.php`.

## [2.6.5] - 2026-11-07

### Fixed
- **Photos with a wide-gamut colour profile looked flat.** Every picture the gallery makes (thumbnails, tiles, covers, the converted copy a HEIC is shown as in the viewer) removed the photo's colour profile along with its camera and location data. Without it a browser reads the numbers as sRGB: a Display P3 iPhone photo lost about a tenth of its saturation (measured on a real photo: the most vivid 1% at 71% where a colour-managed conversion gives 83%). A small profile is now kept (a wide screen shows what the photo holds); a profile over 8 KB is converted to sRGB and dropped; the location, camera and the rest are still removed. Pictures made before are made again, once, as they are asked for.
- **A HEIC in the viewer was always a smaller, converted copy.** A browser that can show HEIC (Safari) is now sent the photo itself, at its own size and colours, under the same rules as any other original (the location blanked for a visitor who may not see it); the viewer finds out once, with a two-pixel HEIC, and falls back to the converted copy if the original fails. For every other browser the converted copy is now up to 4096 pixels on the long side (it was 2400).
- **A damaged visitor log was not noticed, or was blamed on permissions.** The check only opened the file and wrote one row, so damaged pages in the middle of a log passed it; a file whose first bytes were destroyed was reported as "the web server has to be allowed to write there". The log is now looked through (`quick_check`) and called what it is.
- **The Files ZIP could hold an inconsistent visitor log.** It copied a log that is written to as three separate files. The log now goes in as one consistent copy, and the backup is not packed into the Files ZIP again.
- **The Changes tab showed nothing new until the page was reloaded, and its grey number was lost on the second visit.** The list was drawn once, when the page loaded. It is now asked for again each time the tab is opened (and when the window comes back to it), keeping the kinds chosen, the search and the entries you opened; what is new has an amber edge that stays while you are on the tab and goes when you leave it. Opening the tab again with nothing new no longer replaces the grey number with 0: it stays for the day after the last time there was news.
- **The sidebar's Changes number lagged behind the pill on the gallery page.** A page in the admin frame did not tell the sidebar when the window came back, so the number only caught up after a click or a reload. It now does, for every page in the frame.
- **One new photo could be logged more than once in the Changes tab.** The admin page opens several requests together, and each compared the folders with the saved picture before any had written, so each saw the same new photo and wrote it. The check now looks at the saved picture again inside the write and says nothing if another request already said it.
- **The fold arrows (folder tree, panel headings, the pills and the Show links) showed an empty box in a browser with no font for the arrow character** (seen in a car's browser). They are drawn shapes now, in the colour of the text beside them.
- **The Health check's "Left behind" row for leftover thumbnails said they came from another gallery, and "Set aside" could hide new leftovers.** The thumbnails counted are the pictures nothing uses any more in a place from elsewhere on the server: of photos deleted, renamed or replaced here, or made by another gallery that showed the same folders; the text now says so (the Prepare media group is called *Left behind in folders from elsewhere*). Set aside used to remember only an amount and kept the row quiet while the amount was no more than it was: so after the old leftovers were gone, newer ones were hidden. It now remembers a fingerprint of exactly what was set aside (the files, the earlier views, the loose photos) and the row is quiet only while it is about the same things; anything new, or gone, brings it back. Tidying up removes the saved note.
- **A lockout started by someone else locked you out of the admin too.** The pause is per connection, and it was checked before looking at whether you were already signed in, so a roommate, a proxy that hides visitors' real addresses, or your own private window with a few wrong codes paused every signed-in session at that address for a minute (the page, and every save). A session that is already signed in is no longer held back, since it is not guessing anything; anyone not signed in still is, including with the right code.
- **Delete in *Files this gallery has made* skipped the visitor log and the older logs.** The list showed them and said what deleting would do, but the delete itself never visited them. It does now, and takes the new lockout counts too.
- **The *nginx internal redirect* setting no longer looks like something is wrong when nothing is.** Its row only ever showed a fixed warning ("photos and videos stop loading"), because its own status line was filled in only when the gallery had a photo of its own to test with. Now the row says what was found, in the same way as the rows under it: *Doesn't apply here* in green when every photo comes from folders elsewhere on the server (which the gallery always sends itself), *Working* in green when nginx served a test photo, *Not working* in red when it did not. The warning shows only in that last case (or when the check could not tell), and the rule to add is under the row (**Show the rule**, with Copy) for the gallery's address. The help text pointed at the README for the rule, which has never held it.
- **The Health check's list closed after Set aside or Remove them.** Both reload the page, and the list always starts closed, so it vanished under your finger. It now stays open after those two. A new check, `tests/tools/browser/health_checks.py`, covers it.
- **"Changed somewhere else" in the admin is gone.** The quiet bar the admin pages showed when another browser changed a setting, or photos arrived, is replaced by the Changes tab (the settings file and a folder's own data are the owner's own changes). On your gallery page the small pill at the bottom for new photos stays.
- **Collections tab: Open settings did nothing, and the folder tabs sat above it.** *Open settings* loaded the collection's own page but opened on the Collections tab again (it was remembered as the tab to open on), so it looked as if nothing happened; it now lands on the settings tab. The Collections tab was also treated as part of a folder, so that folder's *Folder settings* and *Notes* tabs showed above it (in the desktop shell the breadcrumb did not name it either); it is a whole-gallery page like Shares now.
- **The sidebar's numbers follow an edit made on a gallery page.** In the desktop admin, pressing a lock, a star, the pencil or a link button, using Select, or saving in the viewer's editor on a folder's page now refreshes the sidebar (Edited and the others) about two seconds later. Before, only admin pages told the shell, so the Edited number stayed where it was until the window came back to the front or another page opened.
- **The Edited tab's folder summaries left out new links.** A photo that was given a new link was listed in its folder and counted (the *New links* chip, the total), but the folder card's summary pills ("1 private", "1 caption"…) never said so. They now say "1 new link" / "2 new links". The tab also calls information links *info links* (the chip, the summary pills and the row tags), so they are not mistaken for a photo's own link.
- **Other sections no longer flash up while an admin page loads.** Until the page's script had run, every section (Features, Edited, Shares, Settings and the rest) was drawn one above the other for a moment, then all but one went away; it was most visible when the Health check's *Check again* reloaded Settings. The sections are now hidden from the first moment, and the one the address (or your last visit) names is the only one drawn.
- **The Visitors export icon was drawn tiny.** The button's own padding squeezed the arrow to 12 pixels wide. It is now the same download icon as the rest of the admin, at 22 pixels.
- **The link icon on a folder's card copied a doubled address in the admin's frame** (`https://site/photos/https://site/photos/?folder=x&inframe=1`). The icon now copies the folder's own address, without the frame's `inframe=1`.

### Changed
- **"Use these dates" is a text link.** In a folder's settings the offer to use the span of its photos as the dates was a grey button in the middle of a sentence; it is a periwinkle link at the end of it now, like the other links in the admin. It still only fills the Dates box.
- **The Collections tab is always there** (while *Show subfolders* is on), not only once a collection exists; with none it says so and offers the box to make the first.
- **Collections can be made and deleted from the Collections tab.** A box at the top makes a new one from just a name (it starts on the front page, then opens its own settings), and each collection has a line-drawn bin in a red box after *View* (it asks first; only the collection goes). *Holds* now says "2 folders, 70 nested photos" (the photos inside the folders it holds), with any single photos picked on their own after it; a folder's settings list says the same.
- **A Not listed folder stops talking about public and private.** The *Not listed* pill on its card is a plain note now, not a button (it used to offer to make the folder public). Its page now has one quiet line ("Not listed: only you can open this folder") instead of the Private folder's banner with its counts and *Make it public…* (making it public is still in the folder's settings and on its card). On each photo the lock is an open lock (the photo's own link works) or a solid red one (**Link off**), two states instead of three (a photo marked public in a Not listed folder changes nothing, so that state is gone); press it to switch the link off or back on. Its tooltip and the message that follows say so in those words, and so do the editor's switch and the Select bar's buttons. The message no longer says "visitors can't see them unless they have the private-view password" for a photo in a Not listed folder (nobody gets there that way); it says whose link is off.
- **The Health check's *Check again* no longer reloads the page.** It asks for the Health check again and puts it in place (the list stays open if it was, the rows your browser fills in are asked again). If that fails it reloads, as before.
- **The admin keeps up when you come back to it.** The sidebar's numbers (and the phone Menu's, which left Visitors out) are asked for again when the browser tab or window comes back, also in the desktop shell (a tab brought to the front does not always give the window focus); and an open **Visitors** tab refreshes its list, pills and summary by itself (a small request, not the whole page), keeping its choices, never while a menu or dialog is open (it catches up when it closes), and counts the lockouts it shows as seen. So does an open **Shares** tab's list (a link's state, opens and what is new), which is also left alone while the new-link form is open, several links are selected, a menu is open or a field has focus, and catches up afterwards. Places where you edit are not swapped under your hands. On your gallery page, when the window comes back and photos were added, removed or renamed (a sync), a small pill at the bottom says where and what, folder by folder: *1 item added to random*, *2 items removed from Eurotrip*, *items in Sunrises were renamed or replaced*. Each folder's name is a link: it opens that folder with what arrived since marked (a ring and a small *New*) and scrolled to, and says how many are marked. In Settings, **Browsers signed in** (another browser signing in or out) and **Prepare media**'s numbers (photos that arrived, a run in another browser) are asked for again too, left alone while a sign-out waits for its second press, a browser's history is open, a run is going here or the group is folded. A tab you open after a while is refreshed too. The Trim dialog's refresh uses the same small request.
- **Lockouts are written down.** When too many wrong access codes, setup codes or addresses pause a connection, that is now a line in the visitor log (the time, address and country, and which kind: sign-in, setup code or addresses), shown in the Visitors list and the Timeline like any other visitor, and alone when **Lockouts** is chosen under **Sources**. The Health check says how many there were in the last seven days, with a **→ Visitors** link that opens the tab showing them. Without the Visitors tab only a small count per day and kind is kept (no addresses, 30 days, `.gallery-lockouts.php`), so the Health row still appears. The Visitors number in the sidebar (and in the phone's Menu) turns into a red circle while a lockout has happened that you have not seen, and goes grey a moment after the tab is opened, also when the page opens straight onto it (its tooltip says how many). **Public** is no longer a pill of its own: the new **Sources** list holds Public, Lockouts and each share link.
- **Every jump to somewhere else in the admin reads "→ where".** *→ Visitors*, *→ Prepare media*, *→ Count views*, *→ Folders from elsewhere*, *→ Country lookup*, *→ Browsers signed in*, *→ Server setup*, *→ The rules* (it said *Fix this* and *Open the rules*), *→ Notes* and *→ Shares*, in the Health check, the Features list and the Shares tab.
- **The lockout pages are proper pages, and count down.** Too many wrong access codes (five in 15 minutes), wrong setup codes or wrong share links and photo links (ten) pause that connection for a minute. The access-code and setup-code pauses were bare text ("Try again in a moment"); all three are now the same dark page with the same look, each saying what happened in its own words (*Sign-in paused*, *Setup paused*, *Please wait a moment*), with the seconds left counting down. When the time is up the page takes the visitor back to the sign-in (or the address) by itself, as a plain visit, never sending what was typed again. The pages send a `Retry-After` header with the exact seconds left. The Files dialog's "Wait a few minutes" now says the seconds.
- **The visitor log is its own tab, kept in SQLite, with no caps.** **Visitors** (a sidebar tab after Settings) lists everyone who used the public address (if logged) and every share link, in one table. The top line is pills and a search: **All** is a list of the countries seen (two-letter codes, with names and counts; tick any number), **Public**, and **Share links** (tick any number); a press on a country in a row, a link's name or an IP address picks it above. The four views (Visitors, Folders, Media, Timeline) all follow those choices, and an export icon beside the search (the search box has its own ✕ to clear it) opens three CSVs (that follow them too) and Trim the log. The lists stay open while you tick and close with Done, Esc or a press outside (sheets at the bottom of a phone). The log lives in one SQLite file, `.gallery-visits-<24 random letters and digits>.sqlite`, so the 5,000-line, 2,000-visitor and 50,000-record limits are gone (a list shows the latest 300 and says how many there are). **It needs pdo_sqlite and a writable folder**: without them nothing is logged, the tab is hidden, the logging switch is greyed with the reason (and refused if asked by hand), and Health says so; share links still work, and view counts still fall back to a JSON file. The Shares tab is now only your links, each with a **See visitors** button; the IP addresses view, the per-link log panes and the public address's card are gone. Not carried over: the older JSON logs (they are listed under *Left behind* in Health with a **Remove them** button, and nothing reads them).
- **One setting for how long visitor records are kept.** **Keep visitor records for (days)** (`LOG_KEEP_DAYS`, 0 to start with: until you trim the log) covers the public address and every share link (before, only the public log expired). **Warn when visitor records pass (MB)** (`LOG_WARN_MB`, 100; 0 off) makes the Health check say, with the size and the oldest record, when the log is big. **Log visitors to the public address** no longer needs share links (and so is no longer indented under Count views in Settings).
- **A visitor log that can't be fetched.** Because the log is a SQLite file (no guard line), its name carries a random part, and the Health check asks your browser, as it does for photos, whether the file can be fetched by its address; the server rules in the guide refuse it (it starts with `.gallery-`), and the web-server test now proves it on nginx and Apache.
- **In the admin shell, a button inside a page that opens another tab goes through the shell.** "How it works" on the Features list left the header saying Features, with Features still highlighted and no folder buttons, over a Notes page. Now the header, the folder tools and the sidebar say where you are: it opens the Notes of the folder you were in, and a button that opens a setting highlights Settings.
- **The Features list knows when the short share address rule is in place.** The *Short share addresses* row asks the same question the Health check does (from your browser); once the rule works it says **On** with a link as it looks now and drops the "Open the rule" button, as the Health check already did.
- **Every text link in the admin is the same periwinkle.** The link-styled buttons (*Expand all*, *Collapse all*, *Export everything as CSV*, *Trim the log…*, the "this folder / the whole gallery" choice and the Shares tab's) were grey, white or a stronger blue. Links inside a coloured banner still take the banner's colour.
- **In the admin shell, pressing the folder you are already in (in the folder tree) shows its gallery;** pressing another folder still shows that folder's settings.
- **The map pin grouping is no longer a row in Settings.** Each folder's own settings have it (as before), and 1 mile is the built-in default; a line already in the settings file is still read.
- **Visitor downloads are each folder's own switch.** The *Let visitors download originals* row (Off / Everything / Only some folders, with a folder picker) is gone from Settings. A public folder's settings now have **Visitors can download originals** right after *Gallery of its own*, off to start with, covering only the photos directly in that folder (no inheritance: each folder stands on its own). The main page's settings have **Visitors can download the photos on this page**. While the folder's own switch is on, a line under it says where things stand for the public folders below it, at any depth ("The 5 folders inside it have downloads off", "All 5 … allow downloads", or "3 of the 5 … allow downloads: paris, rome/deep", the names linking to those folders' settings) with **Allow downloads in all** and/or **Turn off in all**: one press does it once, then the line is redrawn, and nothing links the folders afterwards. The switches are hidden while the gallery is closed and on a private or Not listed folder (a Not listed folder keeps its own *Allow downloading originals*). **It fails closed:** a settings file that says Everything, or has the old on/off line, is read as Off, so downloads are never on by accident. The old lines stay in the file until you use a switch. The Edited tab lists the folders that allow it. **Scrub location data** moved to *Location data*.

### Added
- **The Health check is a dashboard.** One page for the whole gallery, in five kinds of row: **to fix** (red or amber, counted in "N things to fix"), **suggestion** (grey circle, counted apart: "· N suggestions"), **heads-up** (an amber ring with a !, not counted: lockouts, a link ending within a week, a closed gallery), **information** (a dot) and **good** (a check). The fold button says *Details* again (the "N optional" it used to carry counted rows that were only information, like the lockouts). A strip of numbers across the top (photos, videos, folders, active links, visitors, log size, backup age, free disk: the lowest across every disk the gallery's folders are on, mapped ones included, with a tap-to-open list when there are several). New rows: the database and the backup, the share links and collections files (an unreadable links file is a red row: every link stops working), links ending within a week, a closed gallery, free disk space, HTTPS, the visitor address behind a proxy, curl or allow_url_fopen missing for updates and the country file, a low PHP memory limit, and the folders' view-count databases. The slow looks (each database looked through) are kept for an hour; **Check again** looks at once.
- **"How to fix" folds on the Health rows that need a change on the server.** A folder the web server can't write in (who the web server is, `chown`, the group way), no SQLite (`php-sqlite3`), no curl or `allow_url_fopen`, plain HTTP (Let's Encrypt, a proxy's `X-Forwarded-Proto`), the visitor address behind a proxy, a low PHP memory limit, and the two "can't be fetched by its address" tests (the visitor log and the backup: the nginx and Apache rules, with Copy buttons, shown only when the test failed). The Copy buttons now work after the Health check is drawn again.
- **Fixed: a warning in the server log on every backup.** The backup's ZIP reader looked up a field by a wrong key (harmless for the entries the gallery writes, but it would have read the wrong bytes after an entry with an extra field).
- **The PHP memory row only appears where it matters, and the gallery raises the limit itself.** PHP's own picture library (GD) needs a whole photo in memory (about 100 MB for 12 megapixels), so before it resizes anything the gallery now asks for 256M for that request, as the update check already did. The Health suggestion about a low limit (it used to say "some may fail to get a thumbnail" even where Imagick, which keeps pictures outside PHP's memory, made every one) now shows only when there is no Imagick, GD is making the thumbnails and the server refused the raise, and it says what to set.
- **A weekly backup of everything that can't be made again.** One ZIP beside `index.php` (settings, share links, collections, the install secret, every folder's captions and flags, view counts, the visitor log, lockout history, your `{gallery}` notes; not photos, thumbnails or what is downloaded again), made by the first visit after a week and by **Back up now**, one copy only (each replaces the last). Each part is copied whole and checked first (SQLite with `quick_check`, copied with `VACUUM INTO`, never by copying the file); a part that fails is replaced by the same part from the backup before, so a damaged file never overwrites a good copy; the finished ZIP is read back and every checksum verified before it takes the old one's place. **Download** (admin password, one-time link). A damaged visitor log is a red row with **Restore the log from the backup** and **Set it aside and start a new log** (the damaged file is kept, renamed `.damaged-<date>`, never deleted).
- **A Changes tab: the log of disk activity.** What happens in your folders without you doing it in the admin (photos added, removed or renamed by a sync, an upload or by hand; a folder that appears or goes) is noticed and written down, with when it arrived, the names and a link that opens the folder with what is new marked. Each page looks at a names-only fingerprint of every folder (about 5 ms for 10,000 photos): the owner's own pages every time, a visitor's at most once a minute; the first look only takes a snapshot. A number on the tab (amber while there is something you have not looked at, grey for a day after you opened it); one *All kinds* pill with any number of kinds, a search box, *Trim the log…*; *Keep change records for (days)* and *Warn when change records pass (MB)* in Settings, and a Health warning past the size. It lives in the visitor log's SQLite file, which therefore now exists on every install with SQLite. On your gallery pages a folder's card gets an amber note of what is new in it (*(+1 photo ›)*, in the style of the private count), the pill at the bottom now comes from the log (it names the folders that changed, with links, and offers Refresh only where the view would change), and a link that marks new media keeps the marks until you leave and cleans its address. The sidebar's order is now Features, Collections, Edited, Shares, Visitors, Changes, Settings (Settings is last, also in the phone Menu and the desktop shell).
- **A folder can keep the location in the files visitors get.** **Scrub location data** (Settings) stays the default for the whole gallery, but a folder's **Locations** section now has **Keep the location in files visitors get**, under its location switch. With it on, visitors' copies of that folder's photos (the viewer's full-size picture, a download, a playing video, a Not listed photo's link) keep the location where the gallery shows it; a hidden location is still taken out. It covers only the photos directly in that folder and is off to start with. The Edited tab lists folders that have it.
- **A Not listed photo's address can send the bare file.** A new switch under Not listed, **Links send the bare file** (off: they open in the gallery, as before), makes each photo's link answer with the picture itself, or the video inline and seekable, with no page around it: for a forum or a chat app. It is what the viewer shows at full size (a picture with its location removed for visitors, an iPhone photo as its converted JPEG), not indexed, no referrer, counted and logged. It is independent of *Allow downloading originals*; the download button is unchanged. Adding `?file` or `?view` to one address overrides the folder's choice for that address.
- **Cover photo for a folder that holds folders.** Folder settings gets a **Cover photo** row (above the description) with a tile for each folder under it, showing that folder's cover. Press one and this folder follows that folder's cover: change it there and this changes too. **Pick any photo instead** chooses one photo from inside. Automatic, as before, is now the cover of the folder's first card (in the order the cards are shown), not simply the first photo by name. A private or Not listed cover is only shown to people who can see it; everyone else gets the first card they can see.
- **Edit on a folder from elsewhere** (Settings → Server setup). Change a place's name and path in one step. Its view counts follow it: the gallery remembers the names a place has had and a photo's views are the sum under all of them, so renaming (and renaming back) loses nothing and nothing is copied.
- **Health check: Left behind.** Rows for earlier views waiting to be added (amber), leftover thumbnails in folders from elsewhere on the server (pictures of photos that are gone, or made by another gallery), photos lying directly in a place added without a name (amber), folders that carry the same hidden id (a copy: links and Not listed addresses open nothing; amber, stays until dealt with) and Tidy-up backups. The first three can be **set aside** (they then sit among the quiet rows, "N set aside" in the summary, a **Bring back** button) and come back by themselves if there is more of them later.
- **Search in Settings.** A box above the groups: type a few words (a setting's name, a word from its help, one of its choices, or its name in the settings file such as `TRACK_VIEWS`) and only the settings that have all of them stay, with their groups open. Clearing the box (or Escape) puts every group back as it was. A setting that only shows while another is on is counted, not shown.
- **Collections.** A collection is a folder that exists only in the gallery: a hand-picked set of folders and single photos from anywhere, shown as a card of its own. Nothing moves on disk, and a collection grants nothing and hides nothing (a visitor sees in it only what they could already see where it really is). It lives in a folder or on the front page (**Show on front page** puts one that lives in a folder there too), has its own title, description, dates, position, Cards or Flat and photo order, an address like a folder's (`?folder=France/best-of-paris`), and the switches **Gallery of its own** (a collection works as a gallery of its own too) and **Private collection**. Make one from a name in the **Collections** section of a folder's (or the gallery's) settings; add members from its own settings (a folder, with everything inside or only its own photos, and single photos) or with **Add to collection…** on the Select bar; take photos out with **Remove from collection**. A **Collections** page gives the whole picture, and collections stand among the folders in italics. A share link can name a collection like a folder (the link then follows it as it changes; its *Public items only* applies to the members); a link that limits what is seen shows only the collections it names. A member folder is remembered by its hidden id, so renaming it keeps it in; one that is gone is simply missing. The records are in `.gallery-collections.php` beside `index.php` (on the list of files the gallery made). Deleting a collection removes only its record.
- **Scrub location data** (Settings, in *Location data*, always shown; on to start with). The location is taken out of every original a visitor is sent: the viewer's full-size picture, a download, a video that plays and a Not listed photo's own link, not only where the gallery hides the location. You, people with the private-view password and share links set to show all locations still get the file as it is. **A gallery that already lets visitors download originals and shows locations starts taking them out when you upgrade.** A photo that carries a location is then sent by the gallery itself rather than handed to the web server.
- **Earlier views.** Settings → Count views finds the view counts another gallery kept for the photos now shown here and, with **Add earlier views to the counts**, adds them to this gallery's own, once per folder (the old numbers are never changed, and pressing it again adds nothing). The per-folder list gets an **Earlier views** column while some folder has any.
- **Tidy leftover thumbnails** (Prepare media). The thumbnails and video pictures nothing uses any more (photos deleted, renamed or replaced, or made by another gallery) in a place from elsewhere on the server, listed with their size, and removed only once you tick that no other gallery still shows these folders. Photos, captions, links, private marks and the file data are never touched.
- **A Not listed folder picked into a share link is asked about first**, because everyone with the link then sees all of it.
- **Not listed folders.** A folder can be Not listed (Privacy, under *Private folder*): a folder only you can open, for sharing one photo at a time. Strangers and people with the private-view password get the same "not found" as for a folder that isn't there, and it is left out of every list; you see it with a **Not listed** pill. It is stored as private plus a flag, so an older version still keeps it private.
- **A Not listed photo's own link.** Each photo in one has a short link, eight letters and digits (`https://example.com/photos/Ab3x9Qz2`, or `…/photos/?Ab3x9Qz2` where the server's one-word rule isn't set up), that opens that one photo, alone, for anyone who has it: no grid, no neighbours, no way into the folder, kept out of search engines, no Referer. There is nothing to make or press: every photo in a folder has its link the moment **Not listed** is switched on, and **Copy link** only copies it. The eight characters are worked out from the folder's id, the file name and the install's secret (nothing is stored; the gallery finds the photo by working out each Not listed photo's code, about a microsecond each). Renaming or moving the folder keeps every link; renaming a photo, or a copy of the folder, ends it. Beside the pencil on its tile (and in the viewer) are **Copy link** and **New link** (the link crossed out: it asks first, then the old link stops at once). A Not listed folder has its own **Allow downloading originals** switch, off to start with.
- **Gallery of its own** (Navigation, in a folder's settings). Someone who arrives inside it, by a typed or pasted address or a link, is offered no way up past it and no folders beside it; the page is built without them. Someone who comes in through the gallery above keeps their way back (a short cookie, set only when a folder is marked, and the browser's own word for a click against a typed address). Nothing changes while no folder is marked.
- **The public address's log says where each visit came in.** A **Came in at** column, an "Arrived at" line in the timeline and a `came_in_at` column in the CSV, for arrivals (a typed or pasted address, a bookmark, a link from another site), and Not listed photos opened by their address are logged and tagged.

### Fixed

### Fixed
- **A folder's settings file that cannot be read hides the folder instead of opening it.** The privacy flags live in each folder's `.gallery-items.php`; a file that was cut short (a full disk, a half-finished copy), left empty or damaged by a hand edit used to read as "nothing is private", so private photos in that folder were served to anyone, and the next save wrote an almost empty file over it. Now the folder and everything in it is hidden from visitors until the file is restored or deleted; you (signed in) still see it all, with a notice on your gallery page and the Health check naming the folder; a save there says *Nothing was saved: a settings file in this folder can't be read* and leaves the file exactly as it was (the same for the share-links file). Just opening pages no longer rewrites the file either (the clean-up of entries for deleted photos only saves when there is something to clean).
- **A save can no longer be seen half-done.** The settings file was emptied and then written in place while visitors' requests read it without waiting, so a visitor arriving in that instant saw a folder with nothing private (reproduced: 4 private photos served in 9,000 requests during 400 saves). A save now writes a whole new file beside the old one and swaps it in, so a reader finds the old file or the new one, never a gap; two saves at once still both land. A data file that is a symlink is still written through.
- **The gallery's cookies stay on its own path.** A gallery in `/trip/` gave its sign-in cookies (the admin session, stay-signed-in, private view, share link and preview) to the whole domain, so any other application there received them. They are now kept to `/trip` (a gallery at the top of its address is unchanged; where the address a visitor used is not under the script's folder, as behind a rewrite, it stays `/`). Nobody needs to sign in again; Log out ends the cookie on both paths.
- **The sign-in throttle file no longer grows without end.** Every wrong password or share-link guess added an entry that was never removed, and the file is read on each sign-in and link visit. A failure now also forgets every address whose lockout ended long ago and with no recent failure (at most 2,000 are kept), and an IPv6 visitor is counted by their /64 (a whole home network, not one of billions of addresses).
- **Thumbnail, poster and clip file names cannot be worked out from a photo's name and date.** They were an unkeyed `md5` of the path and date; with the cache folder open (no server rule) a stranger could compute where a private photo's thumbnail is kept. They are now a keyed hash (made with the install's secret, which is created at the first sign-in: a gallery nobody has signed in to has nothing private to protect, and a visitor still makes no file but thumbnails). Existing files are renamed, not made again, by the next page view once the secret exists.
- **The map library is loaded with an integrity hash** (Leaflet 1.9.4 from cdnjs, in the page and where a map is opened on demand): a browser refuses it if the CDN ever serves a different file.
- **Nothing for a stranger to read in an error.** The `X-Powered-By` header (the PHP version) is removed, errors are logged and not printed into the page (a printed one names folders on the server), and an error nobody caught ends as a plain "Something went wrong" 500 with the details in the server's error log.
- **A link in a note keeps its address whole.** `[text](https://example.com/a_b_c*d*)` had its `*`, `_` and `~` read as bold, italic or strike inside the address, which put tags into the link. The address is set aside first; the words around it and in the label still format.
- **The About page's own address ignores extra path** typed after `index.php` (it used `PHP_SELF`, which includes it).
- **Sorting by file date reads each file's date once** (it read two for every comparison, which is slow on a network disk with thousands of photos).
- **Screen readers and keyboards in the admin:** the sidebar marks the page you are on with `aria-current` (it used `aria-selected` on plain links, which is not allowed); fields that had only a visible caption beside them (a folder's name, dates, description and position, a group's name, the notes editors, the switches in Folder settings) now carry their name; the Shares list's two button groups are groups, not tab lists; the numbers beside the sidebar's entries and the links in *How to read this* in Notes have enough contrast (4.5 : 1 and up); on a phone the admin's heading is hidden by size, not removed, so the page still has one. (The Shares list's quick buttons sit inside each row's summary; the owner called that a non-issue and it stays.)
- **The public pages have a main landmark.** The notes and the photos are inside `<main>` (the title block is before it, the viewer after it) and the path bar is a navigation landmark, so a screen reader can jump to the content; nothing looks different.
- **A photo that is a symlink is no longer shown.** A symlinked folder was already refused; a symlinked photo file (to anywhere on the server) was listed and served. It is now skipped everywhere, as a link to a folder is.
- **"Preview as this link" starts with a form, not an address.** The one-time token used to ride in the address (`…&csrf_token=…`), so it ended up in the browser's history and the server's log. The button now posts it in the body of the request into a new tab; asked for by address, the gallery answers 405 and starts nothing.
- **One list of routes decides who may reach what while the gallery is closed.** The gate used a hand-kept list of parameter names and relied on the order of the `if` blocks that follow it, so a new route added in the wrong place could have been reached by a stranger with `?admin=1` tacked on. `request_routes()` now lists every address that has a script of its own, in the order they are tried; the gate and each handler both ask `request_route()`, and a route is closed to a stranger unless it is marked as a way in (the sign-in, a share link, the admin). Nothing changes for visitors. Tests check that the table and the handlers agree (same names, same order) and that, for every pair of routes, the first one answers.
- **"More options…" in the admin shell no longer leaves a blank frame.** From the quick-share window inside the shell, the full form was opened by sending the frame to a plain admin address, which an admin page refuses to show in a frame; the draft then waited in the browser until you clicked Shares. It now goes to the framed Shares page with the form open and scoped to what you picked.
- **New links start at 2 browsers, not unlimited** (new setting `DEFAULT_LINK_USES`, 2; 0 is unlimited; Settings → Sharing and access). Most links are made for one person and were being left unlimited, so a forwarded link let anyone in and nothing was ever turned away. A saved link's paragraph marks its limit as its own only when it differs from the setting. Existing links are not changed (edit them one by one, or *Extend…*).
- **Cleaned out:** two functions nothing called, about 55 lines of style rules for markup that no longer exists (the old Private tab, export cards and others), the `ENABLE_MAP` alias (the map follows `ENABLE_PHOTO_LOCATION` everywhere, as the README says), a docblock that had drifted away from its function, and the header comment's claim that the script never makes outside requests (a map does, when a visitor opens it). ## [2.0.0] - 2026-10-10

A large release, built and tested in phases on one branch and shipped as one version. **Everything new is off by default, behind its own constant** — a deployment that just swaps in the new file behaves like 1.1.1, apart from the one breaking change below and the two upgrade notes under it.

### Breaking changes
- **PHP 8.3 or newer is now required** (1.x stated 7.4). PHP 7.4 has been unsupported since 2022 and was never tested against this release; 8.1 and 8.2 are out of (or about to leave) security support. The minimum is 8.3, the oldest version still receiving security fixes (until the end of 2027), and it is a tested claim: the full test suite, the fuzzer, the cross-site-scripting check and the real-browser run all pass on PHP 8.3.32 as well as 8.4.26. On an older PHP the page stops with a one-line message saying so.
- **`?download` no longer serves the script.** It now redirects (302) to the GitHub repository. It used to `readfile()` the running `index.php` to anyone who asked; once `ADMIN_PASSWORD` lives in that same file, that would have handed the password to any visitor, and scrubbing secrets out of the output is a fix that has to be remembered forever. Removing the endpoint closes the whole class at once. An old bookmarked link lands on the repository rather than a dead end. `?about`'s download button now points at GitHub too.

### Upgrading from 1.x
- **Your view counts carry over automatically.** 1.x kept them in `.gallery-stats.json` (or a SQLite file with readable filenames). On the first request with `TRACK_VIEWS` on, 2.0 imports the per-photo counts and the sitewide total into its new stores, then removes the old JSON file (or drops the old SQLite table and compacts the file, so the old filenames don't linger in it).
- **You may see one new setup notice** if your folder has subfolders containing photos while `AUTO_GROUP_BY_FOLDER` is off: the collapsed "setup notices" banner says how many photos in subfolders aren't shown (a count, never a name).

### Added — folders
- **Nested folders, to any depth** (`AUTO_GROUP_BY_FOLDER`, off by default). A root like `/trip` with `Europe/France/Paris` underneath shows each subfolder as its own group. With `FOLDER_DISPLAY_MODE = 'overview'` (the default) each level shows one **cover card per subfolder** — a highlight photo, a label and a *recursive* photo count — plus any photos loose at that level, and clicking a card opens `?folder=Europe/France` and repeats. `'inline'` instead shows every folder's photos in one box, for people who use folders only to stay organized. A breadcrumb links through every ancestor.
- `?folder=` is validated against the script's own file list, never trusted: `../`, leading/trailing slashes, a file path, an empty value, a nonexistent folder, and a hidden folder all return 404. Symlinked subfolders are refused outright.
- `EXTRA_FOLDERS`: an explicit, admin-written map of virtual folder names to real paths (for archiving an old trip on another disk) — declared in code you control, so no symlink is involved.
- Per-folder **display name, description, a typed date-range subtitle, a chosen cover photo, and a position among sibling folders**, all editable in `?admin`. Stored inside the folder they describe, so they survive a real rename. The date range is deliberately never derived from EXIF: that would publish when you were away from home.
- A folder may carry its own `{gallery}`-marked `.md`, becoming a note box on that folder's page, scoped to that folder's photos only.
- A `.md` mention of a folder links to its `?folder=` page in overview mode.
- Stats, the thumbnail cache and per-item data are **colocated in each folder**, so two cameras' `IMG_0001.jpg` in different folders never collide, and a real folder rename carries its data along.
- A **"Last updated"** date in the header, derived from the newest file modification time across photos and notes — not a separately maintained marker, so it also reflects files uploaded by FTP.
- A setup notice when photos exist in subfolders but `AUTO_GROUP_BY_FOLDER` is off, so a first-time owner isn't left with a silently sparse gallery (a count only; the search is capped at 40 folders).
- Sibling folders order by an admin-set position, then naturally by name (Day 2 before Day 10), or by folder mtime under `PHOTO_SORT_ORDER = 'mtime'`.
- `?img=` and `?video=` validate the one claimed path directly instead of scanning the whole tree first — one tree walk per thumbnail is what made large, deep galleries slow (measured on 3,000 photos in 200 folders with PHP's built-in server: about 35 ms per `?img=` request before, about 9 ms after). The check rejects `..`, doubled/leading slashes, backslashes, NULs, folders, the script itself, `.gallery-cache`, symlinked folders, non-media extensions, and any name that isn't an exact-case match for a real file (so a case-insensitive filesystem can't dodge a per-photo hide flag). `?track=` and page loads still scan, since they need the whole group.

### Added — video
- `ENABLE_VIDEO`: `.mov` and `.mp4` are served as gallery items. No transcoding, no frame extraction. Tiles and share previews use one generic placeholder graphic; the lightbox plays the clip in a native `<video>`. Seeking works: real HTTP `Range` support (`206`, `416` past the end, malformed ranges ignored). A **duration badge** is read straight from the container's `mvhd` box.

### Added — captions, location, and the admin editor
- **Per-item captions, a web link, and a location**, one per photo or video. The lightbox shows the caption (or just a position counter) — **it no longer prints the raw filename.** Grid badges (caption, location, link) sit along the bottom edge.
- **`ENABLE_PHOTO_LOCATION`** (off by default) is the first of three gates: also needed are a per-folder switch and a per-photo setting (inherit / always show / always hide), all closed by default. GPS is auto-filled from EXIF for JPEG and HEIC where present; coordinates are validated before they reach any URL.
- **Two admin tabs can't silently overwrite each other:** a save whose record changed since the page loaded is refused with an explanation (per record, so different photos never conflict).
- The caption badge is a tap target that opens a popover on a phone, not just a hover tooltip.
- **`?admin`** (`ADMIN_PASSWORD`, empty = the code path doesn't exist): HTTP Basic Auth compared with `hash_equals()`, refused over plain HTTP except on localhost (with a page explaining why), CSRF-protected saves, a 4-hour session, and a failed-login throttle (5 wrong passwords from one address in 15 minutes imposes a 60-second delay; a request with no credentials — the normal first step of any login — doesn't count). Usable from a phone. It edits every item's caption/link/location, folder settings, every `.md` in the folder (raw text, saved byte-for-byte; **Save**, **Save As** and **Delete** are separate actions, and Save As and Delete ask for confirmation; a one-click fix for a missing `{gallery}` marker), and exports each folder's saved data (`.gallery-items.php`) as plain JSON, for one folder or the whole tree. Stale entries for deleted photos are cleaned up and reported.

### Added — hiding items, and Private view
- A **hide flag** per item and per folder (at any depth) in the admin. A hidden item is removed from the page, counts, lightbox list and every endpoint (`?img=`, `?photo=`, `?track=`, `?folder=`, `?video=`) for an unrevealed visitor — not merely styled invisible. A group whose members are all hidden disappears rather than showing "0 photos". Each item can also be forced *public* inside a hidden folder.
- **`PRIVATE_VIEW_PASSWORD`** and a discreet "Private view" footer link (`?reveal`): a password, deliberately not a secret link, since links pasted into chat get crawled. Same HTTPS requirement and throttle as the admin. A valid admin login counts as revealed too.
- An admin **"Hidden items"** summary across the whole tree in three tiers, and a persistent warning that hiding doesn't stop someone who already knows a file's URL unless the web server is locked down.
- **`NGINX_ACCEL_REDIRECT_PREFIX`** hands matching files to nginx via `X-Accel-Redirect`, so an nginx `internal` rule can make the bare file URLs unreachable. See the README for the nginx and Apache setups.

### Added — trip map
- **`ENABLE_MAP`** (off by default): every visible, located photo on one Leaflet + OpenStreetMap map, at its own shareable **`?map`** URL with a condensed preview on the gallery root. Photos within `MAP_CLUSTER_RADIUS_MILES` (default 50) merge into one numbered pin that zooms in when clicked; pins are colored per top-level folder with a legend; a pin opens a popup (thumbnail, label, link) rather than navigating. Hidden items are never plotted. `?map` has its own Open Graph tags and a generic map-pin preview image. **This is the first feature that makes third-party requests** (Leaflet from cdnjs, tiles from OpenStreetMap), which is why it is opt-in.

### Added — walkthroughs
- **README: "Recipes — start here"** with a decision table and one tested walkthrough per use case (plain gallery, for-sale listing, trip album, family photos with private items, an archive on another disk, iPhone photos), plus a **"What affects what"** pair of tables mapping every setting in `index.php` and every admin control to its effect on visitors. Each recipe was followed step by step against the real script, through the admin's real forms, as part of the test suite.
- The admin now shows, when `TRACK_VIEWS` is on, the sitewide page-load total and "👁 N views" under every photo — so `SHOW_VIEW_COUNTS_PUBLICLY = false` really means "count them, show only me".

### Added — other
- `SHOW_VIEW_COUNTS_PUBLICLY` (default `true`): track views for yourself while hiding the public badges.
- View counts are debounced per browser (30 minutes, per photo), so reloading a photo no longer inflates it. A debounced request still returns the current total.
- The SQLite view-stats store keys its rows by a SHA-256 of each photo's path rather than the filename, because that binary file can be fetched by URL and can't carry the PHP guard the JSON files do. Hidden items are counted like any other; no filename appears in the file.

### Security
- **Apache rules are now tested on a real Apache** (2.4.68 + PHP-FPM) and Apache pretty folder URLs are documented (`RewriteRule … [B,L,QSA]`; the `B` flag is needed for names with spaces or `&+#`). Along the way:
- **Apache: the documented `.htaccess` rule missed upper-case extensions** (`IMG_0412.JPG`, `.Jpeg`) because `FilesMatch` is case-sensitive, so those photos — hidden ones included — stayed reachable by address even with the rule installed. Fixed with `(?i)`. Found by running the rules on a real Apache (2.4.68 + PHP-FPM), which also confirmed that `AllowOverride None` silently disables them, and that the admin and Private view login needs `CGIPassAuth On` on Apache with PHP-FPM/CGI (documented).
- **Hidden photos and videos are never cacheable** (`Cache-Control: private, no-store`), as are pages rendered for a revealed viewer (with `Vary: Cookie`) — previously every photo, hidden or not, was `public, immutable`, so a CDN or proxy could have kept a hidden photo and served it to anyone.
- Admin and private-view responses send `Cache-Control: no-store`, `X-Frame-Options: DENY` and a CSP (`frame-ancestors 'none'; form-action 'self'; base-uri 'none'; object-src 'none'`); every response sends `X-Content-Type-Options: nosniff`.
- The admin session has its own cookie name (it no longer shares `PHPSESSID` with a host site) and rejects session ids the server didn't issue (`session.use_strict_mode`).
- A malformed `Host` header is no longer echoed into absolute URLs.
- Verified by a cross-site-scripting canary test (payloads planted in every admin field, notes, file and folder names, query strings and headers; no raw payload came back on ~290 pages) and by PHPStan static analysis (no real findings). The `README`'s new "Security notes" lists what is and isn't protected.

### Fixed
- **Replacing a photo under the same name now shows the new picture.** Photos and videos are cached by browsers for a year, and their address never changed, so anyone who had seen `rack.jpg` kept seeing the old one after you swapped it (this dates from 1.x). Image and video addresses now carry a tag (`&v=…`) hashed from the file's modification time and size, so a replaced file gets a new address while untouched photos keep theirs; link-preview images pick it up too. Checked in a real browser: without the tag the swapped photo kept showing the old picture; with it the new one appears on a normal page load.
- The link inside the admin's red "Hidden items exist" warning was dark blue on dark red (contrast about 1.8:1, nearly unreadable); it now inherits the box's colour.
- **A pasted `?folder=` link now previews with the cover photo chosen in the admin** (it used the folder's first file). One shared function picks the cover for both the card and the preview.
- **Two galleries on one domain no longer sign each other's viewers out.** The "Private view" cookie used one fixed name for the whole domain; it is now named and signed from each copy's own folder, so every gallery keeps its own (and one gallery's cookie is no longer valid in another that merely shares the password).
- **The sitewide "N views" total no longer shows in the public footer when `SHOW_VIEW_COUNTS_PUBLICLY` is off.**
- **The admin no longer says "Saved" when it couldn't write** (a folder the web server can't write to — very common on shared hosting). It says "Nothing was saved" and what to change.
- `examples/example-forsale.md` did what its text promised only by accident: it claimed the filename prefix `widgeta` matches "Widget Model A", which it doesn't, so none of its items got photos. Rewritten (Alpha/Bravo/Charlie), and the claim corrected.
- Directive examples written inside `` `inline code` `` in a notes file were parsed as real directives (so documenting the syntax raised "unknown file" notices on the public page, including the shipped example's own explanation). Braces inside inline code are now inert and shown literally; real directives in the same paragraph still work.
- `?img=...&size[]=x` (an array where a size is expected) was a fatal error; it now falls back to the default size. This one dates from 1.x.

### Notes
- **The generated data files are guarded PHP files, not plain JSON.** `.gallery-items.php`, `.gallery-stats.php` and `.gallery-login-attempts.php` begin with a one-line `<?php http_response_code(404); exit; ?>`, so asking a web server for one by URL returns 404 and nothing else — captions, GPS and the filenames of hidden items are never sent, on any host that runs PHP, with no server rule. They're read as plain text (never executed), and are written with `<`/`>` escaped so a caption can't inject PHP. The one file that can't carry the guard is the optional binary `.gallery-stats.sqlite`, which is why it holds only hashed keys and counts; the README's nginx/Apache rule blocking `.gallery-*` is worth adding as a second layer over all of these. The nginx rules were tested against nginx 1.26 + php-fpm 8.4; the Apache rules were not.
- The original photo files are served untouched, so **embedded EXIF GPS in the full-size image is not stripped** — the location gates control what the gallery shows, not what a saved original contains. See the README.
- `tests/run.php` now has 463 checks, including recipe walkthroughs that drive the admin through its own forms the way a browser submits them, an upgrade from the *real* 1.1.1 script (not an imitation of its data), and iPhone-style big-endian GPS, including a real 1.x-to-2.0 stats upgrade in both storage flavours. The project was also fuzzed with ~2,300 hostile requests across every endpoint (anonymous, revealed and admin, PHP with all errors on): it found and fixed the fatal above, a fatal on a NUL byte in a notes filename, and PHP warnings from array-valued admin form fields. The inline JavaScript was syntax-checked and its logic executed against a fake DOM and Leaflet, and the whole gallery was driven in a real headless Chromium (lightbox and keys, caption popover, folder navigation, the map with real Leaflet and a clickable pin, phone-width layouts, the admin including a real form submit under its Content-Security-Policy, and that the admin cannot be framed). The suite also no longer leaks processes: each run used to orphan its `php -S` servers (~350 MB for ten), which accumulated over a long session and exhausted a small host — and it no longer follows directory symlinks when cleaning up its fixtures.
- Also verified with real tools rather than assumed: swipe gestures with real touch events (left/right/ignored-if-short/up-doesn't-close/down-closes); real H.264 clips with the metadata at the end of the file (as phones write it), at the start, and as a QuickTime `.mov` — duration badge, decoding, **seeking** and playback in Chromium; 400 simultaneous view pings and 30 simultaneous admin saves on php-fpm, counted exactly on both stats backends; the whole suite, the fuzzer, the cross-site-scripting check and the browser run on PHP 8.3 and 8.4; the nginx and Apache rules on the real servers.

## [1.1.0] - 2026-09-07

### Breaking changes
- **A `.md` file is only read if its first line is exactly `{gallery}`.** Any existing `forsale.md` (or similar) needs that line added, or it will silently stop being parsed. This is a hard requirement, not a toggle — added so this script can be dropped into a folder that already has its own unrelated `.md` files (notes, a README) without swallowing them.
- **`TRACK_VIEWS` now defaults to `false`** (was `true`). Set it to `true` to get view-count badges/stats back.
- **`ENABLE_THUMBNAIL_CACHE` (new) defaults to `false`.** Without it, every photo is served at full original resolution as its own "thumbnail," and HEIC/HEIF photos are excluded from the gallery entirely — even with Imagick installed. Set it to `true` for real deployments.
- **`AUTO_GROUP_BY_FILENAME` (new) defaults to `false`** (auto-grouping by a `_01`/`-02` filename suffix was previously always on). Set it to `true` if your photos use that multi-angle naming convention.

Reasoning for all three defaults: this script writes nothing to a folder's disk, and assumes nothing about a folder's filename conventions, unless explicitly told to.

### Added
- Explicit photo grouping in a `.md` file via `{group: Name}` and `{photos: a.jpg, b.jpg, ...}` directives — works regardless of filename, for a folder of photos with no naming convention at all. See the README for the full behavior matrix (boxed vs. unboxed, with/without text, permalinks, positional clustering).
- `{photos:}` used without `{group:}` repositions the listed files adjacent to each other in the gallery, without boxing them or creating an aggregate view count. With prose, they're positioned early (by where that text sits in the `.md`); textless, they fall back to natural order, anchored on the first-listed file.
- `{group:}` used alone (no `{photos:}` in the same paragraph) renames an already auto-detected group's display label.
- `PHOTO_SORT_ORDER` constant: `'filename'` (default, natural sort) or `'mtime'` (file modification time, oldest first).
- A "⚠ N setup notices for the gallery owner" banner, collapsed by default, listing anything that didn't resolve cleanly: a `.md` file missing its `{gallery}` marker (reported as a count only, deliberately never by filename — see Fixed below), an unknown filename referenced in `{photos:}`, a duplicate `{group:}`/`{photos:}` claim, or a directive that isn't attached to the description it was probably meant to go with (see the next bullet). Shown at the top of the notes box if one exists, or right below the page header if no `.md` qualified at all — addressed explicitly to the gallery owner, so it's not alarming to a normal visitor. The same list is also still in an HTML comment near the top of the page source.
- A directive-only paragraph (no prose of its own) immediately following a plain, unclaimed description — separated only by a blank line — is flagged in that notice banner, since it's easy to write by accident and silently changes both what shows in the notes box and where the item sorts. Not flagged when the preceding paragraph already has its own directive, or when a header/list/blockquote sits in between.

### Fixed
- Two unrelated files sharing a base name but differing only in extension (e.g. `topology.jpg` and `topology.png`) could silently merge into a box, regardless of `AUTO_GROUP_BY_FILENAME` — a coincidence, not an intentional grouping signal, since neither file needed any suffix stripped to arrive at that shared name. A real multi-angle group (`dp104_01.jpg`/`dp104_02.jpg` → `dp104`) is unaffected, since stripping is what makes those converge. (An initial fix keyed every file by its full filename including extension, which inadvertently broke classic mention-based auto-linking — a paragraph mentioning "zebra" could no longer match `zebra.jpg`. Fixed properly in the same release.)
- The gallery grid no longer splits into separate fragments around a group box. Previously, standalone single photos were batched into their own `<div class="grid">` blocks that broke every time a box appeared between them, so a short run of singles right before a box rendered as a sparse, incomplete-looking row. The whole gallery is now one continuous grid; a box is simply a grid item spanning the full row width.
- Layout is now two zones: every box (auto-detected or explicit) always renders before every single and unboxed cluster, regardless of where its directive/mention sits in the `.md`. Even the previous fix above couldn't fully prevent a box from landing mid-row and leaving a gap when it interrupted an uneven number of singles — putting every box first eliminates that possibility structurally, since a full-width row always ends cleanly.
- Mention-matching now searches prose only. Previously it scanned raw `.md` content directly, so a filename referenced inside a *different* paragraph's `{photos: a.jpg, b.jpg}` list could falsely count as a mention of its own name if that name happened to appear with valid word boundaries inside the directive text — most obvious with short filenames, but not limited to them.
- A mentioned standalone single's "View 1 photo ↓" note-box link now actually works. It always pointed at `#group-<slug>`, but only a boxed group's container ever carried that id — a plain single card never did, so the link was dead for any mention that didn't turn out to be a real multi-photo group. Every card gets the anchor now.
- The missing-`{gallery}`-marker notice no longer names the rejected `.md` file. Every other notice only ever references a filename the folder owner themselves typed into their own gallery `.md`, already meant to be public — but a `.md` missing the marker is, by definition, one they *didn't* choose to expose. Since a `.md` is served as a plain static file with no access control tied to the marker, naming it handed a visitor the literal URL to go read its contents directly. Now reported as a count only ("N .md files were found but ignored...").
