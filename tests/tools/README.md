# Optional test tools

These sit beside `tests/run.php` (the main suite, which needs only PHP + GD). They are **optional**, need a little more, and are not run by `php tests/run.php`. Both build their own throwaway fixture, use a free port, and clean up after themselves.

| Tool | What it checks | Needs |
|---|---|---|
| [`fuzz/fuzz.py`](fuzz/fuzz.py) | Sends ~7,400 hostile requests (odd paths, arrays, NUL bytes, huge values, wrong methods, ~900 randomized admin POSTs) to every endpoint as an anonymous visitor, a revealed viewer, the admin, three kinds of share-link holder and the owner previewing each link, with PHP reporting every error. Fails on any warning, notice, fatal, deprecation or 5xx. | `python3`, `php` with gd + imagick |
| [`fuzz/xss.py`](fuzz/xss.py) | A cross-site-scripting canary test. Plants hostile text in every input an owner or visitor controls (admin fields, a notes `.md`, file and folder *names*, query strings, headers, cookies), crawls every page as an anonymous visitor, a revealed viewer and the admin, and fails if any payload comes back *raw* in a context where it could run (context-aware: text inside a `<script>` is inert unless it can close the script). It also checks the payloads really did reach the pages escaped, so a clean result can't be vacuous. | `python3`, `php` with gd + imagick |
| [`browser/browser_checks.py`](browser/browser_checks.py) | Drives the gallery in a **real headless Chromium** (via a tiny stdlib DevTools client, [`browser/cdp.py`](browser/cdp.py) — no Playwright/Puppeteer needed): real clicks and key presses on the lightbox (incl. a video) and caption popover, folder navigation and breadcrumbs, the map with real Leaflet (pins, popup), phone-width pages for horizontal overflow, the admin's collapsible panel, **the phone viewer** (the top row of buttons, the photo filling the screen, a finger swiping), sharp tiles picking the right size per screen, "Prepare thumbnails", the owner's lock on tiles, **the draggable "Put first" list** (a mouse and a finger dragging a row past two others, switched-on rows staying on top, a folder's Site's / This folder's own pills), **a real form submission under the page's Content-Security-Policy**, that the admin refuses to be framed, and the contrast of the admin's warning link. Add `--shots DIR` to save screenshots. The map check needs internet access for Leaflet (skipped if offline). | `python3`, `php` with gd + imagick, Chromium (`chromium` on PATH or `CHROMIUM=…`) |
| [`browser/video_checks.py`](browser/video_checks.py) | **Real video in a real browser.** Makes genuine H.264 clips with ffmpeg — metadata at the *end* of the file (as phones write it), at the start, and as a QuickTime `.mov` — and checks, in Chromium, the duration badge, that the lightbox decodes each, that **seeking** works (a real player issuing `Range` requests) and that it plays. | `python3`, `php` (gd), Chromium, **ffmpeg** (`FFMPEG=/path/to/ffmpeg`; a static build from johnvansickle.com works, no install) |
| [`js/run_js_checks.py`](js/run_js_checks.py) | Syntax-checks every inline `<script>`, then runs the real lightbox, caption-popover, view-tracking, map and admin scripts under QuickJS against a small fake DOM and a fake Leaflet, asserting on what they do. It is a safety net for logic errors and typos, **not** a browser (the real-browser tool above covers rendering, CSS and real Leaflet). | `python3`, `php` with gd + imagick, [QuickJS](https://bellard.org/quickjs/) (`qjs`) |
| [`qr/qr_reference.py`](qr/qr_reference.py) | A reference QR code encoder and decoder (byte mode, level H, versions 1 to 20) used to check the gallery's own JavaScript one: the browser checks compare the page's picture with it module for module and read it back (unmask, un-interleave, every Reed-Solomon block, the text). Its self-test also checks the published format and version bit patterns and the block tables' totals. | `python3` only |

```
python3 tests/tools/fuzz/fuzz.py
python3 tests/tools/fuzz/xss.py
python3 tests/tools/qr/qr_reference.py                       # self-test of the reference QR encoder
python3 tests/tools/browser/browser_checks.py [--shots DIR]
FFMPEG=/path/to/ffmpeg python3 tests/tools/browser/video_checks.py
QJS=/path/to/qjs python3 tests/tools/js/run_js_checks.py     # QJS defaults to `qjs` on PATH
```

**How long the browser checks wait.** After an action the checks wait (`drain`) for the page to settle. A wait of 0.25 to 2.9 s ends early once the page has gone quiet (nothing in flight on the network, no short timer or animation frame pending, no running animation or transition, no DOM change, scroll or resize for 150 ms, seen twice in a row); a page that never goes quiet uses the whole wait, and waits of 3 s or more are real-time waits and always run in full. `GALLERY_BROWSER_STRICT=1` makes every wait run in full (the slow, literal mode; `video_checks.py` always does). `GALLERY_BROWSER_STATS=1` prints where the waiting went (by call site, and each page load by address) when the run ends. A `goto` to the same page with only a different `#fragment` is an in-page jump (no load event ever comes): it is finished when the browser says so; any other load that does not finish in 30 s prints a `note` line. Measured 2026-10-23: 726 checks, about 7 minutes (was 15 to 18), the same checks passing.

All of them exit 0 only when nothing is found. The gallery itself runs under `PHP_SERVER` (default `php`), so you can check another PHP version, e.g. `PHP_SERVER=/path/to/php8.3 python3 tests/tools/fuzz/fuzz.py` (the fixture is still built with the `php` on your PATH, which needs gd + imagick; a static CLI build from <https://dl.static-php.dev/> makes a handy second version). `php tests/run.php` already uses whatever PHP you run it with.

**Getting QuickJS without root** (Debian/Ubuntu): `apt-get download quickjs && dpkg -x quickjs_*.deb ~/quickjs`, then `QJS=~/quickjs/usr/bin/qjs`.

**Web-server rules** (the nginx and Apache snippets in the admin and the README) are checked against REAL servers by `python3 -I tests/tools/webrig/check_rules.py`: it downloads nginx, Apache and php-fpm 8.4 (`apt-get download` and `dpkg -x`, no root, into `~/.cache/gallery-test-tools/webrig`), runs both on high ports in front of a throwaway gallery at `/trip/`, takes the rules from the gallery's own Settings page, and checks custom link names, a link and a folder sharing a name, a folder typed without its slash, `/admin`, and a closed gallery on each (42 checks). Run it whenever a rule changes. By hand, the same thing was done with: `apt-get download nginx php8.4-fpm apache2-bin apache2-data apache2 libapr1t64 libaprutil1t64` (or `quickjs` for QuickJS), `dpkg -x` each into a scratch directory, and run them on high ports with `LD_LIBRARY_PATH` pointing at the unpacked libraries (Apache via `mod_proxy_fcgi` to the unpacked php-fpm, with `PHP_INI_SCAN_DIR=/etc/php/8.4/cli/conf.d`). Re-run that after changing a rule in the README. The same rig (nginx + php-fpm with several workers) was used for a one-off **concurrency check**: 400 simultaneous view pings and 400 simultaneous page loads were counted exactly (no lost updates) on both the SQLite and the JSON backend, and 30 simultaneous admin saves to 30 different photos all persisted in a valid data file. (PHP's built-in server handles one request at a time, so it can't test this.)

The shared fixture is [`fuzz/build_fixture.php`](fuzz/build_fixture.php): every feature switched on, folder and file names containing `& < > ' % ;` spaces and non-ASCII, a hidden folder, captions with HTML in them, GPS photos, a video and a HEIC. Run it by hand to get a gallery to poke at:

```
php tests/tools/fuzz/build_fixture.php /tmp/kitchen-sink && php -S localhost:8000 -t /tmp/kitchen-sink
# ?admin password: adm-pw    ?reveal password: viewer-pw
```
(The fuzzer *mutates* its fixture with random admin writes, so it always builds a fresh one — don't point it at yours.)
